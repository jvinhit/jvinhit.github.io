Strategy là pattern hành vi (behavioral) giúp bạn **đóng gói các "cách làm" có thể hoán đổi cho nhau** sau một giao diện chung. Khi bạn thấy một khối `if/else` hay `switch` khổng lồ chọn giữa các thuật toán tương tự nhau, Strategy thường là câu trả lời.

---

## 1. Vấn đề: khối if/else phình to mãi

```ts
// ❌ every new payment method/format/validation rule means editing this function
function formatValue(value: number, type: string): string {
  if (type === 'currency') return `${value.toLocaleString('vi-VN')}₫`;
  else if (type === 'percent') return `${(value * 100).toFixed(1)}%`;
  else if (type === 'bytes') {
    /* ...10 lines of logic... */
    return '...';
  } else if (type === 'compact') {
    /* ...more added... */
  }
  // ...this function grows forever, breaks easily, hard to test each branch
  return String(value);
}
```

Mỗi loại mới = sửa hàm cũ (vi phạm Open/Closed, Phần 1), và mọi nhánh bị nhồi vào một chỗ khó test riêng lẻ.

---

## 2. Strategy bản object (cách "JS" gọn nhất)

Mỗi chiến lược là một hàm; gom chúng vào một bảng tra cứu. Đây là dạng Strategy phổ biến và gọn nhất ở frontend:

```ts
type Formatter = (value: number) => string;

// Each strategy is a pure function, testable in isolation
const formatters: Record<string, Formatter> = {
  currency: (v) => `${v.toLocaleString('vi-VN')}₫`,
  percent: (v) => `${(v * 100).toFixed(1)}%`,
  bytes: (v) => {
    const units = ['B', 'KB', 'MB', 'GB'];
    let i = 0;
    while (v >= 1024 && i < units.length - 1) {
      v /= 1024;
      i++;
    }
    return `${v.toFixed(1)} ${units[i]}`;
  },
};

function formatValue(value: number, type: string): string {
  const formatter = formatters[type] ?? ((v) => String(v)); // safe fallback
  return formatter(value);
}
```

Thêm định dạng mới giờ chỉ là thêm một entry vào `formatters` — **không đụng** `formatValue`. So với bản if/else: dễ test (mỗi formatter là hàm thuần riêng), dễ mở rộng, dễ đọc.

## 3. Strategy đầy đủ với interface (khi cần nhiều method)

Khi mỗi chiến lược cần *nhiều hơn một hàm* (ví dụ vừa validate vừa cho thông báo lỗi, vừa tính phí vừa kiểm tra điều kiện), dùng interface:

```ts
interface ValidationStrategy {
  validate(value: string): boolean;
  message(): string;
}

const emailStrategy: ValidationStrategy = {
  validate: (v) => /^[^@\s]+@[^@\s]+\.[^@\s]+$/.test(v),
  message: () => 'Invalid email',
};

const phoneVNStrategy: ValidationStrategy = {
  validate: (v) => /^(0|\+84)\d{9,10}$/.test(v),
  message: () => 'Invalid phone number',
};

// Context: receives a strategy, doesn't care about internals
class FieldValidator {
  constructor(private strategy: ValidationStrategy) {}

  check(value: string): string | null {
    return this.strategy.validate(value) ? null : this.strategy.message();
  }

  setStrategy(strategy: ValidationStrategy) {
    this.strategy = strategy; // swap behavior at runtime without recreating context
  }
}

const validator = new FieldValidator(emailStrategy);
validator.check('abc'); // "Invalid email"
```

Điểm cốt lõi: `FieldValidator` (context) **không biết** có bao nhiêu kiểu validation. Thêm kiểu mới không sửa nó. Đây chính là nguyên lý Open/Closed thành hình.

## 4. Strategy trong React: truyền hành vi qua props

React dùng Strategy mọi lúc, chỉ là không gọi tên. Một component nhận **hàm** qua props chính là Strategy — caller quyết định "cách làm", component lo "khi nào gọi".

```tsx
interface DataTableProps<T> {
  rows: T[];
  // strategies injected: how to sort, filter, render a row
  sortBy?: (a: T, b: T) => number;
  filterBy?: (row: T) => boolean;
  renderRow: (row: T) => React.ReactNode;
}

function DataTable<T>({ rows, sortBy, filterBy, renderRow }: DataTableProps<T>) {
  let data = rows;
  if (filterBy) data = data.filter(filterBy);
  if (sortBy) data = [...data].sort(sortBy);
  return <div>{data.map(renderRow)}</div>;
}
```

`renderRow`, `sortBy`, `filterBy` đều là strategy. Cùng một `DataTable` phục vụ vô số trường hợp vì hành vi được tiêm từ ngoài. Đây là vì sao "truyền hàm làm prop" mạnh đến vậy — nó là Strategy phổ quát.

---

## 5. Strategy + Factory: cặp đôi quen thuộc

Thường ta chọn strategy dựa trên dữ liệu lúc chạy — đó là lúc Factory (Phần 4) chọn giúp strategy:

```ts
function getValidationStrategy(fieldType: 'email' | 'phone'): ValidationStrategy {
  const strategies = { email: emailStrategy, phone: phoneVNStrategy };
  return strategies[fieldType]; // Factory picks the Strategy
}
```

Mẫu kết hợp này xuất hiện liên tục: Factory *chọn* cách làm, Strategy *là* cách làm, Context *dùng* cách làm mà không biết chi tiết.

---

## 6. Khi nào KHÔNG dùng

- **Chỉ có 2 nhánh đơn giản, ít đổi** → một `if` là đủ, đừng dựng bảng strategy.
- **Các "chiến lược" thực ra rất khác nhau** (không cùng giao diện) → ép chung interface sẽ gượng; có thể chúng là những thứ khác nhau, không phải biến thể.
- Nhớ: Strategy đáng giá khi có **nhiều biến thể cùng hình dạng** và **danh sách còn mở rộng**.

---

## Tóm tắt

- **Strategy** đóng gói các "cách làm" hoán đổi được sau một giao diện chung — xóa sổ if/else khổng lồ.
- Bản **object** (bảng tên → hàm) là dạng gọn nhất ở JS; bản **interface** khi mỗi chiến lược cần nhiều method.
- Trong React, **truyền hàm làm prop** (`renderRow`, `sortBy`) chính là Strategy.
- **Factory + Strategy** là cặp quen thuộc: Factory chọn, Strategy thực thi.
- Đừng dùng khi chỉ 2 nhánh đơn giản hoặc các nhánh không thực sự cùng hình dạng.

**Phần tiếp theo:** Command — biến hành động thành object để làm undo/redo, hàng đợi và macro.
