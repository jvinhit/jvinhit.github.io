JavaScript chạy đơn luồng trên mỗi context (Phần 7), nhưng nền tảng web *có* đa luồng thật qua **Web Workers**. Phần này đi sâu vào cách worker giao tiếp, cách chia sẻ bộ nhớ thật sự với `SharedArrayBuffer`, dùng `Atomics` để đồng bộ, và vì sao những thứ đó bị khoá sau **cross-origin isolation**.

---

## 1. Worker = context JS riêng, luồng riêng

Mỗi worker có **luồng riêng**, **event loop riêng**, **heap riêng** — không chia sẻ biến với luồng chính. Chúng chỉ nói chuyện qua message.

```text
Main thread (window)          Worker thread
  event loop riêng              event loop riêng
  heap riêng       ◄─postMessage─►  heap riêng
  có DOM                         KHÔNG có DOM
```

Ba loại worker:

| Loại | Phạm vi | Dùng cho |
|---|---|---|
| **Dedicated Worker** | một trang sở hữu | tính toán nặng riêng cho trang |
| **Shared Worker** | nhiều tab cùng origin | chia sẻ trạng thái/kết nối giữa tab |
| **Service Worker** | proxy mạng (Phần 10) | offline, cache, push |

```js
const w = new Worker(new URL('./worker.js', import.meta.url), { type: 'module' });
w.postMessage({ cmd: 'crunch', data });
w.onmessage = (e) => render(e.data);
```

## 2. postMessage: structured clone vs transfer

Mặc định, `postMessage` **sao chép** dữ liệu bằng *structured clone algorithm* (Phần khác trong blog). Object lớn → sao chép tốn kém.

```text
structured clone:  [data] ──copy──► [data']   (cả hai bên đều có bản)
transfer:          [buffer] ──move──► [buffer] (bên gửi MẤT quyền, zero-copy)
```

**Transferable** (`ArrayBuffer`, `MessagePort`, `ImageBitmap`, `OffscreenCanvas`…) được *chuyển quyền sở hữu* — zero-copy, nhưng bên gửi không dùng được nữa:

```js
const buf = new ArrayBuffer(64 * 1024 * 1024);
worker.postMessage({ buf }, [buf]); // transfer list → move, không copy
// buf.byteLength === 0 ở đây: đã mất quyền
```

Dùng transfer cho buffer lớn để tránh chi phí clone. Nhưng transfer vẫn là *chuyển*, không phải *chia sẻ* — chỉ một bên giữ tại một thời điểm.

---

## 3. SharedArrayBuffer — bộ nhớ chia sẻ thật

`SharedArrayBuffer` (SAB) là vùng nhớ **nhiều luồng cùng đọc/ghi đồng thời** — không copy, không transfer. Đây là chia sẻ bộ nhớ thật như trong ngôn ngữ đa luồng.

```js
const sab = new SharedArrayBuffer(1024);
const view = new Int32Array(sab);
worker.postMessage({ sab });   // KHÔNG transfer — cả hai cùng thấy cùng vùng nhớ
// ghi ở luồng này, luồng kia thấy ngay
view[0] = 42;
```

Sức mạnh đi kèm hiểm hoạ: nhiều luồng ghi cùng vị trí → **race condition**. Cần công cụ đồng bộ → `Atomics`.

---

## 4. Atomics — đọc/ghi nguyên tử & đồng bộ

`Atomics` cung cấp thao tác **nguyên tử** (không bị ngắt giữa chừng) trên SAB, và cơ chế chờ/đánh thức kiểu mutex.

```js
const view = new Int32Array(sab);

// Thao tác nguyên tử (an toàn khi nhiều luồng cùng đụng)
Atomics.add(view, 0, 1);          // tăng nguyên tử
const v = Atomics.load(view, 0);  // đọc nguyên tử

// Chờ/đánh thức (chỉ trong worker — Atomics.wait chặn luồng)
// Worker: chặn tới khi view[0] != 0
Atomics.wait(view, 0, 0);
// Main: đặt cờ rồi đánh thức 1 worker đang chờ
Atomics.store(view, 0, 1);
Atomics.notify(view, 0, 1);
```

> `Atomics.wait` chặn luồng — cấm dùng trên luồng chính (sẽ throw). Có `Atomics.waitAsync` không chặn cho main thread. Đây là nền của producer/consumer queue giữa các luồng.

## 5. Cross-origin isolation — vì sao SAB bị khoá

Sau các lỗ hổng Spectre/Meltdown, `SharedArrayBuffer` (và timer phân giải cao) bị tắt mặc định, vì bộ nhớ chia sẻ + timer chính xác cho phép side-channel attack. Để mở lại, trang phải vào trạng thái **cross-origin isolated** bằng hai header:

```text
Cross-Origin-Opener-Policy:   same-origin       (COOP — tách browsing context group)
Cross-Origin-Embedder-Policy: require-corp       (COEP — mọi subresource phải opt-in)
```

```js
if (crossOriginIsolated) {
  // mới được dùng SharedArrayBuffer, performance.measureUserAgentSpecificMemory,
  // và timer performance.now() phân giải cao hơn
}
```

Mô hình: COOP cô lập trang khỏi cửa sổ cross-origin; COEP buộc mọi tài nguyên nhúng phải đồng ý (`Cross-Origin-Resource-Policy` hoặc CORS). Cùng nhau, chúng bảo đảm process này không chứa dữ liệu cross-origin chưa được phép — an toàn để mở SAB. Đây cũng là lý do isolation gắn chặt với **Site Isolation** ở Phần 21.

## 6. Khi nào dùng gì

```text
Tính toán nặng, dữ liệu copy được      → Worker + structured clone
Buffer lớn, gửi một chiều              → Worker + transfer (transferable)
Nhiều luồng cùng truy cập state nóng   → SharedArrayBuffer + Atomics (cần COOP/COEP)
Vẽ canvas 60fps khi main bận           → OffscreenCanvas trong worker (Phần 19)
Chia sẻ giữa nhiều tab                 → SharedWorker / BroadcastChannel
```

Đừng vội dùng SAB: với hầu hết ứng dụng, worker + transfer là đủ và đơn giản hơn nhiều. SAB/Atomics dành cho wasm threads, xử lý audio/video realtime, hoặc cấu trúc dữ liệu chia sẻ hiệu năng cao.

---

## 7. Tóm tắt

- **Web Workers** cho đa luồng thật: mỗi worker có luồng/event loop/heap riêng, không DOM; ba loại dedicated/shared/service.
- `postMessage` mặc định **structured clone** (copy); **transferable** chuyển quyền sở hữu zero-copy (bên gửi mất quyền).
- **`SharedArrayBuffer`** chia sẻ bộ nhớ thật giữa các luồng (không copy/transfer) → cần đồng bộ.
- **`Atomics`** cho thao tác nguyên tử và wait/notify; `Atomics.wait` chặn nên cấm trên luồng chính (dùng `waitAsync`).
- SAB + timer phân giải cao bị khoá sau **cross-origin isolation**: cần `COOP: same-origin` + `COEP: require-corp`; kiểm tra `crossOriginIsolated`.
- Chọn công cụ theo nhu cầu: copy → clone, buffer lớn một chiều → transfer, state nóng đa luồng → SAB+Atomics.

**Phần tiếp theo:** Process model deep — Site Isolation và OOPIF, Back/Forward Cache (BFCache), prerender/speculation rules, và Page Lifecycle API điều phối tài nguyên giữa các tab.
