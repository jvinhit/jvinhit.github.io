Một config Neovim dùng được một tuần thì dễ. Dùng được một năm mới khó.

Phần này nói về bảo trì: nhanh, ổn định, rollback được, sync được giữa máy.

---

## Đo trước khi tối ưu

Startup log:

```bash
nvim --startuptime startup.log
```

Mở file log:

```bash
nvim startup.log
```

Với `lazy.nvim`:

```vim
:Lazy profile
```

Đừng tối ưu theo cảm giác. Plugin nào chậm, event nào load sớm, file nào tốn thời gian, hãy đo.

---

## Checkhealth là bác sĩ gia đình

Chạy định kỳ:

```vim
:checkhealth
:checkhealth vim.lsp
:checkhealth lazy
:checkhealth mason
```

Khi có lỗi:

1. đọc message đầy đủ;
2. xác định lớp lỗi: terminal, provider, LSP, plugin, external tool;
3. sửa từ dependency thấp nhất.

Ví dụ LSP không chạy có thể không liên quan plugin, chỉ là executable không có trong PATH.

---

## Lockfile và rollback

Với `lazy.nvim`, commit:

```text
lazy-lock.json
```

Update workflow:

```vim
:Lazy update
```

Sau update:

1. restart Nvim;
2. mở project thật;
3. chạy `:checkhealth`;
4. test LSP/completion/format;
5. nếu ổn, commit lockfile;
6. nếu hỏng, revert lockfile.

Git là nút undo cho config.

## Cấu trúc dotfiles

Một repo dotfiles đơn giản:

```text
dotfiles/
├─ nvim/
│  ├─ init.lua
│  ├─ lazy-lock.json
│  └─ lua/
│     ├─ config/
│     └─ plugins/
├─ shell/
│  └─ zshrc
└─ README.md
```

Symlink:

```bash
ln -s ~/dotfiles/nvim ~/.config/nvim
```

Hoặc dùng tool như GNU Stow:

```bash
stow nvim
```

Đừng để config chỉ sống trên một máy. Một ngày nào đó bạn sẽ đổi laptop, SSH vào server, hoặc rebuild môi trường.

## Secrets không thuộc về dotfiles

Không commit:

- API keys;
- token GitHub;
- private SSH key;
- company-specific config nhạy cảm;
- đường dẫn local chứa tên khách hàng/project riêng tư.

Nếu cần local override:

```lua
local local_config = vim.fn.stdpath("config") .. "/lua/config/local.lua"
if vim.uv.fs_stat(local_config) then
  dofile(local_config)
end
```

Thêm `lua/config/local.lua` vào `.gitignore`.

## Chống plugin bloat

Mỗi tháng tự hỏi:

| Câu hỏi                                  | Nếu câu trả lời là không |
| ---------------------------------------- | ------------------------ |
| Mình dùng plugin này tuần qua không?     | xóa                      |
| Nó thay được bằng built-in không?        | thử built-in             |
| Nó có làm startup chậm không?            | lazy-load hoặc xóa       |
| Nó có chồng chức năng plugin khác không? | chọn một                 |
| Nó có được maintain không?               | cân nhắc thay            |

Config tốt thường nhỏ hơn bạn nghĩ.

## Debug config có phương pháp

Khi Nvim vỡ:

```bash
nvim --clean
```

Nếu `--clean` chạy ổn, lỗi nằm trong config/plugin.

Disable từng lớp:

1. comment plugin mới thêm;
2. chạy `:messages`;
3. chạy `:Lazy health`;
4. kiểm tra `:verbose map key`;
5. kiểm tra `:verbose set option?`;
6. bisect Git commit dotfiles nếu cần.

Đừng xóa sạch `~/.local/share/nvim` ngay. Đó là biện pháp cuối, không phải reflex.

## Version pinning

Một số plugin nên pin version/branch:

```lua
{
  "saghen/blink.cmp",
  version = "1.*",
}
```

Pin khi:

- plugin có major version mới breaking;
- config production cần ổn định;
- bạn không có thời gian migrate ngay.

Không pin quá chặt mọi thứ nếu bạn không có lý do. Lockfile đã giữ revision hiện tại.

## Bài tập

1. Đưa config vào Git repo.
2. Commit `lazy-lock.json`.
3. Chạy `:Lazy profile`, ghi lại 3 plugin tốn thời gian nhất.
4. Chạy `nvim --clean` để thấy Neovim không config.
5. Xóa hoặc disable một plugin không dùng.

## Điều cốt lõi

Config Neovim là phần mềm cá nhân. Hãy đối xử với nó như code: đo, version, review diff, pin khi cần, rollback được. Một setup pro không phải nhiều plugin; nó là setup **sống lâu mà không làm bạn sợ update**.
