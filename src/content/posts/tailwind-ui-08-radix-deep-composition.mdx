## 1. Uncontrolled vs controlled

Mặc định Radix là **uncontrolled** — nó tự giữ trạng thái mở/đóng (hay checked) bên trong. Bạn đặt giá trị ban đầu rồi quên đi:

```tsx
<Dialog.Root defaultOpen={false}>…</Dialog.Root>
<Switch.Root defaultChecked />
```

Chuyển sang **controlled** khi *bạn* cần điều khiển hoặc theo dõi trạng thái — mở dialog từ nơi khác, đồng bộ URL, hay chạy side effect:

```tsx
const [open, setOpen] = useState(false);

<Dialog.Root open={open} onOpenChange={setOpen}>
  …
</Dialog.Root>

// now you can do this from anywhere:
<button onClick={() => setOpen(true)}>Open from outside</button>
```

Quy tắc: **mặc định uncontrolled; chỉ dùng controlled khi có lý do cụ thể**. Mọi Radix primitive theo cùng quy ước `value`/`onValueChange`, `open`/`onOpenChange`, `checked`/`onCheckedChange`.

## 2. `asChild` — mẫu slot

Mặc định `Dialog.Trigger` render một `<button>`. Nhưng bạn đã có component `Button` đã style (từ Phần 5) — bạn không muốn một button trong button. `asChild` bảo Radix: **đừng render phần tử của bạn; hãy ghép hành vi và props vào con của tôi**:

```tsx
import { Button } from '@/components/ui/button';

<Dialog.Trigger asChild>
  <Button variant="outline">Edit profile</Button>
</Dialog.Trigger>
```

Giờ **không có DOM bọc thừa** — `onClick`, `aria-haspopup`, `aria-expanded`, ref và `data-state` của Radix đều rơi vào `Button` *của bạn*. Đây là cách Radix, shadcn và design system của bạn khớp vào nhau gọn gàng.

> **Điểm vướng:** con của `asChild` phải nhận và forward `ref` cùng spread props. Với function component, nghĩa là `React.forwardRef` (hoặc ref-as-prop) và `{...props}` — nếu không, hành vi ghép vào sẽ âm thầm rơi mất.

Bên dưới `asChild` chạy nhờ component `Slot` của Radix, thứ bạn dùng trực tiếp để dựng component *của mình* có khả năng đa hình, hỗ trợ `asChild`:

```tsx
import { Slot } from '@radix-ui/react-slot';

function Button({ asChild, className, ...props }) {
  const Comp = asChild ? Slot : 'button';
  return <Comp className={cn(buttonVariants(), className)} {...props} />;
}
```

Mẹo này — `Slot` khi `asChild`, ngược lại là thẻ — chính là cách `Button` của shadcn hỗ trợ `asChild`.

## 3. Kết hợp qua các primitive

Mọi Radix primitive chung một mô hình tư duy, nên biết một là biết tất.

**Tabs**:

```tsx
<Tabs.Root defaultValue="account">
  <Tabs.List className="flex gap-1 rounded-lg bg-muted p-1">
    <Tabs.Trigger value="account"
      className="flex-1 rounded-md px-3 py-1.5 text-sm
                 data-[state=active]:bg-indigo-500 data-[state=active]:text-white">
      Account
    </Tabs.Trigger>
    <Tabs.Trigger value="password" className="…">Password</Tabs.Trigger>
  </Tabs.List>
  <Tabs.Content value="account">…</Tabs.Content>
  <Tabs.Content value="password">…</Tabs.Content>
</Tabs.Root>
```

**Switch**:

```tsx
<Switch.Root className="h-6 w-11 rounded-full bg-input data-[state=checked]:bg-indigo-500">
  <Switch.Thumb className="block size-5 rounded-full bg-white transition-transform
                          data-[state=checked]:translate-x-5" />
</Switch.Root>
```

**Tooltip** — cần một `Tooltip.Provider` gần gốc app; mở khi hover *và* focus:

```tsx
<Tooltip.Provider delayDuration={200}>
  <Tooltip.Root>
    <Tooltip.Trigger asChild><Button>Save</Button></Tooltip.Trigger>
    <Tooltip.Portal>
      <Tooltip.Content className="rounded bg-surface px-2 py-1 text-xs
                                 data-[state=delayed-open]:animate-in">
        Saved 2 min ago
        <Tooltip.Arrow className="fill-surface" />
      </Tooltip.Content>
    </Tooltip.Portal>
  </Tooltip.Root>
</Tooltip.Provider>
```

**Popover** — như Dialog nhưng không modal; tốt cho editor và picker inline. Cùng hình `Root`/`Trigger`/`Portal`/`Content`.

## 4. Chiến lược style tái sử dụng

Viết lại cùng class `data-[state=…]` ở mỗi lần dùng không scale. Nước đi pro là **bọc mỗi primitive một lần** với style đã nung sẵn, phơi ra API gọn:

```tsx
// components/ui/switch.tsx — wrap once, use everywhere
import * as SwitchPrimitive from '@radix-ui/react-switch';
import { cn } from '@/lib/utils';

export function Switch({ className, ...props }: React.ComponentProps<typeof SwitchPrimitive.Root>) {
  return (
    <SwitchPrimitive.Root
      className={cn('h-6 w-11 rounded-full bg-input data-[state=checked]:bg-primary', className)}
      {...props}
    >
      <SwitchPrimitive.Thumb className="block size-5 rounded-full bg-white transition-transform data-[state=checked]:translate-x-5" />
    </SwitchPrimitive.Root>
  );
}
```

Nếu thấy đây là nhiều boilerplate qua hàng chục component — **đó chính xác là vấn đề shadcn/ui giải quyết**. shadcn là một bộ *các wrapper này* được tuyển chọn, viết sẵn và copy vào repo của bạn. Đó là Phần 9.

## 5. Bài tập

**1.** Khi nào một component Radix nên controlled thay vì uncontrolled?

<details>
<summary>Lời giải</summary>

Khi bạn cần đọc/đặt trạng thái từ bên ngoài — mở bằng code, đồng bộ URL/store, hay chạy side effect khi đổi.
</details>

**2.** Vì sao `asChild` yêu cầu con forward `ref`?

<details>
<summary>Lời giải</summary>

Radix cần ref tới node DOM thật để quản lý focus, định vị, bấm-ngoài; không forward thì nó không chạm được phần tử và hành vi hỏng.
</details>

**3.** Style một `Tabs.Trigger` để tab active có nền indigo và chữ trắng.

<details>
<summary>Lời giải</summary>

```tsx
<Tabs.Trigger value="x"
  className="data-[state=active]:bg-indigo-500 data-[state=active]:text-white">X</Tabs.Trigger>
```
</details>

Nâng cao:trong lab, bật Switch và Popover và để ý cả hai phơi `data-state` — cùng móc bạn nhắm bằng `data-[state=checked]:` / `data-[state=open]:`.

## Điểm chính

- **Mặc định uncontrolled**; dùng controlled chỉ khi có nhu cầu cụ thể.
- `asChild` (qua `Slot`) ghép hành vi Radix vào phần tử **của bạn** — không DOM bọc; con phải forward `ref` + spread props.
- Mọi primitive chung mô hình `value`/`onValueChange` + `data-state` — học một, biết tất.
- Bọc mỗi primitive một lần với style nung sẵn là mẫu scale được — và đúng thứ shadcn sản phẩm hóa.
