Library TypeScript có hai sản phẩm: JavaScript runtime và trải nghiệm compiler của consumer. Test source pass chưa đủ; declaration emit có thể hỏng hoặc lộ internal type.

## Declaration là public ABI ở tầng type

```json
{
  "compilerOptions": {
    "rootDir": "src",
    "outDir": "dist",
    "declaration": true,
    "declarationMap": true,
    "emitDeclarationOnly": false,
    "stripInternal": true
  }
}
```

Inspect `dist/**/*.d.ts`, không chỉ source. Inferred return type có thể kéo theo private dependency, đường dẫn workspace hoặc generic khổng lồ.

```ts
// public boundary: annotation có chủ đích
export function createClient(options: ClientOptions): Client {
  return new InternalClient(options);
}
```

Annotation ở public export tạo firewall: refactor internals không vô tình đổi type surface.

## Public type phải dùng được từ consumer

```ts
export interface ClientOptions {
  baseUrl: URL;
  fetch?: typeof globalThis.fetch;
}

export interface Client {
  getUser(id: string, options?: { signal?: AbortSignal }): Promise<User>;
}
```

Đừng expose concrete class nếu consumer chỉ cần capability. Interface giảm semver surface và cho phép fake trong test.

## Package metadata phải khớp output

```json
{
  "files": ["dist"],
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js"
    }
  }
}
```

Luôn test tarball (`npm pack`/`pnpm pack`) từ một fixture consumer sạch. Workspace symlink có thể che missing file và dependency sai classification.

## Type test gồm positive và negative

```ts
const user = await client.getUser('usr_1');
user.name satisfies string;

// @ts-expect-error — number không phải user id
await client.getUser(123);
```

`@ts-expect-error` tự fail khi dòng không còn error, nên bắt regression “API trở nên quá rộng”. Thêm test inference, overload, subpath import và declaration compatibility trên TypeScript versions bạn support.

## Type SemVer tinh vi hơn runtime SemVer

Có thể breaking dù JavaScript không đổi:

- thêm property bắt buộc vào exported interface;
- thu hẹp parameter hoặc đổi generic default;
- thêm overload làm inference chọn nhánh khác;
- thay `enum`/class làm nominal behavior đổi;
- expose type mới từ dependency và vô tình bắt consumer cài type đó;
- tăng minimum TypeScript version bằng syntax `.d.ts` mới.

Ngược lại, mở rộng union output thường cũng breaking: consumer exhaustive switch sẽ fail — và compiler đang làm đúng việc.

## Prefer types hay interface?

Không có luật “public luôn interface”. Dùng interface cho object contract có chủ ý cho declaration merging/extension; dùng type cho union, tuple, mapped/conditional composition. Quan trọng hơn là document extension point nào được support.

## Dependency hygiene

Nếu declaration public import type từ package khác, consumer cũng cần resolve nó. Dependency type đó thường phải ở `dependencies` hoặc `peerDependencies`, không chỉ `devDependencies`. Inspect declaration graph để quyết định.

## Lab

1. Build một package, đọc toàn bộ entry `.d.ts` như consumer.
2. Tạo fixture cài tarball và chạy `tsc --noEmit`.
3. Viết type tests cho inference và invalid calls.
4. So sánh public declarations trước/sau refactor; phân loại semver.

**Done khi:** package được test từ artifact đã đóng gói, public declaration nhỏ/ổn định, và release review xét cả runtime lẫn type surface.
