Ở v3 bạn cấu hình Tailwind trong một file JavaScript. Ở **v4 cấu hình nằm trong CSS của bạn**, biểu diễn dưới dạng **design token** với directive `@theme`. Đây là khái niệm v4 quan trọng nhất, và là cầu nối tới shadcn/ui sau này.

---

## 1. Design token là gì

Một **design token** là một quyết định thiết kế có tên — "màu brand là `#6366f1`", "bo card là `12px`" — lưu dưới dạng biến để có *một nguồn sự thật duy nhất*. Đổi token, mọi thứ dùng nó đều cập nhật.

Siêu năng lực của Tailwind v4: **mọi token bạn khai trong `@theme` tự động sinh ra utility tương ứng**.

---

## 2. Directive `@theme`

```css
/* src/index.css */
@import "tailwindcss";

@theme {
  --color-brand: #6366f1;
  --color-brand-foreground: #ffffff;
  --radius-card: 12px;
  --font-display: "Cal Sans", sans-serif;
  --spacing-gutter: 1.25rem;
}
```

Từ năm dòng đó bạn đã có utility dùng được khắp nơi:

```html
<button class="bg-brand text-brand-foreground rounded-card font-display p-gutter">
  Upgrade
</button>
```

Cách đặt tên là một **quy ước ánh xạ namespace token → nhóm utility**:

| Token prefix | Generates | Example |
|---|---|---|
| `--color-*` | `bg-*`, `text-*`, `border-*`, `fill-*`… | `--color-brand` → `bg-brand` |
| `--radius-*` | `rounded-*` | `--radius-card` → `rounded-card` |
| `--font-*` | `font-*` | `--font-display` → `font-display` |
| `--spacing-*` | `p-*`, `m-*`, `gap-*`… | `--spacing-gutter` → `p-gutter` |
| `--text-*` | `text-*` (font-size) | `--text-base` → `text-base` |
| `--shadow-*` | `shadow-*` | `--shadow-card` → `shadow-card` |

Đổi một token và toàn bộ UI đi theo — xem trực tiếp:

> **Token là biến CSS thật.** Chúng được phát vào `:root`, nên bạn cũng đọc được lúc runtime (`var(--color-brand)`) hoặc override trong một scope — đúng cách mà theming và dark mode hoạt động.

## 3. Mở rộng vs thay thế mặc định

Mặc định `@theme` **thêm vào** token có sẵn của Tailwind. `--color-brand` của bạn nhập hội cùng `--color-slate-500`. Muốn **xóa sạch một namespace và bắt đầu mới** (vd bảng màu riêng), reset trước:

```css
@theme {
  /* Drop ALL default colors, keep only what you define */
  --color-*: initial;
  --color-bg: #0a0a0a;
  --color-fg: #e5e5e5;
  --color-brand: #c8ff00;
}
```

Rất hợp với design system kiểm soát chặt, không muốn 22 bảng màu mặc định cám dỗ người ta đi chệch hệ thống.

## 4. Dark mode kiểu v4

Tailwind có sẵn variant `dark:`. Mặc định nó theo OS qua `prefers-color-scheme`:

```html
<div class="bg-white text-slate-900 dark:bg-slate-900 dark:text-slate-100">…</div>
```

Nhưng app thật thường muốn **nút bật tay**. Override variant để dựa vào class `.dark` trên cha:

```css
/* src/index.css */
@import "tailwindcss";

/* Make dark: respond to a .dark class instead of the OS */
@custom-variant dark (&:where(.dark, .dark *));
```

Rồi bật class trên `<html>` từ JS và lưu lựa chọn:

```ts
// Toggle + persist (run before paint to avoid a flash)
const root = document.documentElement;
const isDark = localStorage.theme === 'dark';
root.classList.toggle('dark', isDark);

function toggleTheme() {
  const next = !root.classList.contains('dark');
  root.classList.toggle('dark', next);
  localStorage.theme = next ? 'dark' : 'light';
}
```

Cách **token-driven** scale tốt nhất: định nghĩa token màu ngữ nghĩa, rồi *định nghĩa lại* dưới `.dark`. Component tham chiếu token ngữ nghĩa, không bao giờ rẽ nhánh theo theme:

```css
@theme {
  --color-bg: #ffffff;
  --color-fg: #0f172a;
}

.dark {
  --color-bg: #0b1120;
  --color-fg: #e2e8f0;
}
```

```html
<!-- one class, correct in both themes -->
<div class="bg-bg text-fg">…</div>
```

Mẫu token ngữ nghĩa này *chính xác* là thứ shadcn/ui dùng — Phần 10.

## 5. Giá trị tùy ý — cửa thoát hiểm

Khi một giá trị lẻ không có trong thang, dùng ngoặc vuông — nhưng coi đó là **mùi code**, không phải mặc định:

```html
<div class="top-[117px] bg-[#1da1f2] w-[42ch]">…</div>
```

Nếu bạn dùng cùng một giá trị tùy ý hai lần, **nâng nó thành token** trong `@theme`. Đó là khác biệt giữa codebase trôi dạt và một codebase giữ được tính hệ thống.

## 6. Bài tập

**1.** Định nghĩa token `--color-brand` tùy ý và `--radius-card` là `16px`, rồi dựng nút dùng `bg-brand` và `rounded-card`.

<details>
<summary>Lời giải</summary>

```css
@theme {
  --color-brand: #14b8a6;
  --radius-card: 16px;
}
```
```html
<button class="bg-brand rounded-card px-4 py-2 text-white">Go</button>
```
</details>

**2.** Thiết lập dark mode bật tay (theo class) và làm một card đọc được ở cả hai theme bằng token ngữ nghĩa `bg-bg`/`text-fg`.

<details>
<summary>Lời giải</summary>

```css
@custom-variant dark (&:where(.dark, .dark *));
@theme { --color-bg: #fff; --color-fg: #0f172a; }
.dark { --color-bg: #0b1120; --color-fg: #e2e8f0; }
```
```html
<div class="bg-bg text-fg p-6 rounded-card">Readable in both themes</div>
```
</details>

**3.** Bạn thấy mình viết `mt-[18px]` ở ba file. Sửa thế nào?

<details>
<summary>Lời giải</summary>

Nâng thành token: `--spacing-section: 18px;` trong `@theme`, rồi dùng `mt-section`.
</details>

## Điểm chính

- Cấu hình v4 là **CSS-first**: `@theme` chứa design token.
- **Mỗi token tự sinh utility** theo quy ước namespace.
- Token là biến CSS thật → **override trong `.dark`** để theming gọn, token-driven.
- Giá trị tùy ý `[…]` là cửa thoát; lặp lại nghĩa là nên thành token.
