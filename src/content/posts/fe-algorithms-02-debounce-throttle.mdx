Một số sự kiện trình duyệt bắn ra **dồn dập**: `input`, `scroll`, `resize`, `mousemove`. Gõ "iphone" có thể bắn 6 sự kiện `input` trong nửa giây. Nếu mỗi sự kiện gọi API hoặc tính toán nặng, bạn làm 6 lần việc trong khi chỉ cần 1 lần ở lần gõ cuối.

**Debounce** và **throttle** là hai thuật toán điều tiết tần suất giải quyết đúng vấn đề này. Chúng đơn giản nhưng rất dễ làm sai trong React. Phần này ta tự viết từ con số 0 để hiểu tận gốc.

---

## 1. Phân biệt bằng một hình ảnh

Hãy tưởng tượng người dùng tạo ra các sự kiện liên tục:

```text
events:    x x x x x x x x x        x x x
           └──── burst ────┘
debounce:                     ✓              ✓
           (runs only after STOPPING for a window)

throttle:  ✓     ✓     ✓     ✓      ✓     ✓
           (runs steadily, at most once per window)
```

- **Debounce**: gom một cụm sự kiện thành **một** lần chạy, sau khi người dùng *ngừng* được `wait` mili-giây. Hợp cho "đợi gõ xong rồi mới làm".
- **Throttle**: đảm bảo hàm chạy **đều đặn tối đa 1 lần mỗi `wait`** dù sự kiện bắn liên tục. Hợp cho "cập nhật liên tục nhưng có giới hạn".

| Tình huống | Dùng |
|------------|------|
| Search-as-you-type calling an API | **Debounce** (wait until typing stops) |
| Autosave while typing | **Debounce** |
| Update scroll position / progress bar | **Throttle** |
| Track `mousemove` for drawing | **Throttle** |
| Submit button anti double-click | **Debounce** (leading) |

## 2. Debounce — tự viết từ đầu

Ý tưởng: mỗi lần được gọi, **hủy** lịch hẹn cũ và **đặt lại** một lịch hẹn mới sau `wait` ms. Chỉ khi không có lời gọi nào trong `wait` ms thì hàm thật mới chạy.

```ts
type AnyFn = (...args: never[]) => void;

function debounce<F extends AnyFn>(fn: F, wait: number) {
  let timer: ReturnType<typeof setTimeout> | undefined;

  function debounced(this: unknown, ...args: Parameters<F>) {
    clearTimeout(timer); // cancel old schedule: each call "pushes back" the run time
    timer = setTimeout(() => fn.apply(this, args), wait);
  }

  // Allow manual cancel (e.g. on component unmount)
  debounced.cancel = () => clearTimeout(timer);
  return debounced;
}
```

Dùng cho ô search:

```ts
const search = debounce((query: string) => {
  fetch(`/api/search?q=${encodeURIComponent(query)}`);
}, 300);

input.addEventListener('input', (e) => search((e.target as HTMLInputElement).value));
```

Gõ "iphone" trong 400ms chỉ tạo **một** request, ở 300ms sau ký tự cuối.

### Leading edge: chạy ngay lần đầu

Đôi khi bạn muốn chạy **ngay** lần đầu rồi mới chặn các lần sau (ví dụ chống double-click nút submit). Đó là *leading edge*:

```ts
function debounce<F extends AnyFn>(fn: F, wait: number, leading = false) {
  let timer: ReturnType<typeof setTimeout> | undefined;

  return function (this: unknown, ...args: Parameters<F>) {
    const callNow = leading && timer === undefined;
    clearTimeout(timer);
    timer = setTimeout(() => {
      timer = undefined;
      if (!leading) fn.apply(this, args); // trailing
    }, wait);
    if (callNow) fn.apply(this, args); // leading: run now, then lock
  };
}
```

## 3. Throttle — tự viết từ đầu

Ý tưởng: ghi nhớ **lần chạy gần nhất**. Nếu thời gian từ lần đó chưa đủ `wait`, bỏ qua (hoặc hẹn chạy ở cuối khoảng).

```ts
function throttle<F extends AnyFn>(fn: F, wait: number) {
  let last = 0;
  let timer: ReturnType<typeof setTimeout> | undefined;

  return function (this: unknown, ...args: Parameters<F>) {
    const now = Date.now();
    const remaining = wait - (now - last);

    if (remaining <= 0) {
      // Enough time elapsed → run now (leading edge)
      clearTimeout(timer);
      timer = undefined;
      last = now;
      fn.apply(this, args);
    } else if (timer === undefined) {
      // Not enough yet → schedule trailing run at end of window, don't drop the last call
      timer = setTimeout(() => {
        last = Date.now();
        timer = undefined;
        fn.apply(this, args);
      }, remaining);
    }
  };
}
```

Dùng cho scroll:

```ts
const onScroll = throttle(() => {
  const pct = window.scrollY / (document.body.scrollHeight - innerHeight);
  progressBar.style.width = `${pct * 100}%`;
}, 100); // at most 10 times/sec instead of hundreds

window.addEventListener('scroll', onScroll, { passive: true });
```

> Mẹo: với event lắng nghe để cập nhật UI mượt như scroll, cân nhắc `requestAnimationFrame` thay cho throttle theo thời gian — nó tự đồng bộ với nhịp vẽ của trình duyệt. Ta sẽ bàn ở Phần 8 và 11.

## 4. Cái bẫy khi dùng trong React

Đây là lỗi mọi người mắc ít nhất một lần:

```tsx
// ❌ WRONG: every render creates a NEW debounced function
function Search() {
  const [results, setResults] = useState<Item[]>([]);
  const handle = debounce((q: string) => {
    fetchResults(q).then(setResults);
  }, 300); // old timer is "lost" each render → debounce does nothing
  return <input onChange={(e) => handle(e.target.value)} />;
}
```

Mỗi lần component render lại, `debounce(...)` tạo một closure mới với `timer` mới, nên `clearTimeout` không bao giờ hủy được timer của lần render trước. Debounce coi như không hoạt động.

Cách đúng là **giữ ổn định** hàm debounced qua các lần render. Một custom hook là nơi gói gọn logic này:

```tsx
import { useEffect, useMemo, useRef } from 'react';

// Keep callback fresh but debounced function stable (identity unchanged).
function useDebouncedCallback<A extends never[]>(
  callback: (...args: A) => void,
  wait: number,
) {
  const callbackRef = useRef(callback);
  // Update ref each render so closure always calls the latest callback (avoids stale closure)
  useEffect(() => {
    callbackRef.current = callback;
  });

  const debounced = useMemo(() => {
    let timer: ReturnType<typeof setTimeout> | undefined;
    // Object.assign to attach .cancel while staying type-safe (arrow const can't assign props directly)
    return Object.assign(
      (...args: A) => {
        clearTimeout(timer);
        timer = setTimeout(() => callbackRef.current(...args), wait);
      },
      { cancel: () => clearTimeout(timer) },
    );
  }, [wait]);

  // Clear timer on unmount to avoid setState on a dead component
  useEffect(() => () => debounced.cancel(), [debounced]);
  return debounced;
}
```

```tsx
function Search() {
  const [results, setResults] = useState<Item[]>([]);
  const search = useDebouncedCallback((q: string) => {
    fetchResults(q).then(setResults);
  }, 300);
  return <input onChange={(e) => search(e.target.value)} />;
}
```

Hai chi tiết quan trọng làm hook này "đúng chuẩn senior":

1. **`callbackRef`** tránh *stale closure*: hàm debounced ổn định nhưng vẫn gọi phiên bản callback mới nhất (đọc được state/props hiện tại).
2. **Cleanup khi unmount** tránh cảnh báo "setState on unmounted component" và rò rỉ timer.

## 5. Race condition: request cũ về sau request mới

Debounce giảm số request nhưng **chưa giải quyết** một vấn đề tinh vi: request cho "iphone" có thể về **sau** request cho "iphone 15", ghi đè kết quả đúng bằng kết quả cũ. Cần hủy request lỗi thời bằng `AbortController`:

```ts
let controller: AbortController | undefined;

const search = debounce(async (query: string) => {
  controller?.abort(); // cancel in-flight request from the previous keystroke
  controller = new AbortController();
  try {
    const res = await fetch(`/api/search?q=${query}`, { signal: controller.signal });
    render(await res.json());
  } catch (err) {
    if ((err as Error).name !== 'AbortError') throw err; // ignore errors from our own abort
  }
}, 300);
```

Đây là kết hợp kinh điển: **debounce để giảm số lần gọi + abort để đảm bảo chỉ kết quả mới nhất được hiển thị**.

---

## 6. Khi nào tự viết, khi nào dùng thư viện

Tự viết giúp bạn *hiểu*, và đủ dùng cho hầu hết trường hợp. Nhưng `lodash.debounce` / `lodash.throttle` đã xử lý kỹ các tình huống biên (leading + trailing cùng lúc, `maxWait`, giá trị trả về). Trong dự án thật, dùng thư viện đã kiểm chứng cho logic điều tiết là hợp lý — miễn là bạn hiểu nó làm gì bên trong, đúng như ta vừa mổ xẻ.

---

## Tóm tắt

- **Debounce**: gom cụm sự kiện thành 1 lần chạy *sau khi ngừng* `wait` ms. Hợp với search, autosave.
- **Throttle**: chạy *đều đặn tối đa 1 lần mỗi* `wait` ms. Hợp với scroll, mousemove.
- Trong React, **đừng** tạo hàm debounced trực tiếp trong thân component — dùng hook với `useRef` + `useMemo` và nhớ **cleanup khi unmount**.
- Ghép debounce với `AbortController` để tránh race condition "kết quả cũ ghi đè kết quả mới".

**Phần tiếp theo:** Tìm kiếm & lọc client-side — binary search trên dữ liệu đã sort và fuzzy search để gõ sai vẫn ra kết quả.
