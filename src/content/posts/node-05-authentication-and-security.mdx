Đây là **Phase 5 của lộ trình Super Senior 10 phase**. API của bạn chạy và lưu dữ liệu. Giờ ta làm nó an toàn trên internet mở, nơi mọi endpoint bị dò chỉ vài phút sau khi lên. Bảo mật là nơi đi tắt gây rò rỉ — senior coi nó là mặc định, không phải tính năng.

Trước hết, hai từ người ta hay nhập nhằng:

```text
AUTHENTICATION (authn)          AUTHORIZATION (authz)
"Who are you?"                  "Are you allowed to do this?"
prove identity (login)          check permissions (role / ownership)
        │                                │
        ▼                                ▼
  issue a session/token          gate the route / the row
```

Nhầm chúng là nguồn lỗi kiểm soát truy cập số 1.

## Bản đồ thư viện auth của Node

Bạn không tự viết crypto — bạn lắp ráp các thư viện đã kiểm chứng. Biết mỗi cái *dùng để làm gì*:

| Thư viện | Việc |
| -------------------------- | ----------------------------------------------------- |
| `bcrypt` / `argon2`        | hash mật khẩu |
| `jsonwebtoken`             | ký + xác minh JWT |
| `passport` (+ strategies)  | middleware auth cắm được |
| `express-session`          | session phía server |
| `connect-redis`            | lưu session trong Redis |
| `cookie-parser`            | đọc/ký cookie |
| `helmet`                   | đặt ~15 header bảo mật |
| `express-rate-limit`       | kìm lạm dụng |
| `csrf-csrf` / `csrf-sync`  | token CSRF |
| `zod`                      | validate + type input |

Phân chia tư duy: **bcrypt/argon2 bảo vệ mật khẩu khi lưu; jsonwebtoken/express-session mang danh tính giữa các request; helmet/rate-limit/zod/csrf phòng thủ vành đai**.

## Hash mật khẩu — phải đúng chính xác

Bạn **không bao giờ** lưu mật khẩu, kể cả mã hóa (mã hóa đảo ngược được) — bạn lưu một **hash** một chiều. Và không phải hash *nhanh* như `sha256` — nhanh là dở, vì kẻ trộm DB có thể thử hàng tỷ lần đoán mỗi giây. Dùng thuật toán **chậm, có salt, dành riêng cho mật khẩu**: **bcrypt** hoặc **argon2**.

```ts
import bcrypt from 'bcrypt';

// On register: cost factor 12 ≈ ~250ms per hash (tune to your hardware)
const hash = await bcrypt.hash(plainPassword, 12);

// On login: compare is constant-time and reads the salt+cost FROM the hash string
const ok = await bcrypt.compare(attempt, user.passwordHash);
```

Một hash bcrypt thực chất chứa gì — salt và cost đi *bên trong* nó:

```text
$2b$12$eImiTXuWVxfM37uY4JANjQ.gT1f...   ← stored in the DB
 │   │  └ 22-char salt + 31-char hash
 │   └ cost factor (2^12 = 4096 rounds)
 └ algorithm version (bcrypt)
```

Chi tiết senior tách bạn khỏi tutorial:

- **salt đánh bại rainbow table** — salt ngẫu nhiên riêng mỗi user; bcrypt/argon2 tự sinh và nhúng.
- **cost factor là núm vặn** — tăng khi phần cứng nhanh hơn.
- **bcrypt cắt ở 72 byte** — pre-hash bằng SHA-256 nếu cho phép passphrase rất dài.
- **argon2id tốt nhất hiện nay** — khó về bộ nhớ, kháng GPU; ưu tiên cho hệ thống mới.

```ts
import argon2 from 'argon2';
const hash = await argon2.hash(plainPassword, { type: argon2.argon2id });
const ok = await argon2.verify(user.passwordHash, attempt);
```

> Chống dò tài khoản: trả **cùng một lỗi chung** cho "không có user" và "sai mật khẩu", và lý tưởng là cùng thời gian — nếu không kẻ tấn công biết email nào tồn tại.

## Cookie — công thức an toàn mặc định

Dù dùng session hay JWT, **cookie** thường là cách chứng chỉ đi giữa trình duyệt và server. Mỗi thuộc tính chặn một kiểu tấn công cụ thể:

```text
Set-Cookie: sid=abc123; HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=86400
                         │         │       │             │       │
   JS can't read it ◄────┘         │       │             │       └ lifetime (seconds)
   (blunts XSS theft)              │       │             └ which paths send it
   HTTPS only ◄───────────────────┘       └ not sent on cross-site requests
   (no plaintext leak)                       (blunts CSRF)
```

| Thuộc tính | Chống |
| ------------------------ | --------------------------------------------------- |
| `HttpOnly`               | XSS reading the token via `document.cookie`          |
| `Secure`                 | rò qua HTTP thường |
| `SameSite=Lax/Strict`    | CSRF |
| `__Host-` name prefix    | giả mạo |

```ts
res.cookie('sid', id, {
  httpOnly: true,
  secure: process.env.NODE_ENV === 'production',
  sameSite: 'lax',         // 'strict' for max safety; 'none' (with Secure) only for cross-site
  maxAge: 86_400_000,      // ms in Express
});
```

> Quy tắc vàng: **đừng bao giờ lưu token auth trong `localStorage`** — XSS nào cũng đọc được. Cookie `HttpOnly` vô hình với JS.

## Session (có trạng thái)

Mô hình web kinh điển: server giữ dữ liệu session; cookie chỉ giữ một **id** mờ.

```text
 LOGIN                                       LATER REQUEST
 browser ──email+pw──▶ server                browser ──Cookie: sid=abc──▶ server
                       verify hash                                        look up abc
                       create session abc ──▶ Redis                       in Redis ──▶ user
         ◄─Set-Cookie: sid=abc──                       ◄── response ──
```

```ts
import session from 'express-session';
import { RedisStore } from 'connect-redis';
import { Redis } from 'ioredis';

app.use(session({
  store: new RedisStore({ client: new Redis(process.env.REDIS_URL) }), // shared across servers
  secret: process.env.SESSION_SECRET!,   // signs the cookie so it can't be forged
  resave: false,
  saveUninitialized: false,
  cookie: { httpOnly: true, secure: true, sameSite: 'lax', maxAge: 86_400_000 },
}));
```

Siêu năng lực của session: **thu hồi tức thì** — xóa session trong Redis là user đăng xuất mọi nơi ngay lập tức. Cái giá: một lần tra store mỗi request và một store dùng chung.

## JWT (không trạng thái) — giải phẫu trước

JWT là **ba phần Base64URL nối bằng dấu chấm**: `header.payload.signature`.

```text
eyJhbGciOiJIUzI1NiJ9 . eyJzdWIiOiIxMjMiLCJleHAiOjE3...} . 3Txs9...K2
└──── HEADER ────────┘ └──────── PAYLOAD ───────────┘   └─ SIGNATURE ─┘
 { "alg":"HS256",        { "sub":"123",                   HMAC_SHA256(
   "typ":"JWT" }           "role":"admin",                  header.payload,
                           "iat":1700000000,                secret )
                           "exp":1700604800 }
```

Hai sự thật ngăn mọi lỗi JWT:

1. **payload được *ký*, không *mã hóa*** — ai cũng decode đọc được. Đừng để bí mật trong JWT.
2. **chữ ký chứng minh toàn vẹn** — đổi một ký tự payload là chữ ký không khớp secret nữa, server từ chối.

Các **claim** chuẩn: `sub` ....

```ts
import jwt from 'jsonwebtoken';

const accessToken = jwt.sign(
  { sub: user.id, role: user.role },     // payload (claims)
  process.env.JWT_SECRET!,               // secret (HS256) — or a private key (RS256)
  { expiresIn: '15m', issuer: 'api.example.com' },
);

// Verifying throws on bad signature OR expiry — always wrap in try/catch
try {
  const payload = jwt.verify(token, process.env.JWT_SECRET!, { issuer: 'api.example.com' });
} catch (err) {
  // TokenExpiredError | JsonWebTokenError → respond 401
}
```

HS256 vs RS256: HS256 dùng một **secret** chung. RS256 dùng **private key để ký** và **public key để xác minh** — nhiều service xác minh mà không giữ khóa ký (mô hình OAuth/OIDC).

### Access + refresh token — mẫu production

Access token ngắn hạn giới hạn thiệt hại khi rò; refresh token dài hạn (trong cookie `HttpOnly`) lấy token mới âm thầm.

```text
access token  : 15 min   ── used on every API call (Authorization: Bearer ...)
refresh token : 7 days   ── HttpOnly cookie, used ONLY at /auth/refresh
                            └ stored server-side (Redis) so it can be revoked
```

```ts
// /auth/refresh — rotate: issue a new pair AND invalidate the old refresh token
app.post('/auth/refresh', async (req, res) => {
  const token = req.cookies.refreshToken;
  const payload = jwt.verify(token, process.env.REFRESH_SECRET!) as { sub: string; jti: string };

  // Rotation + reuse-detection: the jti must still be the "current" one in Redis
  const current = await redis.get(`refresh:${payload.sub}`);
  if (current !== payload.jti) {
    await redis.del(`refresh:${payload.sub}`); // reuse detected → revoke the whole family
    return res.status(401).json({ error: 'Token reuse detected' });
  }
  // ...issue new access + new refresh, store new jti, set the cookie...
});
```

Đánh đổi thật: JWT thuần **không thu hồi được trước hạn**. Khi bạn thêm denylist để đăng xuất tức thì là đã tái lập state — ổn thôi, chỉ cần thành thật rằng "stateless" đã thành "gần như stateless".

### Session vs JWT — chọn có cân nhắc

| | Sessions (stateful) | JWT (stateless) |
|---|---|---|
| State ở | server (Redis) | inside the token |
| Thu hồi ngay | ✅ delete session | ❌ valid until expiry |
| Chi phí/request | store lookup | just verify signature |
| Đa server | needs shared store | ✅ none needed |
| Hợp cho | web apps | APIs, mobile, microservices |

Lầm tưởng nguy hiểm: JWT không "an toàn hơn" — chúng khó *thu hồi* hơn.

## Passport.js — strategy cắm được

Passport hợp nhất tất cả sau **strategy** (mỗi phương thức một cái).

```ts
import passport from 'passport';
import { Strategy as LocalStrategy } from 'passport-local';
import bcrypt from 'bcrypt';

passport.use(new LocalStrategy(
  { usernameField: 'email' },
  async (email, password, done) => {
    const user = await User.findOne({ where: { email } });
    // Same generic failure for "no user" and "wrong password" → no enumeration.
    if (!user || !(await bcrypt.compare(password, user.passwordHash))) return done(null, false);
    return done(null, user);
  },
));
```

```ts
import { Strategy as JwtStrategy, ExtractJwt } from 'passport-jwt';

passport.use(new JwtStrategy({
  jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
  secretOrKey: process.env.JWT_SECRET!,
}, async (payload: { sub: string }, done) => {
  const user = await User.findByPk(payload.sub);
  return user ? done(null, user) : done(null, false);
}));
```

## OAuth2 / OIDC — "Đăng nhập với Google"

OAuth2 cho user đăng nhập qua provider mà không đưa bạn mật khẩu. Luồng hiện đại là **Authorization Code + PKCE**:

```text
1. your app ──redirect──▶ Google consent screen
2. user approves
3. Google ──redirect to callbackURL?code=XYZ──▶ your app
4. your server ──exchange code (+ secret/PKCE) for tokens──▶ Google
5. you get an id_token (OIDC) → find-or-create a local user → issue YOUR session/JWT
```

```ts
import { Strategy as GoogleStrategy } from 'passport-google-oauth20';

passport.use(new GoogleStrategy({
  clientID: process.env.GOOGLE_CLIENT_ID!,
  clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
  callbackURL: '/auth/google/callback',
}, async (_at, _rt, profile, done) => {
  const [user] = await User.findOrCreate({
    where: { googleId: profile.id },
    defaults: { email: profile.emails?.[0]?.value, name: profile.displayName },
  });
  return done(null, user);
}));
```

> **OIDC** là tầng danh tính mỏng trên OAuth2, thêm `id_token` (một JWT mô tả user). "Đăng nhập với X" là OIDC.

## Phân quyền — RBAC, permission & sở hữu

**Phân quyền theo vai trò** chặn route theo role:

```ts
const authorize = (...roles: string[]): RequestHandler => (req, res, next) => {
  if (!req.user || !roles.includes(req.user.role)) {
    return res.status(403).json({ error: 'Forbidden' });
  }
  next();
};

app.delete('/users/:id', requireAuth, authorize('admin'), deleteUser);
```

Mịn hơn thì dùng **theo permission** (role *có* permission như `user:delete`). Và quy tắc hay sót nhất: **kiểm tra quyền sở hữu (IDOR), không chỉ đăng nhập**:

```ts
// ❌ Authenticated, but user A can pass user B's id and delete B's post
// ✅ Enforce ownership at the data layer
const post = await Post.findByPk(req.params.id);
if (!post) throw new NotFoundError();
if (post.userId !== req.user.id && req.user.role !== 'admin') throw new ForbiddenError();
```

> **IDOR** là một trong những rò rỉ phổ biến nhất thực tế — luôn giới hạn query theo user hiện tại.

## Các phòng thủ OWASP mọi API Node cần

```ts
import helmet from 'helmet';
import rateLimit from 'express-rate-limit';
import cors from 'cors';

app.use(helmet());                                   // ~15 headers: CSP, HSTS, X-Frame-Options...
app.use(cors({ origin: process.env.FRONTEND_URL, credentials: true })); // never '*' WITH credentials
app.use('/api/', rateLimit({ windowMs: 15 * 60_000, limit: 100 }));
app.use('/auth/login', rateLimit({ windowMs: 15 * 60_000, limit: 10 })); // strict on login
app.use(express.json({ limit: '1mb' }));             // body-size guard
```

Các mối đe dọa và cách sửa trong Node:

- không render dữ liệu chưa tin; đặt CSP; token trong cookie HttpOnly.
- cookie `SameSite` + token CSRF.
- query parameterized; validate bằng Zod.
- allowlist host outbound; chặn IP nội bộ/metadata.
- rate limit chặt + khóa tài khoản/giãn thời gian.
- không viết cứng; nạp từ env; `.env` gitignore; `npm audit`.

```ts
import { z } from 'zod';
const Register = z.object({ email: z.string().email(), password: z.string().min(8) });
// validate at the edge → trust inward (Phase 3)
```

- Hash mạnh; lỗi+thời gian giống nhau.
- Token trong cookie an toàn.
- Access ngắn + refresh xoay vòng có phát hiện tái dùng.

- helmet, CORS khóa origin, rate limit.
- Input validate; query parameterized; giới hạn body.

## 6. Dự án thực hành

1. Auth mật khẩu hoàn chỉnh: xác nhận giá trị lưu là hash và hai lỗi giống nhau.

2. JWT access + refresh có xoay vòng: phát access 15m + refresh 7d trong cookie HttpOnly; dựng `/auth/refresh` có xoay vòng + phát hiện tái dùng và logout thu hồi.

3. Session trong Redis: đổi sang session + Redis; chứng minh đăng xuất tức thì bằng cách xóa session.

4. Đăng nhập OAuth2/OIDC: đấu Google/GitHub với find-or-create và hoàn tất luồng.

5. RBAC + sở hữu: thêm role + permission; chứng minh IDOR trả `403`.

6. Gia cố vành đai: thêm helmet, CORS khóa, rate-limit (chứng minh `429`), Zod, và token CSRF.

## Phần tiếp theo

API của bạn giờ an toàn để mở ra: mật khẩu hash đúng, cookie an toàn, quyết định session-vs-JWT rõ ràng kèm xoay vòng refresh, strategy Passport, đăng nhập OAuth2/OIDC, RBAC + permission kèm kiểm sở hữu, và bộ gia cố OWASP đầy đủ.
