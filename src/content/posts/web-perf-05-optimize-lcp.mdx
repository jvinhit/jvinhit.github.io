LCP (≤ 2.5s) đo khi phần tử nội dung lớn nhất hiển thị xong. Để tối ưu, ta phải chia LCP thành các thành phần thời gian và tấn công cái lớn nhất. Phần này theo đúng khung phân tích của Google.

---

## 1. LCP gồm bốn thành phần thời gian

```text
LCP = TTFB + Resource load delay + Resource load time + Render delay
       │        │                    │                    │
       │        │                    │                    └─ waiting for main thread to paint
       │        │                    └─ time to load the LCP element (image)
       │        └─ time from TTFB until LCP element STARTS loading
       └─ server returns first byte
```

Profiling LCP nghĩa là tìm thành phần nào chiếm nhiều nhất, rồi sửa đúng cái đó. Ba thành phần "delay" thường là chỗ lãng phí nhất.

---

## 2. Giảm TTFB (server response)

TTFB là thời gian server trả byte đầu. TTFB cao kéo *mọi thứ* sau nó trễ theo. Cách giảm:

- **CDN**: phục vụ HTML/asset từ edge gần người dùng (Phần 11).
- **Cache phía server**: cache HTML render (SSG/ISR), cache truy vấn DB.
- **Giảm việc trên đường tới HTML**: tránh truy vấn chậm/đồng bộ trước khi trả HTML.
- **Streaming SSR**: gửi phần đầu HTML ngay trong khi phần sau còn render.

> Với trang tĩnh hoặc SSG, TTFB thường rất thấp vì HTML đã dựng sẵn — đây là lợi thế hiệu năng lớn của static-first (như chính blog này).

---

## 3. Loại bỏ resource load delay (phát hiện phần tử LCP sớm)

Đây là lỗi phổ biến và dễ sửa nhất: phần tử LCP (thường là ảnh hero) bị phát hiện **muộn** vì nó nằm trong CSS background, được nạp bằng JS, hoặc bị các tài nguyên khác chen trước.

```html
<!-- ❌ hero is a CSS background → browser only sees it after CSS parse -->
<div class="hero" style="background-image: url(/hero.jpg)"></div>

<!-- ✅ use <img> for early discovery + preload + high priority -->
<img src="/hero.avif" alt="..." fetchpriority="high" width="1200" height="600" />
```

```html
<!-- preload in <head> so LCP image starts loading immediately, not after CSS/JS (Part 4) -->
<link rel="preload" as="image" href="/hero.avif" fetchpriority="high" />
```

Hai đòn quan trọng nhất cho ảnh LCP: **dùng `<img>` thật** (không CSS background) và **`fetchpriority="high"`** để nó không bị các ảnh/script khác chen hàng.

---

## 4. Giảm resource load time (ảnh tải nhanh hơn)

Khi đã bắt đầu tải sớm, giảm *thời gian tải* phần tử LCP:

- **Định dạng hiện đại**: AVIF/WebP nhỏ hơn JPEG/PNG nhiều (Phần 9).
- **Kích thước đúng**: đừng tải ảnh 4000px để hiển thị 1200px; dùng `srcset`/`sizes` (Phần 9).
- **Nén hợp lý**: chất lượng ~75–80 thường không phân biệt được bằng mắt.
- **Đừng lazy-load ảnh LCP**: `loading="lazy"` cho ảnh hero là phản tác dụng — nó trì hoãn chính phần tử LCP.

```html
<!-- ❌ do NOT lazy-load the LCP image -->
<img src="/hero.avif" loading="lazy" />

<!-- ✅ LCP image loads immediately (eager by default) + high priority -->
<img src="/hero.avif" fetchpriority="high" />
```

---

## 5. Giảm render delay (chặn vẽ)

Đôi khi ảnh đã tải xong nhưng vẫn chưa vẽ vì main thread bận hoặc nội dung chờ thứ khác:

- **JS chặn**: bundle lớn chạy đồng bộ giữ main thread — `defer`/code-split (Phần 4, 8).
- **Font chặn text LCP**: nếu phần tử LCP là text, font tải chậm có thể trì hoãn nó — dùng `font-display: swap` + preload font (Phần 10).
- **Hydration nặng** (SSR framework): hydration đồng bộ lớn có thể chặn — cân nhắc partial/streaming hydration.
- **CSS chặn**: inline critical CSS để render sớm (Phần 4).

---

## 6. Checklist tối ưu LCP

Theo thứ tự "rẻ và hiệu quả nhất trước":

1. Phần tử LCP là **`<img>` thật** (không CSS background)?
2. Có khai báo **`width`/`height`** (cũng giúp CLS — Phần 7)?
3. **`fetchpriority="high"`** + **không** `loading="lazy"` cho ảnh LCP?
4. **`preload`** ảnh LCP / **preconnect** tới CDN ảnh?
5. Ảnh dùng **AVIF/WebP**, kích thước đúng, nén hợp lý?
6. **TTFB** thấp (CDN, cache, SSG)?
7. Nếu LCP là text: **font-display: swap** + preload font?
8. Bundle JS **defer/split** để không chặn render?

> Đo lại sau mỗi thay đổi (Phần 3). LCP thường cải thiện mạnh chỉ với 3 đòn đầu: `<img>` thật + `fetchpriority` + preload.

---

## Tóm tắt

- LCP = **TTFB + load delay + load time + render delay**; tìm thành phần lớn nhất rồi sửa.
- Giảm **TTFB** bằng CDN/cache/SSG (static-first có lợi thế lớn).
- Loại **load delay**: ảnh LCP là `<img>` thật, `fetchpriority="high"`, `preload`.
- Giảm **load time**: AVIF/WebP, kích thước đúng, **không** lazy-load ảnh LCP.
- Giảm **render delay**: defer/split JS, inline critical CSS, font-display swap.

**Phần tiếp theo:** Tối ưu INP — diệt long task, chia nhỏ việc, đẩy tính toán sang web worker.
