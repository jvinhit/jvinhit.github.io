Đây là **Phần 1 của series 12 bài** đưa bạn từ "mở Vim rồi không thoát được" đến dùng **Neovim như editor chính** thay VSCode.

Mục tiêu không phải biến bạn thành người sưu tầm plugin. Mục tiêu là: mở project thật, đọc code nhanh, sửa code tự tin, nhảy định nghĩa, rename symbol, format/lint, chạy test, làm Git, debug, và bảo trì dotfiles mà không sợ vỡ.

Tại ngày **2026-07-09**, baseline của series là:

- Neovim stable 0.12.x.
- Lua config thay vì Vimscript cho cấu hình mới.
- `lazy.nvim` làm plugin manager thực dụng.
- Native LSP mới: `vim.lsp.config()` và `vim.lsp.enable()`.
- `mason.nvim` để cài tool ngoài như LSP, formatter, linter.
- Completion hiện đại với `blink.cmp` stable v1.
- Formatter/linter tách riêng bằng `conform.nvim` và `nvim-lint`.
- Treesitter theo hướng core API của Neovim, tránh tư duy config cũ.

Nếu bạn đọc sau mốc này, hãy kiểm tra lại `nvim --version` và release page. Neovim đang đổi rất nhanh.

---

## Vì sao chuyển từ VSCode sang Nvim?

VSCode mạnh vì mọi thứ hiện sẵn: sidebar, command palette, file explorer, extensions, terminal, Git, debug. Neovim mạnh ở chỗ khác:

- thao tác text cực nhanh bằng modal editing;
- chạy tốt trong terminal, SSH, container, máy yếu;
- config là code Lua, version được bằng Git;
- LSP/formatter/linter/debug đều là các lớp ghép được;
- editor trở thành một phần của workflow shell, không phải một app tách biệt.

Điểm đau khi mới chuyển là bạn mất đi "đường ray" quen thuộc của VSCode. Series này sẽ dựng lại đường ray đó trong Neovim, từng lớp một.

## Stack đề xuất 2025-2026

Đây là stack "ít nhưng đủ":

| Nhu cầu            | Lớp chính                             | Vì sao                                              |
| ------------------ | ------------------------------------- | --------------------------------------------------- |
| Plugin manager     | `lazy.nvim`                           | ổn định, có lockfile, lazy-load tốt                 |
| Cài external tools | `mason.nvim`                          | quản lý LSP/DAP/linter/formatter trong Nvim         |
| LSP configs        | `nvim-lspconfig` + native `vim.lsp.*` | dùng API mới, tránh style cũ                        |
| Completion         | `blink.cmp` v1 stable                 | nhanh, ít phụ thuộc, hỗ trợ LSP/snippet/path/buffer |
| Format             | `conform.nvim`                        | kiểm soát formatter theo filetype tốt               |
| Lint               | `nvim-lint`                           | bổ sung CLI linter ngoài LSP                        |
| Syntax             | Treesitter core + parser tooling      | highlight theo AST, folding, selection              |
| Finder             | Telescope hoặc Snacks picker          | thay Command Palette + Quick Open                   |
| Git                | `gitsigns.nvim`                       | hunk, blame, stage/reset trong buffer               |
| File explorer      | `oil.nvim` hoặc `mini.files`          | thao tác file như edit buffer                       |

Điều quan trọng: mỗi plugin phải trả lời một nhu cầu thật. Nếu bạn chưa biết plugin giải quyết việc gì, đừng cài vội.

## Tư duy khác VSCode

VSCode hỏi: "Bạn muốn click vào UI nào?"

Neovim hỏi: "Bạn muốn biến text hiện tại thành text gì?"

Ví dụ:

| Việc                      | VSCode               | Nvim                                |
| ------------------------- | -------------------- | ----------------------------------- |
| Xóa trong ngoặc           | chọn text bằng chuột | `di(`                               |
| Đổi trong dấu nháy        | click, kéo, gõ lại   | `ci"`                               |
| Di chuyển tới function kế | outline/minimap      | `]m`, search, Treesitter textobject |
| Mở file                   | sidebar hoặc Cmd+P   | picker, buffer, `:edit`             |
| Rename symbol             | F2                   | `grn` hoặc keymap riêng             |
| Code action               | bóng đèn             | `gra`                               |

Người mới thường cố biến Neovim thành VSCode thu nhỏ. Đừng làm vậy. Hãy giữ các năng lực VSCode cần thiết, nhưng học ngôn ngữ thao tác text của Vim.

## Những gì không nên học ngay

Đừng bắt đầu bằng:

- tự viết statusline phức tạp;
- cài 80 plugin theo dotfiles của người khác;
- học Vimscript sâu;
- tối ưu startup khi config mới có 10 plugin;
- tranh luận distro nào tốt nhất.

Hãy bắt đầu bằng:

1. mở, sửa, lưu, thoát;
2. di chuyển không dùng phím mũi tên;
3. text object: word, quote, bracket, paragraph;
4. buffer/window;
5. LSP cơ bản;
6. search/grep;
7. Git/test/terminal.

## Checklist trước khi bắt đầu

Cài các tool nền:

```bash
nvim --version
git --version
rg --version
fd --version
node --version
npm --version
```

Khuyến nghị:

- Neovim 0.12.x nếu có thể.
- `git`, `ripgrep`, `fd`, `curl` hoặc `wget`.
- Nerd Font nếu muốn icon đẹp.
- Node.js nếu làm frontend.
- Một terminal tốt: WezTerm, Ghostty, Alacritty, iTerm2, Windows Terminal.

Nếu thiếu `rg` hoặc `fd`, fuzzy finder vẫn chạy nhưng trải nghiệm grep/file search sẽ kém hơn hẳn.

## Cheatsheet nhập môn

| Phím/lệnh | Ý nghĩa                        |
| --------- | ------------------------------ |
| `i`       | vào Insert mode                |
| `Esc`     | về Normal mode                 |
| `:w`      | lưu                            |
| `:q`      | thoát                          |
| `:wq`     | lưu và thoát                   |
| `:q!`     | thoát bỏ thay đổi              |
| `h j k l` | trái, xuống, lên, phải         |
| `w b e`   | nhảy theo word                 |
| `0 ^ $`   | đầu dòng, ký tự đầu, cuối dòng |
| `gg G`    | đầu file, cuối file            |
| `/text`   | search trong file              |
| `n N`     | kết quả search kế/trước        |
| `u`       | undo                           |
| `<C-r>`   | redo                           |

Quy tắc luyện: mỗi ngày chỉ thêm 3-5 phím mới. Đừng học bằng bảng dài; học bằng việc sửa code thật.

## Bài tập

1. Cài Neovim và chạy `:checkhealth`.
2. Mở một project thật bằng `nvim .`, mở một file, sửa một dòng, lưu, thoát.
3. Trong một file bất kỳ, không dùng chuột và không dùng phím mũi tên trong 10 phút.
4. Ghi lại 5 thao tác VSCode bạn dùng nhiều nhất. Series sẽ map từng thao tác sang Nvim.

<details>
<summary>Gợi ý kiểm tra</summary>

```vim
:checkhealth
:echo stdpath('config')
:echo stdpath('data')
:version
```

Nếu `stdpath('config')` trả về `~/.config/nvim`, đó là nơi ta sẽ tạo config ở phần sau.

</details>
