Kéo-thả là một trong những tương tác *loại trừ* nhiều người nhất: người dùng bàn phím không kéo được, người run tay khó giữ-di-thả chính xác, người dùng cảm ứng với screen reader gần như bất lực. WCAG 2.2 đưa ra tiêu chí **2.5.7 Dragging Movements** (Part 13) buộc mọi thao tác kéo phải có cách thay thế. Phần này xây một sortable list dùng được cho tất cả.

> Nguyên tắc: kéo-thả là *cách tăng cường*, không phải *cách duy nhất*. Luôn có một con đường không cần kéo.

---

## 1. Vì sao native HTML drag-and-drop không đủ a11y

API `draggable="true"` + sự kiện `dragstart`/`drop` của HTML **không** thao tác được bằng bàn phím và hỗ trợ screen reader rất kém trên các nền tảng. Đừng coi nó là giải pháp accessible.

```text
Native DnD (draggable + drop events):
  ✗ không có đường bàn phím
  ✗ screen reader không hiểu "đang kéo cái gì, thả vào đâu"
  ✗ trên cảm ứng thường không hoạt động

→ Cần TỰ xây mô hình thao tác accessible song song.
```

## 2. Mô hình "nhấc – di chuyển – thả" bằng bàn phím

Cách phổ biến và dễ dùng nhất: mỗi item có một **drag handle là `<button>`** thật. Người dùng nhấn Space/Enter để "nhấc", dùng phím mũi tên để di chuyển, Space/Enter để "thả", Esc để hủy.

```html
<ul id="list" aria-label="Thứ tự công việc">
  <li>
    <button type="button" class="handle" aria-describedby="dnd-help">
      <span class="sr-only">Sắp xếp: </span>Viết báo cáo
    </button>
  </li>
  <!-- … -->
</ul>
<p id="dnd-help" class="sr-only">
  Nhấn Space để nhấc, mũi tên lên/xuống để di chuyển, Space để thả, Escape để hủy.
</p>
```

```js
let grabbed = null;

handle.addEventListener('keydown', (e) => {
  const li = handle.closest('li');
  if (e.key === ' ' || e.key === 'Enter') {
    e.preventDefault();
    if (!grabbed) {
      grabbed = li;
      handle.setAttribute('aria-pressed', 'true');
      announce(`Đã nhấc "${label(li)}". Dùng mũi tên để di chuyển.`);
    } else {
      grabbed = null;
      handle.setAttribute('aria-pressed', 'false');
      announce(`Đã thả "${label(li)}" tại vị trí ${index(li) + 1}.`);
    }
  }
  if (grabbed && (e.key === 'ArrowUp' || e.key === 'ArrowDown')) {
    e.preventDefault();
    move(grabbed, e.key === 'ArrowUp' ? -1 : 1);
    handle.focus(); // giữ focus trên handle đang di chuyển
    announce(`Vị trí ${index(grabbed) + 1} trên ${list.children.length}.`);
  }
  if (e.key === 'Escape' && grabbed) { revert(grabbed); grabbed = null; announce('Đã hủy.'); }
});
```

Mỗi bước di chuyển **thông báo vị trí mới** qua live region (Part 16) — đó là "mắt" của người dùng screen reader trong thao tác này.

## 3. Nút di chuyển tường minh — đơn giản & bền nhất

Mô hình nhấc-thả vẫn cần học. Cách *đơn giản nhất* và đạt 2.5.7 chắc chắn: cặp nút **Lên / Xuống** (hoặc menu "Di chuyển tới…").

```html
<li>
  Viết báo cáo
  <button type="button" aria-label="Di chuyển 'Viết báo cáo' lên">▲</button>
  <button type="button" aria-label="Di chuyển 'Viết báo cáo' xuống">▼</button>
</li>
```

```text
Ưu: ai cũng hiểu ngay, không cần chế độ, hoạt động mọi thiết bị.
Nhược: chậm với danh sách dài.
→ Thực dụng: cung cấp CẢ kéo (cho chuột) LẪN nút (cho mọi người).
```

Với danh sách dài, thêm "Move to top/bottom" hoặc một combobox "Chuyển tới vị trí #".

## 4. Pointer events — bao phủ cảm ứng + chuột

Nếu tự xây kéo bằng pointer (thay vì native DnD), dùng **Pointer Events** để hỗ trợ cả chuột, cảm ứng và bút trong một code path. Nhớ tiêu chí **Pointer Cancellation (2.5.2)**: hành động phải kích hoạt khi **nhả** (up), và cho phép hủy bằng cách kéo ra ngoài.

```js
el.addEventListener('pointerdown', (e) => {
  el.setPointerCapture(e.pointerId); // theo dõi pointer kể cả khi ra ngoài el
  startDrag(e);
});
el.addEventListener('pointermove', onDrag);
el.addEventListener('pointerup', (e) => commitDrag(e));   // hành động ở "up", không phải "down"
el.addEventListener('pointercancel', cancelDrag);
```

Đừng phụ thuộc hover để lộ handle: trên cảm ứng không có hover (Part 21). Handle phải luôn hiển thị hoặc hiện khi focus.

## 5. ARIA cho trạng thái kéo (khi cần)

Có thuộc tính ARIA cũ `aria-grabbed`/`aria-dropeffect` nhưng chúng **đã deprecated** và hỗ trợ kém — đừng dùng. Thay vào đó truyền đạt trạng thái bằng:

```text
✅ aria-pressed trên handle (đang nhấc hay không)
✅ live region thông báo: "đã nhấc", "vị trí 3/8", "đã thả", "đã hủy"
✅ aria-describedby trỏ tới hướng dẫn phím tắt
❌ aria-grabbed / aria-dropeffect (deprecated)
```

Sự kết hợp `aria-pressed` + announcement vừa đủ để người dùng SR theo dõi toàn bộ thao tác.

## 6. Tóm tắt

- HTML DnD native (`draggable`) **không** accessible — luôn xây một con đường không cần kéo (WCAG **2.5.7**).
- Mô hình **nhấc–di chuyển–thả** bằng bàn phím: drag handle là `<button>`, Space/Enter nhấc-thả, mũi tên di chuyển, Esc hủy; **thông báo vị trí mỗi bước** qua live region.
- Đơn giản & bền nhất: cặp nút **Lên/Xuống** (kèm `aria-label` mô tả rõ); cung cấp cả kéo lẫn nút.
- Tự xây kéo bằng **Pointer Events** cho chuột/cảm ứng/bút; kích hoạt ở "up" và cho hủy (**2.5.2 Pointer Cancellation**); đừng dựa vào hover.
- Truyền trạng thái bằng `aria-pressed` + live region; **tránh** `aria-grabbed`/`aria-dropeffect` (deprecated).

**Phần tiếp theo:** i18n, RTL & phát âm screen reader — `lang`/`dir`, văn bản hai chiều (bidi), ảnh hưởng của ngôn ngữ tới cách AT đọc, và format số/ngày theo locale một cách accessible.
