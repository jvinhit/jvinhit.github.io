Nếu semantic HTML là nền tảng và quản lý bàn phím/focus giữ người dùng định hướng, **form** là nơi hầu hết app production vẫn trượt audit accessibility. Thiếu label, placeholder giả làm label, hay lỗi chỉ hiện bằng màu đỏ khiến người dùng screen reader đoán field cần gì và liệu họ có sai không.

Phần này đi qua label lập trình, nhóm bằng `fieldset`/`legend`, field bắt buộc và `autocomplete`, validation accessible, và ví dụ React field nối đầy đủ.

---

## 1. Mỗi input cần label lập trình

**Tên accessible** cho form control phải tính được từ DOM — không suy từ placeholder hay `<span>` gần đó mà không liên kết. Ba pattern hợp lệ, theo thứ tự ưu tiên:

| Pattern | HTML | Tốt cho |
|---------|------|---------------------|
| **`for` + `id`** | `<label for="email">Email</label><input id="email">` | Hầu hết field; label và input có thể là sibling |
| **Wrapping label** | `<label>Email <input></label>` | Field một dòng đơn giản |
| **`aria-label` / `aria-labelledby`** | `<input aria-label="Search">` | Chỉ icon hoặc khi không có label hiển thị được |

```html
<!-- ❌ Placeholder is NOT a label — disappears when typing, often low contrast -->
<input type="email" placeholder="Email address">

<!-- ✅ Explicit association — name survives focus and input -->
<label for="signup-email">Email address</label>
<input id="signup-email" name="email" type="email" autocomplete="email">
```

> Placeholder có thể bổ sung label như **gợi ý**, nhưng không bao giờ thay thế label. WCAG **3.3.2 Labels or Instructions** yêu cầu label (hoặc hướng dẫn) cho mọi input.

## 2. Nhóm control liên quan

Nhóm radio, tập checkbox, và khối nhiều field (địa chỉ thanh toán, phần ngày) cần **nhãn nhóm** ngoài label từng field. Dùng **`<fieldset>`** với **`<legend>`** — trình duyệt phơi legend làm tên nhóm cho AT.

```html
<fieldset>
  <legend>Shipping method</legend>

  <label>
    <input type="radio" name="shipping" value="standard">
    Standard (5–7 days)
  </label>
  <label>
    <input type="radio" name="shipping" value="express">
    Express (1–2 days)
  </label>
</fieldset>

<fieldset>
  <legend>Billing address</legend>
  <label for="bill-street">Street</label>
  <input id="bill-street" name="street" autocomplete="street-address">
  <!-- more fields… -->
</fieldset>
```

Với nhóm chỉ mang tính thị giác mà AT không cần tên nhóm, `<div>` với heading styled là đủ — nhưng **radio luôn dùng chung `name` và luôn cần fieldset**. Một `<legend>` mỗi `<fieldset>`; không lồng fieldset trừ khi UX thật sự cần.

## 3. Field bắt buộc và `autocomplete`

### Bắt buộc

Đánh dấu field bắt buộc trên **hai kênh**: thị giác (chữ hoặc dấu sao kèm giải thích) và lập trình.

```html
<label for="name">
  Full name <span aria-hidden="true">*</span>
  <span class="sr-only">(required)</span>
</label>
<input
  id="name"
  name="name"
  required
  aria-required="true"
  autocomplete="name"
>
```

- **`required`** — validation ràng buộc gốc + phơi cho AT trên trình duyệt hỗ trợ.
- **`aria-required="true"`** — thừa nhưng rõ cho AT cũ; vô hại trên input `required` gốc.
- Đừng chỉ dựa màu cho "bắt buộc" — Phần 8 nói về chỉ báo thị giác.

### `autocomplete` — giúp mọi người

Thuộc tính **`autocomplete`** ánh xạ field sang token mà trình duyệt và password manager hiểu (`email`, `given-name`, `postal-code`, v.v.). Tăng tốc nhập liệu cho **mọi** người dùng và đáp **WCAG 1.3.5 Identify Input Purpose** mức AA.

```html
<input id="email" name="email" type="email" autocomplete="email">
<input id="pwd" name="password" type="password" autocomplete="current-password">
<input id="cc" name="cc-number" autocomplete="cc-number" inputmode="numeric">
```

Dùng [token autofill WHATWG](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#autofill-detail-tokens) — `autocomplete="off"` trên form đăng nhập thường **làm hại** accessibility và UX.

## 4. Thông báo lỗi accessible

Lỗi validation phải **cảm nhận được**, **hiểu được**, và **liên kết** với field bị lỗi. Cách nối:

1. Đặt **`aria-invalid="true"`** trên control không hợp lệ.
2. Trỏ **`aria-describedby`** tới `id` phần tử lỗi (và id help text nếu có, cách nhau bằng space).
3. Khi submit fail: **chuyển focus** tới field lỗi đầu tiên **hoặc** tóm tắt lỗi ở đầu.
4. **Thông báo** lỗi qua `role="alert"` hoặc `aria-live="assertive"` để screen reader đọc ngay.

```html
<label for="email">Email</label>
<input
  id="email"
  type="email"
  aria-invalid="true"
  aria-describedby="email-error email-hint"
>
<p id="email-hint">We will never share your email.</p>
<p id="email-error" role="alert">Enter a valid email address.</p>
```

| Technique | Role | Khi nào |
|-----------|------|-----------------|
| `role="alert"` | Implicit `aria-live="assertive"` | Lỗi inline khi blur/submit |
| Error summary + links | `role="alert"` on summary | Form dài nhiều lỗi |
| `aria-invalid="false"` | Clears invalid state | Sau khi người dùng sửa field |

**Đừng** chỉ dựa màu — kết hợp viền đỏ với chữ và `aria-invalid`. Phần 8 đi sâu tương phản và tín hiệu không-màu.

## 5. Help inline với `aria-describedby`

Văn bản gợi ý ("Mật khẩu phải 12+ ký tự") nên nằm trong DOM **trước** hoặc **sau** input và được tham chiếu bởi `aria-describedby`. Screen reader đọc label, rồi mô tả, rồi giá trị.

```html
<label for="password">Password</label>
<input
  id="password"
  type="password"
  aria-describedby="password-requirements"
  autocomplete="new-password"
>
<p id="password-requirements">
  At least 12 characters, one number, and one symbol.
</p>
```

Khi có cả help và lỗi, liệt kê **cả hai** id trong `aria-describedby` — thứ tự ảnh hưởng thứ tự đọc trên vài AT: `aria-describedby="password-requirements password-error"`.

## 6. React form field accessible hoàn chỉnh

Component field tái sử dụng nối label, input, hint, và lỗi với id ổn định:

```tsx
import { useId } from 'react';

type FormFieldProps = {
  label: string;
  name: string;
  type?: string;
  value: string;
  onChange: (value: string) => void;
  error?: string;
  hint?: string;
  required?: boolean;
  autoComplete?: string;
};

export function FormField({
  label,
  name,
  type = 'text',
  value,
  onChange,
  error,
  hint,
  required,
  autoComplete,
}: FormFieldProps) {
  const id = useId();
  const hintId = hint ? `${id}-hint` : undefined;
  const errorId = error ? `${id}-error` : undefined;
  const describedBy = [hintId, errorId].filter(Boolean).join(' ') || undefined;

  return (
    <div className="field">
      <label htmlFor={id}>
        {label}
        {required && (
          <>
            {' '}
            <span aria-hidden="true">*</span>
            <span className="sr-only"> (required)</span>
          </>
        )}
      </label>

      <input
        id={id}
        name={name}
        type={type}
        value={value}
        onChange={(e) => onChange(e.target.value)}
        required={required}
        aria-required={required || undefined}
        aria-invalid={error ? true : undefined}
        aria-describedby={describedBy}
        autoComplete={autoComplete}
      />

      {hint && (
        <p id={hintId} className="hint">
          {hint}
        </p>
      )}

      {error && (
        <p id={errorId} role="alert" className="error">
          {error}
        </p>
      )}
    </div>
  );
}
```

Khi submit form, validate trước, rồi quản lý focus vào cuộc:

```tsx
function SignupForm() {
  const [errors, setErrors] = useState<Record<string, string>>({});
  const firstErrorRef = useRef<HTMLInputElement>(null);

  function handleSubmit(event: React.FormEvent<HTMLFormElement>) {
    event.preventDefault();
    const nextErrors = validate(event.currentTarget);
    setErrors(nextErrors);

    if (Object.keys(nextErrors).length > 0) {
      firstErrorRef.current?.focus();
    }
  }

  return (
    <form onSubmit={handleSubmit} noValidate>
      {/* first field with error gets ref={firstErrorRef} */}
      <FormField label="Email" name="email" /* … */ />
      <button type="submit">Create account</button>
    </form>
  );
}
```

Thư viện như **react-hook-form** + **zod** xử lý logic validation; bạn vẫn giữ **phần nối accessibility** (`aria-*`, focus, alert).

## 7. Lỗi thường gặp — placeholder, disabled, control tùy biến

| Pitfall | Vì sao fail | Sửa |
|---------|------------------------------|------------|
| **Placeholder as label** | Tên biến mất; tương phản thấp | `<label>` hiển thị luôn |
| **`disabled` on submit** | AT bỏ qua field disabled; user không đọc được lý do | Ưu tiên `aria-disabled` + chặn tương tác bằng JS nếu cần trạng thái disabled đọc được |
| **Custom select/combobox** | Mất liên kết label gốc | Theo pattern combobox WAI-ARIA APG; nối `aria-labelledby` |
| **Errors only in toast** | Không liên kết với field | Inline hoặc summary + `aria-describedby` |
| **Silent `novalidate` without custom errors** | Submit có vẻ không làm gì | Luôn đưa lỗi ra DOM |

> `<select>`, `<input type="date">`, và `<button type="submit">` gốc gần như luôn accessible hơn bản rebuild tùy biến hoàn toàn — mở rộng trước khi thay thế.

---

## Tóm tắt

- Mỗi input cần **label lập trình** — `for`/`id`, label bọc, hoặc `aria-label`/`aria-labelledby`; placeholder không bao giờ đủ.
- Nhóm control liên quan bằng **`<fieldset>` + `<legend>`**; nhóm radio luôn cần cả hai.
- Đánh dấu **bắt buộc** thị giác và bằng `required`/`aria-required`; dùng token **`autocomplete`** đúng cho WCAG 1.3.5.
- Lỗi: **`aria-invalid="true"`**, **`aria-describedby`** trỏ text lỗi, **`role="alert"`**, focus lỗi đầu hoặc summary — không chỉ màu.
- Nối id hint và lỗi trong một component; validate khi submit và chuyển focus có chủ đích.

**Phần tiếp theo:** Tên accessible và thay thế ảnh — cách trình duyệt tính tên, viết alt text, và xử lý icon, SVG, biểu đồ.
