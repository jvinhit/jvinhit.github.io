## Nền tảng Express

```bash
npm install express@5
npm install -D @types/express
```

```ts
import express from 'express';

const app = express();

app.use(express.json()); // parse JSON bodies → req.body (replaces Phase 2's readJson)

app.get('/users/:id', (req, res) => {
  res.json({ id: req.params.id });
});

app.listen(3000, () => console.log('http://localhost:3000'));
```

So với Phase 2: không `createServer`, không parse URL, không tự set status/header. Express là **tầng mỏng** trên `http` server: một router, một pipeline middleware, và helper tiện dụng. Bên dưới `app` vẫn là callback `(req, res)` bạn có thể truyền cho `http.createServer(app)` — hữu ích khi cần server thô (cho WebSocket hay tắt êm).

### Vòng đời request

```text
incoming request
   ▼
app-level middleware (helmet, cors, json, logger)   ── runs in order ──┐
   ▼                                                                    │
router match → route-level middleware → route handler                  │ any of these can
   ▼                                                                    │ end the response
res.json() / res.send() ── response sent ◄──────────────────────────── ┘
   ▼ (if next(err) called anywhere)
error-handling middleware (4 args), registered LAST
```

Giữ bức tranh này trong đầu — mọi bug Express là "một middleware chạy sai thứ tự, không gọi `next()`, hoặc kết thúc response hai lần".

## Đào sâu middleware

Một middleware là `(req, res, next) => …` — đúng mẫu `compose`/`next` bạn dựng ở Phase 2, giờ là hạng nhất.

```ts
app.use(express.json());                          // JSON bodies
app.use(express.urlencoded({ extended: true }));  // HTML form posts
app.use(express.static('public'));                // serve files from ./public

// Custom middleware — runs on every request, in registration order
app.use((req, res, next) => {
  const start = performance.now();
  res.on('finish', () => {
    console.log(`${req.method} ${req.path} ${res.statusCode} ${(performance.now() - start).toFixed(1)}ms`);
  });
  next(); // forget this → the request hangs forever
});
```

Năm điều cần thấm:

- **Thứ tự quan trọng** — chạy trên xuống; đăng ký body parser và auth *trước* route cần chúng.
- **Phạm vi** — toàn cục / theo tiền tố path / theo route.
- **Cắt mạch** — có thể *kết thúc* request mà không gọi `next()`.
- `next('route')` bỏ phần còn lại của stack route; `next(err)` nhảy thẳng tới error handler.
- **Gắn dữ liệu suy ra vào `req`**, không tạo global mới — nó theo request và chết cùng request.

> Gõ type cho prop tùy biến: mở rộng `Request` thay vì cast:

```ts
// types/express.d.ts
declare global {
  namespace Express {
    interface Request { user?: { id: string; role: string }; requestId?: string }
  }
}
export {};
```

## Mẫu routing

```ts
app.get('/users', listUsers);              // collection
app.post('/users', createUser);
app.get('/users/:id', getUser);            // req.params.id
app.put('/users/:id', updateUser);
app.delete('/users/:id', deleteUser);

// Chain handlers for one path with app.route to avoid repeating it
app.route('/posts')
  .get(listPosts)
  .post(createPost);
```

biết rõ cái nào là cái nào. Giá trị query luôn là chuỗi; tự ép kiểu và validate.

### Router — tổ chức app đang lớn

`express.Router()` là một **mini-app**: gom route liên quan và middleware riêng của chúng vào module:

```ts
// routes/users.ts
import { Router } from 'express';
const router = Router();

router.use(requireAuth);          // applies to every route in THIS router only
router.get('/', listUsers);
router.post('/', createUser);
router.get('/:id', getUser);

export default router;
```

```ts
// app.ts
import usersRouter from './routes/users.js';
app.use('/api/users', usersRouter); // every route is prefixed with /api/users
```

> **Thay đổi routing Express 5**: đoạn tùy chọn dùng `{}`, wildcard phải **có tên**, chuỗi regex nội tuyến bị bỏ. Nếu route copy từ tutorial cũ chạy sai, đây là lý do.

## Kiến trúc phân tầng — đừng để controller phình

Hình dạng senior: **route → controller → service → repository**. Controller chỉ dịch HTTP qua lại domain; service giữ business logic; repository giữ truy cập dữ liệu.

```ts
// controller — thin: parse input, call service, shape the HTTP response
export const getUser: RequestHandler = async (req, res) => {
  const user = await userService.getById(req.params.id); // throws NotFoundError if missing
  res.json(user);
};

// service — business rules, framework-agnostic (no req/res in here)
export const userService = {
  async getById(id: string) {
    const user = await userRepo.findById(id);
    if (!user) throw new NotFoundError('User not found');
    return user;
  },
};
```

Vì sao? Service **test được không cần HTTP** và **dùng lại** từ CLI, queue worker, hay route khác. Ta chính thức hóa ở Phase 6 và Phase 10.

## Chiến lược xử lý lỗi

Senior tập trung lỗi bằng một cây lỗi có type và một handler toàn cục:

```ts
export class AppError extends Error {
  constructor(message: string, public readonly statusCode: number) {
    super(message);
    this.name = this.constructor.name;
    Error.captureStackTrace?.(this, this.constructor); // clean stack, omits this ctor
  }
}
export class NotFoundError extends AppError { constructor(m = 'Not Found') { super(m, 404); } }
export class ValidationError extends AppError { constructor(m = 'Invalid input') { super(m, 422); } }
export class UnauthorizedError extends AppError { constructor(m = 'Unauthorized') { super(m, 401); } }
```

Error handler được nhận diện qua **bốn** tham số và đăng ký **cuối cùng**:

```ts
import type { Request, Response, NextFunction } from 'express';

// 404 for anything no route matched — registered AFTER all routes, BEFORE the error handler
app.use((req: Request, _res: Response, next: NextFunction) => {
  next(new NotFoundError(`Cannot ${req.method} ${req.path}`));
});

app.use((err: unknown, req: Request, res: Response, _next: NextFunction) => {
  const isApp = err instanceof AppError;
  const status = isApp ? err.statusCode : 500;
  if (!isApp || status >= 500) console.error(`[${req.requestId}]`, err); // log real causes
  res.status(status).json({
    error: {
      message: isApp ? err.message : 'Internal Server Error',
      status,
      // never leak stack traces in production
      ...(process.env.NODE_ENV !== 'production' && err instanceof Error ? { stack: err.stack } : {}),
    },
  });
});
```

Nguyên tắc senior: **lỗi dự kiến thì có type và rõ ràng; lỗi bất ngờ thì log lại và giấu sau 500 chung** — đừng để lộ stack trace cho client.

## Xử lý lỗi async

**Express 5 tự bắt promise bị reject** trong async handler và chuyển tới error handler — cải tiến lớn so với Express 4:

```ts
// Express 5: just throw or let it reject — the framework forwards it.
app.get('/users/:id', async (req, res) => {
  const user = await User.findById(req.params.id);
  if (!user) throw new NotFoundError('User not found');
  res.json(user);
});
```

Để rõ ý định và hành vi đồng nhất, bọc async handler bằng một helper nhỏ:

```ts
import type { Request, Response, NextFunction, RequestHandler } from 'express';

const catchAsync =
  (fn: (req: Request, res: Response, next: NextFunction) => Promise<unknown>): RequestHandler =>
  (req, res, next) => { fn(req, res, next).catch(next); };
```

## Validation

Đừng bao giờ tin input. Hai cách vững.

cho chuỗi nội tuyến trên route:

```ts
import { body, validationResult } from 'express-validator';

app.post('/register',
  body('email').isEmail().normalizeEmail(),
  body('password').isLength({ min: 8 }).matches(/^(?=.*[A-Za-z])(?=.*\d)/),
  (req, res, next) => {
    const errors = validationResult(req);
    if (!errors.isEmpty()) return res.status(422).json({ errors: errors.array() });
    next();
  },
  registerHandler,
);
```

cho validation schema-first còn cho bạn giá trị **đã parse, có type** — lựa chọn của tôi cho code mới:

```ts
import { z } from 'zod';
import type { RequestHandler } from 'express';

const RegisterSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
  age: z.coerce.number().int().positive().optional(), // coerce query strings → number
});

// Reusable validator factory — replaces req.body with the typed, parsed result
const validate =
  (schema: z.ZodType): RequestHandler =>
  (req, _res, next) => {
    const result = schema.safeParse(req.body);
    if (!result.success) return next(new ValidationError(result.error.issues[0].message));
    req.body = result.data; // now strongly typed downstream
    next();
  };

app.post('/register', validate(RegisterSchema), registerHandler);
```

> Validate ở **biên** (route), rồi tin dữ liệu khi đi **vào trong**. Đừng validate lại cùng hình dạng ở mọi service.

## Bộ middleware production

```bash
npm install morgan cors helmet compression express-rate-limit
```

```ts
import morgan from 'morgan';
import cors from 'cors';
import helmet from 'helmet';
import compression from 'compression';
import rateLimit from 'express-rate-limit';

app.disable('x-powered-by');                         // don't advertise Express
app.set('trust proxy', 1);                           // correct req.ip behind a proxy/LB
app.use(helmet());                                   // ~15 security headers (Phase 5)
app.use(cors({ origin: process.env.FRONTEND_URL, credentials: true }));
app.use(compression());                              // gzip/br responses
app.use(express.json({ limit: '1mb' }));             // body-size guard (the Phase 2 lesson)
app.use(morgan(process.env.NODE_ENV === 'production' ? 'combined' : 'dev'));

// Blunt brute-force / abuse at the edge
app.use('/api/', rateLimit({ windowMs: 60_000, limit: 100, standardHeaders: 'draft-7' }));
```

> `trust proxy` quan trọng: sau Nginx/load balancer, `req.ip` là IP của proxy trừ khi bạn tin header `X-Forwarded-For` — rate-limit theo sai IP sẽ thả hết hoặc chặn hết.

## Context request & log có cấu trúc

Gắn request id ở biên và xuyên nó qua log bằng `AsyncLocalStorage` — vô giá để truy vết một request qua nhiều dòng log:

```ts
import { randomUUID } from 'node:crypto';

app.use((req, _res, next) => {
  req.requestId = (req.headers['x-request-id'] as string) ?? randomUUID();
  next();
});
```

Ta đổi `console` sang log JSON có cấu trúc (pino/Winston) ở Phase 6.

## Tắt êm với Express

Giữ tham chiếu tới server bên dưới để xả khi deploy:

```ts
const server = app.listen(3000);

function shutdown(signal: string): void {
  console.log(`${signal} — draining`);
  server.close(() => process.exit(0));   // stop accepting, finish in-flight
  setTimeout(() => process.exit(1), 10_000).unref(); // hard cap
}
process.on('SIGTERM', () => shutdown('SIGTERM'));
process.on('SIGINT', () => shutdown('SIGINT'));
```

## 4. Dự án thực hành

1. REST API đầy đủ (CRUD): dựng lại API `tasks` bằng Express 5, tách `route → controller → service`. Để ý nó ngắn và rõ hơn.

2. Bộ middleware production: ráp helmet, cors, compression, morgan, giới hạn JSON, rate-limit, `trust proxy`, middleware request-id, và logger đo thời gian.

3. Hệ thống lỗi có type: thêm cây lỗi, handler 404 cuối, error handler toàn cục, và `catchAsync`. Kích 404/422/500 và xác nhận hình dạng nhất quán.

4. Tầng validation Zod: dựng factory `validate(schema)` dùng lại; validate body và query trên route tạo; chứng minh `req.body` có type khi đi tiếp.

Bài tập thêm: viết route `*splat`; bảo vệ router bằng `requireAuth`; thêm tắt êm và xác nhận request đang chạy hoàn tất khi `SIGTERM`.
