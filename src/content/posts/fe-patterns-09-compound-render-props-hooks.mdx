React phát triển bộ pattern riêng để giải bài toán "chia sẻ logic và dựng API component linh hoạt" mà GoF không nói tới. Ba pattern quan trọng nhất: **Compound Components**, **Render Props**, và **Custom Hooks**. Hiểu khi nào dùng cái nào là dấu hiệu của một React dev trưởng thành.

---

## 1. Vấn đề: chia sẻ logic mà không lặp code

Giả sử nhiều component cần cùng logic "theo dõi kích thước cửa sổ", "lấy dữ liệu kèm loading/error", "quản lý trạng thái mở/đóng". Cách ngây thơ là copy logic vào từng component. Ba pattern dưới đây giải bài toán này theo ba cách, mỗi cách hợp một tình huống.

---

## 2. Cách mặc định để chia sẻ logic

Hook là cách **được khuyến nghị** và gọn nhất để tách *logic* khỏi *UI*. Logic sống trong hook, UI tự do render theo ý mình.

```ts
// Extract data-fetching logic into a reusable hook — no UI coupling
function useFetch<T>(url: string) {
  const [state, setState] = useState<{ data: T | null; loading: boolean; error: Error | null }>({
    data: null,
    loading: true,
    error: null,
  });

  useEffect(() => {
    let active = true; // guard against setState after unmount / url change
    setState({ data: null, loading: true, error: null });

    fetch(url)
      .then((r) => r.json())
      .then((data) => active && setState({ data, loading: false, error: null }))
      .catch((error) => active && setState({ data: null, loading: false, error }));

    return () => {
      active = false; // cleanup: discard stale results (race condition)
    };
  }, [url]);

  return state;
}
```

```tsx
// UI stays clean because logic is in the hook (Single Responsibility, Part 1)
function UserProfile({ id }: { id: string }) {
  const { data, loading, error } = useFetch<User>(`/api/users/${id}`);
  if (loading) return <Spinner />;
  if (error) return <ErrorBox error={error} />;
  return <h1>{data?.name}</h1>;
}
```

Hook giải quyết đúng điều mà HOC (Phần 8) và render props từng giải, nhưng **không thêm tầng component nào** vào cây — không "wrapper hell", luồng dữ liệu rõ ràng. Đây là lý do cộng đồng React dịch chuyển sang hook.

## 3. API linh hoạt qua Context

Khi bạn xây một component *có nhiều phần phối hợp* (Tabs, Accordion, Select, Menu), ép tất cả vào một prop khổng lồ sẽ cứng nhắc. **Compound components** cho phép người dùng tự sắp xếp các phần con, trong khi các phần chia sẻ trạng thái ngầm qua Context.

```tsx
// ❌ Rigid "config" API — every customization needs a new prop
<Tabs tabs={[{ label: 'A', content: <A /> }, { label: 'B', content: <B /> }]} />

// ✅ Compound API — user lays out freely, still shares implicit state
<Tabs defaultValue="a">
  <Tabs.List>
    <Tabs.Trigger value="a">Tab A</Tabs.Trigger>
    <Tabs.Trigger value="b">Tab B</Tabs.Trigger>
  </Tabs.List>
  <Tabs.Panel value="a"><A /></Tabs.Panel>
  <Tabs.Panel value="b"><B /></Tabs.Panel>
</Tabs>
```

Cài đặt dùng Context để các phần con biết tab nào đang active mà không cần truyền prop thủ công:

```tsx
const TabsContext = createContext<{ active: string; setActive: (v: string) => void } | null>(null);

function useTabsContext() {
  const ctx = useContext(TabsContext);
  if (!ctx) throw new Error('Tabs.* must be used inside <Tabs>'); // guard against misuse
  return ctx;
}

function Tabs({ defaultValue, children }: { defaultValue: string; children: React.ReactNode }) {
  const [active, setActive] = useState(defaultValue);
  return <TabsContext.Provider value={{ active, setActive }}>{children}</TabsContext.Provider>;
}

function Trigger({ value, children }: { value: string; children: React.ReactNode }) {
  const { active, setActive } = useTabsContext();
  return (
    <button aria-selected={active === value} onClick={() => setActive(value)}>
      {children}
    </button>
  );
}

function Panel({ value, children }: { value: string; children: React.ReactNode }) {
  const { active } = useTabsContext();
  return active === value ? <div role="tabpanel">{children}</div> : null;
}

// Attach sub-parts as properties for Tabs.Trigger, Tabs.Panel API
Tabs.List = ({ children }: { children: React.ReactNode }) => <div role="tablist">{children}</div>;
Tabs.Trigger = Trigger;
Tabs.Panel = Panel;
```

Đây là pattern mà Radix UI, Reach UI, và shadcn/ui dùng cho mọi component phức hợp — vì nó cho người dùng **toàn quyền bố cục** mà vẫn giữ logic phối hợp ở trong.

## 4. Truyền hàm render để chia sẻ logic + kiểm soát render

Render props: component nhận một **hàm trả về JSX** làm prop (hoặc children), truyền state nội bộ vào hàm đó. Người dùng quyết định render gì từ state được cung cấp.

```tsx
function MouseTracker({ children }: { children: (pos: { x: number; y: number }) => React.ReactNode }) {
  const [pos, setPos] = useState({ x: 0, y: 0 });
  return (
    <div onMouseMove={(e) => setPos({ x: e.clientX, y: e.clientY })}>
      {children(pos)} {/* hand state to caller; caller renders freely */}
    </div>
  );
}

// Usage: caller has full control over display
<MouseTracker>{({ x, y }) => <p>Cursor at {x}, {y}</p>}</MouseTracker>
```

Phần lớn việc render props từng làm nay hook làm gọn hơn. Nhưng render props vẫn **vô địch** ở một tình huống: khi logic **gắn chặt với một phần JSX cụ thể** mà component cung cấp — ví dụ thư viện virtual list, drag-drop, hay `<Formik>` cũ, nơi component phải bao quanh phần render của bạn.

---

## 5. Chọn pattern nào?

| Nhu cầu | Pattern nên dùng |
|---------|------------------|
| Share **logic** (fetch, state, side-effect) | **Custom Hook** (default) |
| Build **multi-part coordinated** components (Tabs, Select) | **Compound Components** |
| Logic must **wrap JSX** the component provides | **Render Props** |
| Wrap/decorate an entire component (error boundary) | **HOC** (Part 8) |

Thứ tự ưu tiên thực dụng năm nay: **hook trước**, compound khi xây UI primitive nhiều phần, render props/HOC chỉ khi hook không đủ.

---

## 6. Khi nào KHÔNG dùng

- Compound components cho component đơn giản (chỉ một phần) → thừa Context, thêm phức tạp vô ích.
- Render props lồng nhau nhiều tầng → "callback hell" trong JSX, khó đọc; tách thành hook.
- Tách hook quá sớm cho logic chỉ dùng một nơi → chỉ trừu tượng khi có tái dùng thật (nguyên tắc no over-engineering).

---

## Tóm tắt

- **Custom Hooks** là cách mặc định, gọn nhất để chia sẻ *logic* — tách logic khỏi UI, không thêm tầng component.
- **Compound Components** (qua Context) cho API linh hoạt với component nhiều phần — pattern của Radix/shadcn.
- **Render Props** vẫn hợp khi logic phải bao quanh JSX do component cung cấp.
- Chọn theo nhu cầu; ưu tiên hook, dùng compound/render props/HOC khi chúng thực sự phù hợp hơn.

**Phần tiếp theo:** State patterns — Flux/Redux một chiều và State Machine để dập tắt "trạng thái không thể xảy ra".
