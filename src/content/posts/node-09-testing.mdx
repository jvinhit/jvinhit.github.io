## Kim tự tháp & test cái gì

```text
        ╱╲      E2E  — few, slow, high confidence (full system)
       ╱──╲
      ╱ Int ╲   Integration — some, medium (modules + DB/HTTP together)
     ╱──────╲
    ╱  Unit  ╲  Unit — many, fast, isolated (one function/class)
   ╱──────────╲
```

Chiến lược senior: **nhiều unit test nhanh, ít integration test, vài E2E**. Đảo ngược cho bộ test giòn và đau.

Test **hành vi, không phải cài đặt**: khẳng định cái nó trả/ném/đổi, không phải nó gọi method private nào. luôn phủ **edge case và đường lỗi**, không chỉ happy path.

### Test double — dùng đúng từ

| Loại | Làm gì |
| --------------- | ------------------------------------------------------- |
| **dummy**       | nhồi chỗ, không dùng |
| **stub**        | trả giá trị đóng hộp |
| **spy**         | ghi lại cách bị gọi |
| **mock**        | spy có kỳ vọng |
| **fake**        | impl nhẹ |

## Unit test

Unit test kiểm một đơn vị **độc lập** — phụ thuộc được mock. Đây chính là lý do ta dùng DI ở Phase 6. Theo **Arrange–Act–Assert**:

```ts
import { UserService } from '../src/services/UserService';

describe('UserService', () => {
  const repo = { findById: jest.fn(), findByEmail: jest.fn(), create: jest.fn() };
  const service = new UserService(repo as never);
  beforeEach(() => jest.clearAllMocks());

  it('returns a user profile', async () => {
    const mockUser = { id: '1', email: 'a@b.com' };   // Arrange
    repo.findById.mockResolvedValue(mockUser);
    const result = await service.getUserProfile('1');  // Act
    expect(result).toEqual(mockUser);                  // Assert
    expect(repo.findById).toHaveBeenCalledWith('1');
  });

  it('throws when the user is missing', async () => {
    repo.findById.mockResolvedValue(null);
    await expect(service.getUserProfile('999')).rejects.toThrow('User not found');
  });
});
```

Hai kỹ thuật senior: **tham số hóa** ca lặp bằng `it.each`, và **điều khiển thời gian** bằng fake timer:

```ts
it.each([
  ['', 'empty'],
  ['no-at', 'missing @'],
])('rejects invalid email %s', (email) => expect(() => parseEmail(email)).toThrow());

jest.useFakeTimers().setSystemTime(new Date('2026-01-01')); // freeze "now"
```

## Integration test (supertest)

Integration test chạy các module thật cùng nhau bằng HTTP request thật với **supertest**:

```ts
import request from 'supertest';
import { app } from '../src/app';
import { User } from '../src/models/User';

describe('Auth API', () => {
  beforeEach(async () => { await User.destroy({ where: {} }); }); // clean slate

  it('registers a new user', async () => {
    const res = await request(app).post('/auth/register')
      .send({ email: 'new@example.com', password: 'SecurePass123' });
    expect(res.status).toBe(201);
    expect(res.body.token).toBeDefined();
  });

  it('rejects a duplicate email', async () => {
    await User.create({ email: 'dup@example.com', password: 'hashed' });
    const res = await request(app).post('/auth/register')
      .send({ email: 'dup@example.com', password: 'SecurePass123' });
    expect(res.status).toBe(409);
  });
});
```

### Chiến lược database test

Dùng database **thật nhưng vứt được**, không mock — mục đích là test tích hợp thật. **Testcontainers** dựng một Postgres vứt-đi mỗi lần chạy:

```ts
import { PostgreSqlContainer } from '@testcontainers/postgresql';

let container: Awaited<ReturnType<PostgreSqlContainer['start']>>;
beforeAll(async () => {
  container = await new PostgreSqlContainer('postgres:17-alpine').start();
  process.env.DATABASE_URL = container.getConnectionUri();
});
afterAll(() => container.stop());
```

Để cô lập **giữa các test**, mẹo nhanh và đúng nhất là chạy mỗi test **trong một transaction rồi rollback** — reset tức thì.

## Kiểm thử end-to-end

E2E test kiểm cả hành trình xuyên nhiều endpoint, theo thứ tự:

```ts
it('register → fetch profile → update profile', async () => {
  const reg = await request(app).post('/auth/register')
    .send({ email: 'flow@example.com', password: 'SecurePass123' });
  const token = reg.body.token;

  const profile = await request(app).get('/api/users/profile')
    .set('Authorization', `Bearer ${token}`);
  expect(profile.status).toBe(200);

  const updated = await request(app).put('/api/users/profile')
    .set('Authorization', `Bearer ${token}`).send({ firstName: 'Flo' });
  expect(updated.body.firstName).toBe('Flo');
});
```

## Mock dịch vụ bên ngoài

Đừng bao giờ gọi API bên thứ ba thật trong test — chậm, giòn, tốn tiền. **nock** chặn HTTP ra; **msw** tương tự; **faker** sinh dữ liệu thực tế:

```ts
import nock from 'nock';

it('handles the payment provider', async () => {
  nock('https://api.stripe.com').post('/v1/charges').reply(200, { id: 'ch_1', paid: true });
  const result = await paymentService.charge(1000);
  expect(result.paid).toBe(true);
});
```

> Luôn test cả đường **thất bại** — cho mock trả `500`/timeout và khẳng định retry/circuit-breaker hoạt động.

## Fixture & factory

Dữ liệu test viết cứng sẽ mục. Dùng **factory** dựng object hợp lệ với field ghi đè được:

```ts
import { faker } from '@faker-js/faker';

const makeUser = (overrides: Partial<NewUser> = {}): NewUser => ({
  email: faker.internet.email(),
  password: 'SecurePass123',
  ...overrides,                       // override only what the test cares about
});

const admin = makeUser({ role: 'admin' });
```

## Coverage có ý nghĩa

```ts
// jest.config.ts
export default {
  preset: 'ts-jest',
  testEnvironment: 'node',
  setupFilesAfterEach: ['<rootDir>/__tests__/setup.ts'], // connect/clear DB per test file
  collectCoverage: true,
  coverageThreshold: { global: { branches: 80, functions: 80, lines: 80, statements: 80 } },
};
```

Coverage là **sàn, không phải đích**: 80% 80% là lành mạnh, nhưng 100% coverage code tầm thường không có khẳng định edge-case là vô giá trị. Để đo test có *bắt bug* thật không, dùng **mutation testing** (`Stryker`). Chạy test trong CI mỗi push để test fail chặn merge.

## Trình chạy dựng sẵn hiện đại

Node 24 có **trình chạy test dựng sẵn** — không phụ thuộc, TS native, nhanh:

```ts
import { test, describe } from 'node:test';
import assert from 'node:assert/strict';

describe('math', () => { test('adds', () => assert.equal(2 + 2, 4)); });
```

```bash
node --test                          # discover and run *.test.ts
node --test --experimental-test-coverage
```

Senior biết cả hai: Jest vì hệ sinh thái và mock; `node:test` hoặc **Vitest** cho tốc độ.

## Test giòn — dị ứng của senior

Test giòn (lúc đậu lúc rớt) tệ hơn không có test — nó tập cho team phớt lờ màu đỏ. Nguyên nhân và cách sửa: state chung, thời gian thật, mạng thật, phụ thuộc thứ tự, promise chưa await.

## 10. Dự án thực hành

1. Bộ unit (≥80%): unit-test service với repo mock; tham số hóa; áp ngưỡng.

2. Integration với Testcontainers: test bằng supertest với Postgres vứt-đi, cô lập mỗi test bằng transaction rollback.

3. Luồng E2E: khẳng định status và trạng thái mỗi bước.

4. Factory + mock ngoài: dựng factory faker; mock API thanh toán và test cả thành công lẫn thất bại.

5. Cổng CI + mutation testing: đấu bộ test vào pipeline; chạy Stryker và cải thiện một test yếu.

Bài tập thêm: chuyển một file sang `node:test`/Vitest và so thời gian; tìm và sửa một test giòn.
