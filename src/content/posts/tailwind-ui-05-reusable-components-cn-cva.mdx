Phản đối kinh điển với Tailwind — *"nhưng tôi lặp `px-4 py-2 rounded-md …` khắp nơi!"* — có câu trả lời thật, và đó **không** phải `@apply`. Câu trả lời là **component**: trích markup một lần, dùng lại mọi nơi. Phần này dạy đúng bộ công cụ mà shadcn/ui dựng trên đó — nắm chắc giờ thì shadcn sẽ thấy hiển nhiên sau này.

---

## 1. Bản năng đầu tiên: component, không phải `@apply`

```tsx
// Button.tsx — extract once, reuse everywhere
export function Button({ children }: { children: React.ReactNode }) {
  return (
    <button className="rounded-md bg-indigo-500 px-4 py-2 text-white hover:bg-indigo-600">
      {children}
    </button>
  );
}
```

Sao không dùng `@apply`? Vì nó kéo bạn *quay lại* việc đặt tên và bảo trì một stylesheet song song — đúng vấn đề mà utility đã giải quyết. Chỉ dùng `@apply` cho vài primitive toàn cục thật nhỏ. Còn lại: component.

---

## 2. Vấn đề của component cho phép override

Một component thật phải nhận `className` để người gọi tinh chỉnh:

```tsx
function Button({ className, children }) {
  return <button className={`px-4 py-2 bg-indigo-500 ${className}`}>{children}</button>;
}

// caller wants more padding + a different color
<Button className="px-8 bg-emerald-500">Save</Button>;
```

Class render ra là `px-4 py-2 bg-indigo-500 px-8 bg-emerald-500`. Giờ **hai class `px-*` và hai class `bg-*` cùng tồn tại**. Cái nào thắng? Không theo thứ tự trong markup — mà theo **thứ tự trong file CSS sinh ra**, thứ bạn không kiểm soát. Override trở nên không đáng tin.

---

## 3. `clsx` + `tailwind-merge` = `cn()`

Hai thư viện nhỏ sửa điều này:

- dựng chuỗi class từ điều kiện một cách gọn.
- cho một chuỗi class, **loại các class Tailwind xung đột đứng trước** để cái cuối thắng.

```bash
npm install clsx tailwind-merge
```

Gộp thành một helper — `cn` này có trong *mọi* project shadcn:

```ts
// lib/utils.ts
import { clsx, type ClassValue } from 'clsx';
import { twMerge } from 'tailwind-merge';

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}
```

Giờ component có thể dự đoán:

```tsx
import { cn } from '@/lib/utils';

function Button({ className, ...props }) {
  return (
    <button
      className={cn('px-4 py-2 bg-indigo-500 rounded-md', className)}
      {...props}
    />
  );
}
```

... — các `px-4` và `bg-indigo-500` xung đột bị loại bỏ. Xem nó giải quyết trực tiếp ở panel 2 bên dưới.

`clsx` còn làm điều kiện dễ đọc:

```tsx
cn('rounded-md', isActive && 'ring-2 ring-indigo-400', disabled && 'opacity-50')
```

## 4. `cva` — variant type-safe

Nút có *variant* (primary, secondary, destructive) và *size* (sm, lg). Tự viết bằng `if`/ternary rối rất nhanh. **`class-variance-authority` (cva)** là giải pháp chuẩn:

```bash
npm install class-variance-authority
```

```ts
// button-variants.ts
import { cva, type VariantProps } from 'class-variance-authority';

export const buttonVariants = cva(
  // base — always applied
  'inline-flex items-center justify-center gap-2 font-medium transition-colors ' +
  'focus-visible:outline-2 focus-visible:outline-offset-2 disabled:opacity-50 disabled:pointer-events-none',
  {
    variants: {
      variant: {
        default: 'bg-indigo-500 text-white hover:bg-indigo-600',
        secondary: 'bg-zinc-800 text-zinc-100 hover:bg-zinc-700',
        destructive: 'bg-red-600 text-white hover:bg-red-700',
        outline: 'border border-border hover:bg-accent/10',
        ghost: 'hover:bg-accent/10',
      },
      size: {
        sm: 'h-8 px-3 text-sm rounded-md',
        default: 'h-10 px-4 text-sm rounded-lg',
        lg: 'h-12 px-6 text-base rounded-xl',
      },
    },
    defaultVariants: { variant: 'default', size: 'default' },
  }
);

export type ButtonVariants = VariantProps<typeof buttonVariants>;
```

`Button` trở nên mỏng, type đầy đủ, vẫn override được:

```tsx
import { cn } from '@/lib/utils';
import { buttonVariants, type ButtonVariants } from './button-variants';

type ButtonProps = React.ComponentProps<'button'> & ButtonVariants;

export function Button({ className, variant, size, ...props }: ButtonProps) {
  return (
    <button className={cn(buttonVariants({ variant, size }), className)} {...props} />
  );
}
```

```tsx
<Button>Default</Button>
<Button variant="destructive" size="lg">Delete</Button>
<Button variant="outline" className="w-full">Full width outline</Button>
```

TypeScript giờ tự gợi ý `variant` và `size` và từ chối gõ sai. Mẫu `cva` + `cn` này **chính là** hình hài của mọi component shadcn — bạn sẽ nhận ra ngay ở Phần 9.

## 5. `compoundVariants` — nét pro

Khi các *tổ hợp* cần xử lý riêng, dùng `compoundVariants`:

```ts
cva('…', {
  variants: { variant: { outline: '…', ghost: '…' }, size: { icon: 'size-9 p-0' } },
  compoundVariants: [
    // only when variant=outline AND size=icon
    { variant: 'outline', size: 'icon', class: 'border-dashed' },
  ],
});
```

Cách này giữ variant phổ biến sạch mà vẫn diễn đạt được các ca đặc biệt hiếm.

## 6. Bài tập

**1.** Viết helper `cn()` từ trí nhớ và giải thích vì sao chỉ `clsx` là chưa đủ.

<details>
<summary>Lời giải</summary>

```ts
export const cn = (...i: ClassValue[]) => twMerge(clsx(i));
```
`clsx` chỉ nối chuỗi — không biết `px-4` và `px-8` xung đột. `tailwind-merge` hiểu Tailwind và chỉ giữ cái cuối.
</details>

**2.** Đoán kết quả của `cn('p-2 text-sm', 'p-6')`.

<details>
<summary>Lời giải</summary>

`p-2` bị loại vì xung đột với `p-6`.
</details>

**3.** Thêm variant `link` (trông như link chữ gạch chân) vào `buttonVariants` ở trên.

<details>
<summary>Lời giải</summary>

```ts
variant: {
  // …
  link: 'text-indigo-500 underline-offset-4 hover:underline',
}
```
</details>

Nâng cao:trong panel merge, gõ override xung đột ở `rounded-*` và xác nhận cái trước bị gạch ngang.

---

## Điểm chính

- Lặp lại được giải quyết bằng **component**, không phải `@apply`.
- `cn() = twMerge(clsx(...))`: `clsx` cho điều kiện, `tailwind-merge` để **override thắng chắc chắn**.
- `cva` cho **prop variant + size type-safe**; `compoundVariants` xử lý tổ hợp.
- Hình hài `cva` + `cn` này **chính là** mọi component shadcn.
