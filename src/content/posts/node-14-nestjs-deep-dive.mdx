Đây là **Bonus Phase 14**. Bạn lưu trữ được (Phase 11–12) và tăng tốc với Redis (Phase 13); giờ ta cho tất cả một cấu trúc. Suốt series bạn tự dựng pipeline middleware, DI container, kiến trúc phân tầng, validation, guard, và error handler. **NestJS** là điều xảy ra khi các mẫu đó được chính thức hóa thành một framework có chủ kiến, đầy đủ pin. Vì bạn hiểu nền tảng bên dưới, Nest sẽ như *đặt tên cho thứ bạn đã biết*.

Nest ưu tiên TypeScript, **ưu tiên dependency injection**, và chạy trên Express (hoặc Fastify) bên dưới.

## Vì sao cần framework như Nest

Express thô cho tự do và không cấu trúc — mỗi team tự bịa folder, DI, quy ước. Nest cung cấp **kiến trúc chuẩn** và một **DI container** thật, nên team lớn build nhất quán và test được.

```bash
npm i -g @nestjs/cli
nest new my-api
nest g resource users    # scaffolds module + controller + service + DTOs + tests
```

## Các khối xây dựng

```text
Module ── groups a feature (imports, controllers, providers, exports)
  ├── Controller ── HTTP layer: routes, params (thin — like Phase 3)
  └── Provider/Service ── business logic, injected via DI (Phase 6)
```

### Module

Module ráp một feature; `AppModule` là gốc:

```ts
import { Module } from '@nestjs/common';

@Module({
  imports: [PrismaModule],        // other modules this one depends on
  controllers: [UsersController],
  providers: [UsersService],
  exports: [UsersService],        // make UsersService available to importing modules
})
export class UsersModule {}
```

### Controller — tầng HTTP mỏng

```ts
import { Controller, Get, Post, Param, Query, Body, HttpCode } from '@nestjs/common';

@Controller('users')                          // route prefix /users
export class UsersController {
  constructor(private readonly users: UsersService) {} // injected by DI

  @Get()
  findAll(@Query('page') page = '1') { return this.users.findAll(Number(page)); }

  @Get(':id')
  findOne(@Param('id') id: string) { return this.users.findOne(id); } // 404 thrown in service

  @Post()
  @HttpCode(201)
  create(@Body() dto: CreateUserDto) { return this.users.create(dto); }
}
```

Để ý cái biến mất so với Phase 3: không `res.status().json()` tay, không đấu router — decorator khai báo route và Nest serialize giá trị trả.

### Provider & DI

`@Injectable()` đánh dấu một class mà container có thể tạo và tiêm:

```ts
import { Injectable, NotFoundException } from '@nestjs/common';

@Injectable()
export class UsersService {
  constructor(private readonly prisma: PrismaService) {} // constructor injection

  findAll(page: number) { return this.prisma.user.findMany({ skip: (page - 1) * 20, take: 20 }); }

  async findOne(id: string) {
    const user = await this.prisma.user.findUnique({ where: { id } });
    if (!user) throw new NotFoundException('User not found'); // → automatic 404
    return user;
  }
}
```

Đây là **mẫu repository + service (Phase 6)** và **đảo ngược phụ thuộc (Phase 10)**, giờ được framework thực thi. Provider tùy biến và **scope** hoạt động đúng như container bạn đã dựng.

## DTO & validation

Một **DTO** định nghĩa hình dạng dữ liệu đến; `ValidationPipe` toàn cục validate và biến đổi:

```ts
import { IsEmail, IsString, MinLength } from 'class-validator';

export class CreateUserDto {
  @IsEmail() email!: string;
  @IsString() @MinLength(8) password!: string;
}
```

```ts
// main.ts — turn it on globally, and strip unknown fields
app.useGlobalPipes(new ValidationPipe({ whitelist: true, transform: true }));
```

`whitelist: true` bỏ thuộc tính không có trong DTO; `transform: true` ép payload về class DTO và kiểu nguyên thủy. Ưu tiên **nestjs-zod** nếu muốn Zod làm nguồn sự thật duy nhất.

## Vòng đời request — pipeline của Nest

Đây là pipeline middleware Phase 2/3, chính thức hóa thành các giai đoạn có tên, có thứ tự:

```text
request
  ▼
Middleware ─▶ Guards ─▶ Interceptors(pre) ─▶ Pipes ─▶ Handler
                                                          │
response ◄── Interceptors(post) ◄─────────────────────────┘
  ▲
Exception Filter  (catches anything thrown anywhere above)
```

### Guard — phân quyền

Guard trả true/false để cho qua — hợp cho auth và RBAC (Phase 5):

```ts
import { Injectable, CanActivate, ExecutionContext } from '@nestjs/common';
import { Reflector } from '@nestjs/core';

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private readonly reflector: Reflector) {}
  canActivate(ctx: ExecutionContext): boolean {
    const required = this.reflector.get<string[]>('roles', ctx.getHandler());
    if (!required) return true;
    const { user } = ctx.switchToHttp().getRequest();
    return required.includes(user?.role);   // false → automatic 403
  }
}
```

```ts
// A custom @Roles('admin') decorator attaches metadata the guard reads
export const Roles = (...roles: string[]) => SetMetadata('roles', roles);

@Post() @Roles('admin') @UseGuards(JwtAuthGuard, RolesGuard)
remove(@Param('id') id: string) { /* ... */ }
```

### Interceptor — bọc handler

Interceptor chạy trước *và* sau handler — lý tưởng cho định hình response, log, đo thời gian, cache:

```ts
@Injectable()
export class TransformInterceptor implements NestInterceptor {
  intercept(_ctx: ExecutionContext, next: CallHandler): Observable<unknown> {
    return next.handle().pipe(map((data) => ({ data, timestamp: Date.now() })));
  }
}
```

### Exception filter — lỗi tập trung

Họ `HttpException` sẵn có lo phần lớn; một filter tùy biến hình dạng response (error handler toàn cục Phase 3, chính thức hóa):

```ts
@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    const res = host.switchToHttp().getResponse();
    const status = exception instanceof HttpException ? exception.getStatus() : 500;
    res.status(status).json({ error: { status, message: /* ... */ '' } });
  }
}
```

## Database, config & việc async

Bọc `PrismaClient` trong một provider tiêm được và export từ một module:

```ts
@Injectable()
export class PrismaService extends PrismaClient implements OnModuleInit, OnModuleDestroy {
  async onModuleInit() { await this.$connect(); }
  async onModuleDestroy() { await this.$disconnect(); } // graceful shutdown (Phase 7)
}
```

## Kiểm thử

DI của Nest khiến test dễ — đổi provider thật bằng mock qua testing module:

```ts
import { Test } from '@nestjs/testing';

const moduleRef = await Test.createTestingModule({
  providers: [
    UsersService,
    { provide: PrismaService, useValue: mockPrisma }, // inject a fake
  ],
}).compile();

const service = moduleRef.get(UsersService);
```

Cho end-to-end, khởi động app và lái bằng **supertest**, lý tưởng với Postgres Testcontainers.

## Nest vs Express thô — chọn lựa

| | Express (Phase 3) | NestJS |
|---|---|---|
| Cấu trúc | you decide | enforced, standard |
| DI | bring your own | built-in |
| Mã khuôn | minimal | more upfront |
| Hợp cho | small/bespoke services | large teams, long-lived apps |

Quan điểm senior: dùng Nest khi **quy mô team và tuổi thọ** xứng với cấu trúc; service nhỏ tập trung có thể vui hơn với Express/Fastify thuần.
