Bạn đã xong series Tailwind, Radix & shadcn/ui — bạn *đọc, dựng, theme và mở rộng* được component. Series mới này trả lời câu mọi kỹ sư gặp: **làm sao những mảnh đó thành một app thật, ship được?**

Qua **12 phần** ta dựng **Pulse** — một dashboard CRM/SaaS nhỏ — từ đầu đến cuối. Stack này là thứ team React senior thật sự ship:

| Styling / components | **Tailwind v4 + shadcn/ui** | 2 |
| Routing | **React Router v7** (data mode) | 3 |
| Server state | **TanStack Query** | 4–5 |
| Forms | **react-hook-form + zod** | 6 |
| Client state | **Zustand** | 7 |
| Quality | **Vitest + Testing Library + MSW** | 11 |

Lần này không có playground nhúng — **bản thân app là demo**. Phần 1 là nền móng mọi thứ đứng trên: bộ công cụ và bộ khung project.

```text
pulse/
├─ .oxlintrc.json          # lint rules
├─ .oxfmtrc.jsonc          # format rules
├─ .env.example            # documented env contract (committed)
├─ .env.local              # real values (gitignored)
├─ index.html
├─ package.json
```

## 1. Vì sao pnpm

*Docs: [pnpm motivation](https://pnpm.io/motivation).*

### Vấn đề

`npm` và Yarn Classic chép mọi dependency vào `node_modules` của từng project, và layout hoist phẳng cho phép code `import` package bạn chưa khai báo — **phantom dependency**. Trên app thật với hàng trăm package, đó là cài chậm, hàng GB file trùng, và lockfile không thật sự đảm bảo những gì bạn import.

### Công cụ: store địa chỉ-theo-nội-dung + symlink

pnpm lưu mỗi phiên bản package **một lần** trong store toàn cục địa chỉ-theo-nội-dung, rồi hard-link vào `node_modules` của từng project. `node_modules` đó là cây *nghiêm ngặt*: chỉ import được thứ đã khai báo trong `package.json`.

```text
npm:   project-a/node_modules/lodash   (full copy)
       project-b/node_modules/lodash   (another full copy)

pnpm:  ~/.pnpm-store/v3/.../lodash@4.x  (stored once)
       project-a/node_modules/lodash → hard-linked from the store
       project-b/node_modules/lodash → hard-linked from the store
```

Ba lợi ích đến từ thiết kế đó: cài nhanh (chủ yếu link, không chép), dung lượng đĩa giảm mạnh, và **phantom dependency thành bất khả** — quên thêm package thì import lỗi ngay thay vì chạy nhờ ăn may.

### Ghim version để mọi máy và CI khớp

Dùng **Corepack** (đi kèm Node) và ghim pnpm trong `package.json`, để đồng nghiệp hay CI không cài bằng major version khác:

```bash
corepack enable
```

```jsonc
// package.json
{
  "packageManager": "pnpm@9.15.0",
  "engines": { "node": ">=20" }
}
```

Một `.npmrc` nhỏ làm cài nghiêm và dự đoán được:

```ini
# .npmrc
engine-strict=true        # refuse to install on the wrong Node version
auto-install-peers=true   # install peer deps automatically
```

### Lỗi thường gặp

- **Công cụ giả định layout hoist** — vài package cũ mong `node_modules` phẳng. pnpm xử lý hầu hết qua `node-linker`; chỉ dùng `public-hoist-pattern` khi thật sự hỏng.
- **Trộn package manager** — commit cả `package-lock.json` lẫn `pnpm-lock.yaml` làm CI rối. Chọn một; xóa cái còn lại.

### Tóm tắt một dòng

pnpm = một store toàn cục + `node_modules` nghiêm ngặt → cài nhanh, ít đĩa, không phantom import; ghim qua `packageManager` để tái lập.

## 2. Dựng app — Vite + React + TypeScript

*Docs: [Vite — scaffolding](https://vite.dev/guide/#scaffolding-your-first-vite-project).*

Vite đã có series riêng — ở đây ta chỉ *dùng* nó. Dựng SPA React + TypeScript:

```bash
pnpm create vite@latest pulse --template react-ts
cd pulse
pnpm install
pnpm dev
```

Template cho bạn `index.html` (entry của Vite, nạp `/src/main.tsx` như ES module gốc), `src/main.tsx` (mount React vào `#root`), `vite.config.ts`, và — quan trọng — **config TypeScript tách đôi**.

### Vì sao ba file tsconfig

Vite tách config vì **code app** (DOM, trình duyệt) và **file config** (`vite.config.ts`, Node) chạy ở môi trường khác và cần `lib`/`types` khác:

```jsonc
// tsconfig.json — a solution file that references the two real configs
{
  "files": [],
  "references": [
    { "path": "./tsconfig.app.json" },
    { "path": "./tsconfig.node.json" }
  ]
}
```

Config app là nơi đặt strict và alias:

```jsonc
// tsconfig.app.json
{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["ES2023", "DOM", "DOM.Iterable"],
    "jsx": "react-jsx",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "verbatimModuleSyntax": true,

    /* the lines that make refactoring safe */
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "noFallthroughCasesInSwitch": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,

    /* path alias (mirrored in vite.config.ts below) */
    "baseUrl": ".",
    "paths": { "@/*": ["src/*"] }
  },
  "include": ["src"]
}
```

Các flag đáng giá:

- bật `noImplicitAny`, `strictNullChecks`,… Không thương lượng; chính nó làm refactor lớn an toàn.
- `arr[0]` có type `T | undefined`, buộc xử lý trường hợp rỗng. Chặn cả một lớp crash `undefined`.
- làm `import type` rõ ràng để bundler xóa type sạch và không vô tình ship import chỉ-type thành code runtime.
- code chết làm fail typecheck thay vì mục ruỗng.

### Config Vite

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import tailwindcss from '@tailwindcss/vite'; // added in Part 2
import { fileURLToPath, URL } from 'node:url';

export default defineConfig({
  plugins: [react(), tailwindcss()],
  resolve: {
    alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) },
  },
});
```

### Tóm tắt một dòng

`pnpm create vite` cho vỏ SPA nhanh; tsconfig tách giữ app vs Node nghiêm, và bật `strict` + `noUncheckedIndexedAccess` trước khi viết feature đầu.

## 3. Lint & format bằng oxlint + oxfmt

*Docs: [oxlint config](https://oxc.rs/docs/guide/usage/linter/config.html) · [oxfmt config](https://oxc.rs/docs/guide/usage/formatter/config.html).*

### Vấn đề

Setup kinh điển là ESLint + Prettier + một đống plugin và config chia sẻ. Chạy được, nhưng trên codebase thật thì *chậm* (lint nhiều giây), và config tràn lan, với rule Prettier đánh nhau với rule stylistic của ESLint.

### Công cụ: bộ Oxc

`oxlint` và `oxfmt` viết bằng Rust, chạy **nhanh hơn 40–100×** — lint từ vài giây xuống mili-giây. `oxlint` có sẵn rule React, import, TypeScript — không phải quản lý version plugin.

```bash
pnpm add -D oxlint oxfmt
pnpm exec oxlint --init   # writes .oxlintrc.json
pnpm exec oxfmt --init    # writes .oxfmtrc.jsonc
```

### Config: rule lint

`.oxlintrc.json` cho phép comment (như JSONC) và cố ý gần hình ESLint v8 nên đọc quen:

```jsonc
// .oxlintrc.json
{
  "$schema": "./node_modules/oxlint/configuration_schema.json",
  "plugins": ["react", "react-hooks", "typescript", "import"],
  "categories": {
    "correctness": "error",   // real bugs
    "suspicious": "warn"
  },
  "rules": {
    "eqeqeq": "error",
    "no-console": "warn"
  },
  "ignorePatterns": ["dist", "coverage", "node_modules"]
}
```

- bật bộ rule có sẵn (không cài). `react-hooks` ép rules-of-hooks và exhaustive deps.
- bật cả nhóm cùng lúc.
- override từng rule, kiểu ESLint.

### Config: định dạng

`oxfmt` gần như tương thích Prettier nên output khớp thứ team đã quen:

```jsonc
// .oxfmtrc.jsonc
{
  "printWidth": 100,
  "singleQuote": true,
  "semi": true,
  "trailingComma": "all",
  // the Prettier Tailwind plugin is built in — class strings stay in canonical order
  "sortTailwindcss": {}
}
```

`sortTailwindcss` nghĩa là chuỗi `className` tự sắp theo thứ tự chuẩn của Tailwind, **không cần plugin thêm**.

### Script

```jsonc
// package.json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc -b && vite build",
    "preview": "vite preview",
    "lint": "oxlint",
    "lint:fix": "oxlint --fix",
    "format": "oxfmt .",
    "format:check": "oxfmt --check .",
    "typecheck": "tsc --noEmit -p tsconfig.app.json"
  }
}
```

### Cổng pre-commit

Chặn code chưa format hoặc lint lỗi bị commit — nhanh tới mức không ai để ý. Ta dùng **husky** để quản lý git hook và **lint-staged** để chạy công cụ chỉ trên file đã stage:

```bash
pnpm add -D husky lint-staged
pnpm exec husky init   # creates .husky/ + adds the "prepare" script
```

`husky init` viết script `prepare` để hook tự cài sau mỗi `pnpm install` (kể cả trong CI và máy đồng nghiệp):

```jsonc
// package.json
{
  "scripts": { "prepare": "husky" },
  "lint-staged": {
    "*.{ts,tsx}": ["oxlint --fix", "oxfmt"],
    "*.{json,css,md}": ["oxfmt"]
  }
}
```

Rồi đặt lệnh thật vào file hook:

```bash
# .husky/pre-commit
pnpm exec lint-staged
```

`lint-staged` chỉ chạy trên file đã stage nên hook giữ dưới một giây dù repo lớn; `pnpm exec` đảm bảo nó dùng binary ghim cục bộ, không phải bản global lạc.

### Một ví dụ cụ thể

Bạn viết `if (status == 'active')` và quên khai báo một import đang dùng:

```text
$ pnpm lint
  ⚠ eqeqeq: expected '===' and instead saw '=='   src/lib/customers.ts:12
  ✖ no-undef: 'Customer' is not defined            src/lib/customers.ts:3

Finished in 38ms   (ESLint would take ~3s on the same tree)
```

### Lỗi thường gặp

- **Mong oxlint phủ 100% rule ESLint** — nó phủ rule giá trị cao, không mọi rule plugin hiếm. Với hầu hết app đó là điểm cộng.
- **Chạy oxfmt và Prettier cùng lúc** — chọn một, nếu không chúng đánh nhau khi save. Ta dùng oxfmt.
- **Quên extension editor** — cài extension *Oxc* để lint/format khi save với đúng config CI dùng.

### Tóm tắt một dòng

oxlint + oxfmt thay ESLint + Prettier bằng một bộ Rust nhanh, hai config nhỏ, hỗ trợ sẵn React/TS/Tailwind, và cổng pre-commit dưới một giây.

## 4. Biến môi trường type-safe

*Docs: [Vite — env & mode](https://vite.dev/guide/env-and-mode.html).*

Pulse gọi API nên base URL phải cấu hình theo môi trường — không hard-code. Vite chỉ phơi biến tiền tố `VITE_` ra client nên không vô tình lộ secret server:

```bash
# .env.local  (gitignored — real values live here)
VITE_API_URL=http://localhost:4000/api
```

```ini
# .env.example  (committed — documents the contract, no real values)
VITE_API_URL=
```

### Hai lớp an toàn

**Lớp 1 — gắn type cho env lúc compile.** Augment `ImportMetaEnv` để `import.meta.env.VITE_API_URL` là `string` có type khắp nơi, và gõ sai `VITE_API_RUL` là lỗi compile:

```ts
// src/vite-env.d.ts
/// <reference types="vite/client" />

interface ImportMetaEnv {
  readonly VITE_API_URL: string;
}
interface ImportMeta {
  readonly env: ImportMetaEnv;
}
```

**Lớp 2 — validate lúc runtime.** Type biến mất lúc runtime; giá trị `.env` thiếu vẫn là `undefined`. Validate một lần lúc boot bằng zod để app fail nhanh với message rõ thay vì lỗi `fetch` khó hiểu ở sâu ba màn hình:

```ts
// src/lib/env.ts
import { z } from 'zod';

const schema = z.object({
  VITE_API_URL: z.string().url(),
});

// throws at module load if anything is missing or malformed
export const env = schema.parse(import.meta.env);
```

### Lỗi thường gặp

- **Để secret trong biến `VITE_`** — mọi thứ tiền tố `VITE_` bị bundle vào JS client và user thấy được. Secret chỉ thuộc về server.
- **Commit `.env.local`** — gitignore nó; thay vào đó commit `.env.example` để đồng nghiệp biết cần đặt biến nào.
- **Đọc `import.meta.env` trực tiếp khắp app** — dồn qua `env.ts` để có một nguồn đã validate và một chỗ để đổi.

### Tóm tắt một dòng

Chỉ biến tiền tố `VITE_` tới client; gắn type trong `vite-env.d.ts` và validate một lần bằng zod để cấu hình sai fail nhanh.

## 5. Alias đường dẫn — thôi đếm `../`

Import tương đối kiểu `../../../lib/api` dễ vỡ — đổi chỗ file là mọi import hỏng. Ta đã khai báo `@/*` ở **cả** `tsconfig.app.json` (§2, cho editor + `tsc`) lẫn `vite.config.ts` (cho bundler).

Giờ `import { api } from '@/lib/api'` luôn trỏ từ `src/` dù file import nằm đâu — và là alias shadcn/ui mong trong `components.json` (Phần 2) và Vitest tái dùng (Phần 11).

### Tóm tắt một dòng

Định nghĩa `@/* → src/*` ở **cả** `tsconfig.app.json` và `vite.config.ts` để import sống sót khi đổi chỗ file.

## 6. Cấu trúc thư mục scale được

Cấu trúc ta phát triển qua series là **feature-first**, với primitive dùng chung ở gốc:

```text
src/
  main.tsx              # entry: providers + router
  app/
    router.tsx          # React Router route tree (Part 3)
    providers.tsx       # QueryClientProvider, Toaster (Part 4)
  components/
    ui/                 # shadcn/ui components you own (Part 2)
    layout/             # AppShell, Sidebar, Topbar
  features/
    customers/          # one folder per domain feature
      api.ts            # query/mutation functions
      hooks.ts          # useCustomers, useCreateCustomer…
      schema.ts         # zod schemas + inferred types
      keys.ts           # query-key factory (Part 4)
      components/       # feature-specific UI
  lib/
    api-client.ts       # typed fetch wrapper (Parts 4, 9)
    query-client.ts     # configured QueryClient (Part 4)
    env.ts              # validated env
    utils.ts            # cn(), formatters
  stores/               # Zustand stores (Part 7)
  test/                 # setup, MSW handlers (Part 11)
```

Ý chính là **feature-first**: mọi thứ về "customers" nằm dưới `features/customers/`, nên kỹ sư mới tìm thấy tất cả một chỗ, và xóa feature là xóa một folder. Mối quan tâm xuyên suốt (API client, `cn`, env) nằm trong `lib/`, khớp quy tắc "logic trong `lib/`" của blog này.

### Best practice: tránh file `index.ts` barrel

Hấp dẫn khi thêm `features/customers/index.ts` re-export mọi thứ. Đừng. File barrel nghĩa là import *một* helper kéo *cả* đồ thị module vào bundle, phá tree-shaking và làm phình chunk:

```ts
// ❌ barrel — importing one thing drags in the entire feature
import { useCustomers } from '@/features/customers';

// ✅ import directly from the file that defines it
import { useCustomers } from '@/features/customers/hooks';
```

Import thẳng từ file định nghĩa. Thói quen nhỏ giữ bundle gọn (ta đo ở Phần 10).

### Quy ước đặt tên

Theo coding standards của project:

- Component.
- Util / file hook.
- Biến & hàm: `camelCase`; type & interface: `PascalCase`, không tiền tố `I`.

### Tóm tắt một dòng

Nhóm theo **feature**, giữ hạ tầng chung trong `lib/` và UI chung trong `components/`, và **tránh file barrel** để bundle tree-shake được.

## 8. Bài tập

**1.** Bạn clone nhánh đồng nghiệp, `pnpm install` ok nhưng `import _ from 'lodash'` lỗi dù máy họ chạy được. Nguyên nhân?

<details>
<summary>Lời giải</summary>

Phantom dependency: `lodash` chưa thêm vào `package.json` nhưng chạy trên npm/Yarn nhờ hoist. Với `node_modules` nghiêm ngặt của pnpm, import lỗi — sửa bằng `pnpm add lodash`.
</details>

**2.** Vì sao alias `@/*` phải khai báo ở *cả* `tsconfig.app.json` và `vite.config.ts`?

<details>
<summary>Lời giải</summary>

`tsconfig` dạy language server (editor + `tsc`) resolve `@/`; `vite.config.ts` dạy bundler lúc build/dev. Thiếu một là hoặc gạch đỏ hoặc lỗi build.
</details>

**3.** Ta vừa gắn type env trong `vite-env.d.ts` *vừa* validate bằng zod. Có thừa không?

<details>
<summary>Lời giải</summary>

Không — chúng phủ hai thời điểm khác. `.d.ts` cho autocomplete/chống-gõ-sai lúc compile; type bị xóa lúc runtime, nên giá trị thiếu vẫn `undefined` ở production. `parse` của zod kiểm giá trị thật lúc boot và fail nhanh. Cần cả hai.
</details>

**4.** Vì sao tránh barrel `features/customers/index.ts` dù nó làm import ngắn hơn?

<details>
<summary>Lời giải</summary>

Barrel re-export cả feature, nên import một helper có thể kéo cả đồ thị module vào bundle và làm yếu tree-shaking. Import thẳng từ file định nghĩa giữ chunk gọn.
</details>

Nâng cao:nối hook pre-commit trọn vẹn (`pnpm exec husky init`, rồi thêm `pnpm exec lint-staged` vào `.husky/pre-commit`), cố tình commit code sai format và xác nhận `lint-staged` chặn/sửa nó.

## Điểm chính

- **pnpm** cho cài nhanh, store chung, `node_modules` nghiêm ngặt diệt phantom dep; ghim bằng `packageManager`.
- **Vite + React + TS strict** là nền SPA — tsconfig tách, `strict`, và `noUncheckedIndexedAccess` từ ngày đầu.
- **oxlint + oxfmt** thay ESLint + Prettier bằng bộ nhanh hơn nhiều, rule có sẵn, và cổng pre-commit dưới một giây.
- **Gắn type và** validate env; dùng cấu trúc **feature-first** với alias `@/` và **không file barrel**.
