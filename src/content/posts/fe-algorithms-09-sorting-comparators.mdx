Bảng dữ liệu nào cũng cần sắp xếp: theo tên, theo ngày, theo trạng thái rồi theo tên. Nghe đơn giản, nhưng `Array.sort` của JavaScript có vài cái bẫy khiến kết quả sai một cách lặng lẽ — và sort sai trong một bảng thì người dùng rất khó phát hiện cho tới khi quá muộn.

---

## 1. Bẫy kinh điển: `sort()` so sánh kiểu chuỗi

Mặc định `Array.sort` chuyển phần tử thành **chuỗi** rồi so theo thứ tự ký tự (Unicode). Với số, kết quả sai hoàn toàn:

```ts
[10, 1, 2, 20, 3].sort();
// → [1, 10, 2, 20, 3]   ❌ because "10" < "2" in string order
```

Always pass a **comparator function** that returns negative/zero/positive:

```ts
[10, 1, 2, 20, 3].sort((a, b) => a - b);
// → [1, 2, 3, 10, 20]   ✅
```

Quy ước comparator: trả **< 0** nếu `a` đứng trước `b`, **> 0** nếu `a` đứng sau, **0** nếu coi như bằng. Nhớ quy ước này thì viết comparator nào cũng đúng.

---

## 2. `sort` làm thay đổi mảng gốc — coi chừng React

`Array.sort` sắp xếp **tại chỗ** (mutate) và trả về chính mảng đó. Trong React, mutate state trực tiếp là lỗi: không trigger re-render đúng và phá quy tắc bất biến.

```ts
// ❌ mutate state → React won't see the change / dangerous shared reference
const sorted = rows.sort(byName);

// ✅ copy first (entire section works on a new array)
const sorted = [...rows].sort(byName);
// or use the newer immutable API: rows.toSorted(byName)
```

`Array.prototype.toSorted()` (ES2023) trả về mảng mới đã sort, không đụng mảng gốc — gọn cho code immutable.

## 3. Sort ổn định (stable) và vì sao nó quan trọng

Sort **ổn định** nghĩa là hai phần tử "bằng nhau" theo comparator vẫn **giữ nguyên thứ tự tương đối** ban đầu. Từ ES2019, `Array.sort` được đảm bảo ổn định trên mọi engine hiện đại.

Tính ổn định mở ra một mẹo mạnh: **sort đa khóa bằng cách sort nhiều lần từ khóa phụ đến khóa chính**. Nhưng cách *rõ ràng và hiệu quả hơn* là gộp mọi tiêu chí vào một comparator:

```ts
type Comparator<T> = (a: T, b: T) => number;

// Chain comparators: first wins; on tie, try the next
function chain<T>(...comparators: Comparator<T>[]): Comparator<T> {
  return (a, b) => {
    for (const cmp of comparators) {
      const result = cmp(a, b);
      if (result !== 0) return result; // decided → stop
    }
    return 0;
  };
}
```

```ts
interface User {
  role: 'admin' | 'member';
  name: string;
  createdAt: number;
}

const byRole: Comparator<User> = (a, b) => a.role.localeCompare(b.role);
const byName: Comparator<User> = (a, b) => a.name.localeCompare(b.name);
const byNewest: Comparator<User> = (a, b) => b.createdAt - a.createdAt;

const sorted = [...users].sort(chain(byRole, byName, byNewest));
// Sort by role, then name on tie, then newest first on another tie
```

`chain` là một comparator có thể tái dùng — đúng tinh thần "tách logic, ghép được" mà series design pattern (bên cạnh) sẽ bàn kỹ.

## 4. Sort chuỗi đúng cách: `Intl.Collator`

`localeCompare` hay so sánh `<` trên chuỗi sẽ sai với tiếng Việt, tiếng có dấu, và chữ hoa/thường. Ví dụ "z" < "Á" theo Unicode thô, nhưng người Việt mong "Á" đứng sau "a" và trước "b".

Dùng `Intl.Collator` để sort theo locale, và **chỉ tạo collator một lần** (khởi tạo khá tốn kém):

```ts
// Create ONCE, reuse — don't create inside the comparator (recreated every comparison)
const collator = new Intl.Collator('vi', {
  sensitivity: 'base', // 'a' === 'A' === 'á' at base level; tune as needed
  numeric: true, // "file2" < "file10" instead of string order
});

const sortedNames = [...names].sort((a, b) => collator.compare(a, b));
```

`numeric: true` đặc biệt hữu ích: nó làm "natural sort" để "Chương 2" đứng trước "Chương 10" — điều mà so sánh chuỗi thuần không làm được.

## 5. Tối ưu: sort theo khóa tính toán nặng (Schwartzian transform)

Nếu comparator phải tính một giá trị **đắt** cho mỗi cặp (ví dụ chuẩn hóa chuỗi, parse ngày), bạn sẽ tính lại giá trị đó `O(n log n)` lần — rất lãng phí. Mẹo **decorate–sort–undecorate** (Schwartzian transform): tính khóa **một lần cho mỗi phần tử** (`O(n)`), sort theo khóa, rồi bỏ khóa đi.

```ts
function sortByExpensiveKey<T, K>(
  items: T[],
  keyOf: (item: T) => K,
  compare: (a: K, b: K) => number,
): T[] {
  return items
    .map((item) => ({ item, key: keyOf(item) })) // compute key once per element: O(n)
    .sort((a, b) => compare(a.key, b.key)) // compare on precomputed keys
    .map((wrapped) => wrapped.item); // unwrap
}
```

```ts
// Sort by accent-stripped normalized name — normalization runs O(n) times, not O(n log n)
const sorted = sortByExpensiveKey(
  users,
  (u) => u.name.normalize('NFD').replace(/\p{Diacritic}/gu, '').toLowerCase(),
  (a, b) => a.localeCompare(b),
);
```

Với 10.000 phần tử, `n log n ≈ 130.000` lần gọi `keyOf` rút xuống còn `10.000` — nhanh hơn cả chục lần khi `keyOf` nặng.

## 6. Sort trong bảng có thể đổi cột: lưu trạng thái sort

Bảng thực tế cho người dùng click header để đổi cột/chiều sort. Mô hình hóa trạng thái sort rõ ràng giúp code gọn và dễ ghép với URL-state:

```ts
interface SortState {
  key: string;
  dir: 'asc' | 'desc';
}

function makeComparator<T extends Record<string, unknown>>(sort: SortState): Comparator<T> {
  const sign = sort.dir === 'asc' ? 1 : -1;
  return (a, b) => {
    const av = a[sort.key];
    const bv = b[sort.key];
    if (typeof av === 'number' && typeof bv === 'number') return (av - bv) * sign;
    return String(av).localeCompare(String(bv)) * sign;
  };
}
```

> Ở bảng lớn, sort lại toàn bộ mỗi lần click có thể nặng. Cân nhắc: sort trên dữ liệu đã đánh chỉ mục, hoặc đẩy sort về server khi dữ liệu quá lớn. Đo trước (Phần 1) rồi mới quyết.

## Tóm tắt

- `Array.sort` mặc định so sánh **kiểu chuỗi** — luôn truyền comparator cho số.
- `sort` **mutate** mảng gốc → trong React dùng `[...arr].sort()` hoặc `toSorted()`.
- Sort đã **ổn định** từ ES2019; gộp nhiều tiêu chí bằng comparator `chain`.
- Sort chuỗi đúng locale bằng `Intl.Collator` (tạo **một lần**, bật `numeric` cho natural sort).
- Khóa tính nặng → **Schwartzian transform** để tính khóa `O(n)` thay vì `O(n log n)`.
