## What's actually inside a glTF \{Bên trong một glTF thực ra có gì\}

glTF is the **"JPEG of 3D"** — an open Khronos format designed to be *transmitted and rendered*, not edited. \{glTF là **"JPEG của 3D"** — định dạng mở của Khronos, thiết kế để *truyền tải và render*, không phải để chỉnh sửa.\} Knowing its shape makes every loader message readable. \{Hiểu cấu trúc của nó giúp đọc được mọi thông báo của loader.\} A glTF file is a small JSON document plus binary buffers, arranged as a strict hierarchy: \{Một file glTF là một JSON nhỏ cộng các buffer nhị phân, sắp theo một phân cấp chặt chẽ:\}

```
scene → nodes (transforms) → meshes → primitives (geometry + 1 material)
                                         ↳ accessors → bufferViews → buffer
materials · textures · images · samplers · skins · animations · cameras
```

The single most important rule lives there: **a primitive has exactly one material.** \{Quy tắc quan trọng nhất nằm ở đó: **một primitive có đúng một material.**\} An object with two materials becomes two primitives — which is why your imported mesh count is often higher than your object count. \{Một object hai material sẽ thành hai primitive — nên số mesh sau khi import thường nhiều hơn số object.\}

It ships in three packagings: \{Nó đóng gói theo ba kiểu:\}

- **`.glb`** — one **binary** file: JSON + geometry + textures packed together. **Ship this.** One request, nothing to misplace. \{**`.glb`** — một file **nhị phân**: JSON + hình học + texture gói chung. **Ship cái này.** Một request, không lạc file.\}
- **`.gltf` (separate)** — JSON that references external `.bin` and image files. Great for inspecting and version control; many files to serve. \{**`.gltf` (tách rời)** — JSON tham chiếu file `.bin` và ảnh bên ngoài. Tốt để soi và quản version; nhưng nhiều file phải phục vụ.\}
- **`.gltf` (embedded)** — single JSON with base64 buffers. Avoid for production: base64 adds ~33% bloat. \{**`.gltf` (nhúng)** — một JSON với buffer base64. Tránh dùng production: base64 phình ~33%.\}

Features beyond the core arrive as **`KHR_*` / `EXT_*` extensions**: `KHR_draco_mesh_compression` and `EXT_meshopt_compression` (geometry), `KHR_texture_basisu` (KTX2 GPU textures), `KHR_materials_clearcoat` / `_transmission` / `_volume` / `_emissive_strength` (advanced PBR → `MeshPhysicalMaterial`), and `KHR_lights_punctual` (authored lights). \{Các tính năng ngoài lõi đến dưới dạng **extension `KHR_*` / `EXT_*`**.\} `GLTFLoader` handles the common ones, but the three compression extensions need a matching **decoder** wired in — miss it and the load throws. \{`GLTFLoader` xử lý các cái phổ biến, nhưng ba extension nén cần **decoder** tương ứng — thiếu là load văng lỗi.\}

## Blender pre-flight: the exact steps \{Tiền kiểm Blender: các bước chính xác\}

The export is only ever as clean as the file. \{Bản xuất chỉ sạch bằng đúng file gốc.\} Run this checklist (Blender 3.6–4.x) before every export — it kills the "rotated / huge / black / untextured" bugs at the source. \{Chạy checklist này (Blender 3.6–4.x) trước mỗi lần xuất — nó diệt tận gốc các lỗi "xoay / khổng lồ / đen / mất texture".\}

**1. Set units.** \{**1. Đặt đơn vị.**\} *Scene Properties* → *Units* → System: **Metric**, Unit Scale **1.0**, Length: **Meters**. Model so 1 Blender unit = 1 metre. \{Dựng sao cho 1 đơn vị Blender = 1 mét.\}

**2. Clean the geometry** (Object Mode, object selected): \{**2. Làm sạch hình học** (Object Mode, đã chọn object):\}

- **Apply transforms:** *Object → Apply → All Transforms* (`Ctrl+A`). After this the N-panel reads Location 0, Rotation 0, Scale 1. \{**Apply transform:** sau đó N-panel hiện Location 0, Rotation 0, Scale 1.\}
- **Set the origin:** *Object → Set Origin → Origin to Geometry* (or to the base, for floor-standing props). The origin becomes the object's pivot in Three.js. \{**Đặt origin:** origin trở thành tâm xoay của object trong Three.js.\}
- **Recalculate normals:** Edit Mode (`Tab`) → select all (`A`) → *Mesh → Normals → Recalculate Outside* (`Shift+N`). Turn on the **Face Orientation** overlay — red faces are flipped and will look black or inside-out. \{**Tính lại normal:** bật overlay **Face Orientation** — mặt đỏ là bị lật, sẽ trông đen hoặc lộn trong ra ngoài.\}
- **Merge doubles:** *Mesh → Clean Up → Merge by Distance* removes duplicate verts that break shading. \{**Gộp đỉnh trùng:** loại đỉnh trùng làm hỏng shading.\}

**3. UV unwrap** anything textured: Edit Mode → `U` → **Smart UV Project** (fast) or **Unwrap** after marking seams (`Ctrl+E → Mark Seam`). **No UVs = no texture maps.** \{**3. Unwrap UV** cho mọi thứ có texture. **Không UV = không texture map.**\}

**4. Author materials with the Principled BSDF** (the *only* shader glTF maps cleanly). \{**4. Làm material bằng Principled BSDF** (shader *duy nhất* glTF ánh xạ gọn).\} In the Shading workspace: \{Trong workspace Shading:\}

- Base Color image → **Base Color** (keep its Color Space **sRGB**). \{Ảnh Base Color → **Base Color** (giữ Color Space **sRGB**).\}
- Roughness / Metallic images → set the Image Texture's Color Space to **Non-Color**, then connect to Roughness / Metallic. \{Ảnh Roughness / Metallic → đặt Color Space **Non-Color**, rồi nối vào Roughness / Metallic.\}
- Normal map → Image Texture (**Non-Color**) → **Normal Map** node → **Normal**. \{Normal map → Image Texture (**Non-Color**) → node **Normal Map** → **Normal**.\}
- The exporter automatically **packs** your separate Roughness/Metallic into one glTF metallic-roughness texture. \{Exporter tự **gói** Roughness/Metallic riêng thành một texture metallic-roughness của glTF.\}

**5. Name your objects** in the Outliner. \{**5. Đặt tên object** trong Outliner.\} Names survive as `node.name` / `mesh.name` — that's how `getObjectByName('Door')` finds the door later. \{Tên sống sót thành `node.name` / `mesh.name` — để `getObjectByName('Door')` tìm được cánh cửa sau này.\}

## The export dialog, option by option \{Hộp thoại export, từng tùy chọn\}

*File → Export → glTF 2.0*. \{*File → Export → glTF 2.0*.\} The right sidebar is where exports go right or wrong — here is what each section that matters actually does. \{Thanh bên phải là nơi quyết định xuất đúng hay sai — đây là ý nghĩa thật của từng mục quan trọng.\}

- **Format** — pick **glTF Binary (.glb)** for production. *Separate* gives `.gltf + .bin +` images (inspectable); *Embedded* base64-inlines everything (bloated). \{**Format** — chọn **glTF Binary (.glb)** cho production.\}
- **Include → Selected Objects** — export only your selection, not the whole scene. \{**Include → Selected Objects** — chỉ xuất phần đã chọn.\}
- **Include → Custom Properties** — writes object custom props into glTF `extras`, which become `object.userData`. Use it for gameplay metadata. \{**Include → Custom Properties** — ghi custom props vào `extras`, thành `object.userData`.\}
- **Include → Cameras / Punctual Lights** — usually **off** for web; you light and frame in Three.js. \{**Include → Cameras / Punctual Lights** — thường **tắt** với web; bạn dựng đèn và khung hình trong Three.js.\}
- **Transform → +Y Up** — **ON.** Converts Blender's Z-up to glTF/Three.js Y-up. Off = your model lies on its back. \{**Transform → +Y Up** — **BẬT.** Đổi Z-up của Blender sang Y-up. Tắt = model nằm ngửa.\}
- **Data → Mesh → Apply Modifiers** — **ON.** Bakes Subsurf/Mirror/Array into the exported geometry. \{**Data → Mesh → Apply Modifiers** — **BẬT.** Nướng Subsurf/Mirror/Array vào hình học.\}
- **Data → Mesh → UVs / Normals / Tangents** — keep UVs + Normals on; turn **Tangents** on if you use normal maps (saves runtime tangent generation). \{**Data → Mesh → UVs / Normals / Tangents** — bật UVs + Normals; bật **Tangents** nếu dùng normal map.\}
- **Data → Material → Images** — *Automatic* keeps PNG/JPEG; force **JPEG** + lower *Image Quality* to shrink the file. \{**Data → Material → Images** — *Automatic* giữ PNG/JPEG; ép **JPEG** + giảm *Image Quality* để nhẹ file.\}
- **Data → Skinning / Shape Keys** — on for rigged or morph-target meshes (export the armature too). \{**Data → Skinning / Shape Keys** — bật cho mesh có xương hoặc morph target.\}
- **Animation → Animation** — **ON** to include actions. Enable **Always Sample Animations** to bake to keyframes (highest fidelity); use *Group by NLA Track* / *Export All Armature Actions* to ship multiple clips. \{**Animation → Animation** — **BẬT**. Bật **Always Sample Animations** để nướng ra keyframe; dùng *Group by NLA Track* để xuất nhiều clip.\}
- **Compression (Draco)** — **OFF for now.** Turn it on and the loader *must* have a `DRACOLoader`, or the import fails (that's Part 15). \{**Compression (Draco)** — **TẮT lúc này.** Bật thì loader *bắt buộc* có `DRACOLoader`, không thì import fail (để Part 15).\}

## A complete, runnable loader \{Một loader hoàn chỉnh, chạy được\}

The 10-line snippet works, but a *production* loader gets four things right at once: color management, image-based lighting, every optional decoder, and async safety. \{Đoạn 10 dòng thì chạy, nhưng loader *production* làm đúng bốn thứ cùng lúc: quản lý màu, ánh sáng IBL, mọi decoder tùy chọn, và an toàn bất đồng bộ.\} Here is the whole thing — copy it. \{Đây là toàn bộ — cứ copy.\}

```js
import * as THREE from 'three';
import { OrbitControls } from 'three/addons/controls/OrbitControls.js';
import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';
import { DRACOLoader } from 'three/addons/loaders/DRACOLoader.js';
import { KTX2Loader } from 'three/addons/loaders/KTX2Loader.js';
import { MeshoptDecoder } from 'three/addons/libs/meshopt_decoder.module.js';
import { RoomEnvironment } from 'three/addons/environments/RoomEnvironment.js';

// 1) Renderer — correct color + tone mapping is half of "looking right".
const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(innerWidth, innerHeight);
renderer.setPixelRatio(Math.min(devicePixelRatio, 2));
renderer.outputColorSpace = THREE.SRGBColorSpace;     // default since r152
renderer.toneMapping = THREE.ACESFilmicToneMapping;   // filmic highlights
renderer.toneMappingExposure = 1.0;
renderer.shadowMap.enabled = true;
document.body.appendChild(renderer.domElement);

// 2) Scene, camera, controls.
const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(45, innerWidth / innerHeight, 0.1, 100);
camera.position.set(3, 2, 4);
const controls = new OrbitControls(camera, renderer.domElement);
controls.enableDamping = true;

// 3) Image-based lighting — PBR metal/roughness needs something to reflect.
const pmrem = new THREE.PMREMGenerator(renderer);
scene.environment = pmrem.fromScene(new RoomEnvironment(), 0.04).texture;

// 4) A key light for crisp shadows (env light alone is too soft).
const sun = new THREE.DirectionalLight(0xffffff, 2);
sun.position.set(5, 8, 4); sun.castShadow = true;
scene.add(sun, new THREE.HemisphereLight(0xbfd4ff, 0x202428, 0.4));

// 5) GLTFLoader wired with EVERY optional decoder, so any .glb just works.
const draco = new DRACOLoader()
  .setDecoderPath('https://www.gstatic.com/draco/versioned/decoders/1.5.7/');
const ktx2 = new KTX2Loader()
  .setTranscoderPath('https://cdn.jsdelivr.net/npm/three@0.160.0/examples/jsm/libs/basis/')
  .detectSupport(renderer);
const loader = new GLTFLoader()
  .setDRACOLoader(draco)
  .setKTX2Loader(ktx2)
  .setMeshoptDecoder(MeshoptDecoder);

// 6) Load → fit → ground → shadows → play animation.
let mixer; const clock = new THREE.Clock();
loader.load('/models/helmet.glb', (gltf) => {
  const model = gltf.scene;
  model.traverse((o) => { if (o.isMesh) o.castShadow = o.receiveShadow = true; });
  fitAndGround(model, controls);
  scene.add(model);
  if (gltf.animations.length) {
    mixer = new THREE.AnimationMixer(model);
    mixer.clipAction(gltf.animations[0]).play();
  }
}, undefined, (err) => console.error('glTF failed:', err)); // ALWAYS handle errors

renderer.setAnimationLoop(() => {
  if (mixer) mixer.update(clock.getDelta());
  controls.update();
  renderer.render(scene, camera);
});
```

Two things to internalize. \{Hai điều cần khắc cốt.\} First, `load()` is **asynchronous** — everything that touches the model lives **inside the success callback**, never on the next line. \{Một, `load()` **bất đồng bộ** — mọi thứ chạm vào model nằm **trong callback thành công**, đừng để dòng kế.\} Second, wiring Draco/KTX2/Meshopt is harmless even when the file uses none of them — but it means a teammate's compressed export won't mysteriously fail on your page. \{Hai, nối Draco/KTX2/Meshopt vô hại kể cả khi file không dùng — nhưng nó giúp bản xuất nén của đồng đội không bỗng dưng fail trên trang của bạn.\}

## How glTF maps onto Three.js objects \{glTF ánh xạ sang object Three.js thế nào\}

`gltf.scene` is an ordinary `THREE.Group`, so everything you know about the scene graph applies. \{`gltf.scene` là một `THREE.Group` bình thường, nên mọi thứ bạn biết về scene graph đều áp dụng.\} This is the exact translation the importer performs: \{Đây là bản dịch chính xác mà importer thực hiện:\}

| glTF concept | Three.js result | Note |
|---|---|---|
| `scene` | `gltf.scene` (`Group`) | the root you `add()` |
| `node` | `Object3D` / `Group` / `Bone` | transform hierarchy preserved |
| `mesh` + `primitive` | **one `Mesh` per primitive** | a 2-material object → 2 child Meshes |
| `material` | `MeshStandardMaterial` (or `MeshPhysicalMaterial` if `KHR_*`) | maps wired automatically |
| `texture` / `image` | `THREE.Texture` | color space set per slot |
| `skin` | `SkinnedMesh` + `Skeleton` | bones live under nodes |
| `animation` | `AnimationClip[]` → `gltf.animations` | play with `AnimationMixer` |
| `camera` | `PerspectiveCamera` / `OrthographicCamera` → `gltf.cameras` | not auto-activated |
| node `extras` | `object.userData` | your Blender custom props land here |

So a clean way to inspect any import is a single traversal — and you must use it to **turn shadows on, because the importer never does**: \{Vậy cách gọn để soi mọi bản import là một lần traverse — và bạn phải dùng nó để **bật bóng đổ, vì importer không bao giờ tự bật**:\}

```js
let meshes = 0, tris = 0; const materials = new Set();
gltf.scene.traverse((o) => {
  if (!o.isMesh) return;
  meshes++; materials.add(o.material.uuid);
  o.castShadow = o.receiveShadow = true;       // <-- the importer won't
  const g = o.geometry;
  tris += (g.index ? g.index.count : g.attributes.position.count) / 3;
});
```

## Materials & color space: the mapping that bites \{Vật liệu & color space: ánh xạ hay cắn\}

`GLTFLoader` rebuilds each material and — crucially — sets the **right color space on every texture**. \{`GLTFLoader` dựng lại từng material và — quan trọng — đặt **đúng color space cho mọi texture**.\} This table is why hand-loading the same PNG with `TextureLoader` so often looks wrong: \{Bảng này giải thích vì sao tự nạp cùng file PNG bằng `TextureLoader` lại hay sai màu:\}

| Blender (Principled BSDF) | glTF channel | Three.js property | Color space |
|---|---|---|---|
| Base Color | `baseColorTexture` | `map` + `color` | **sRGB** |
| Metallic | metallic-roughness **B** | `metalnessMap` + `metalness` | linear |
| Roughness | metallic-roughness **G** | `roughnessMap` + `roughness` | linear |
| Ambient Occlusion | `occlusionTexture` **R** | `aoMap` | linear |
| Normal | `normalTexture` | `normalMap` | linear |
| Emission | `emissiveTexture` | `emissiveMap` + `emissive` | **sRGB** |
| Alpha / Blend mode | `alphaMode` + base color α | `transparent` / `opacity` / `alphaTest` | — |
| Clearcoat | `KHR_materials_clearcoat` | `MeshPhysicalMaterial.clearcoat` | — |
| Transmission | `KHR_materials_transmission` | `MeshPhysicalMaterial.transmission` | — |

The packing convention to remember is **ORM**: ambient **O**cclusion in red, **R**oughness in green, **M**etalness in blue, all in one image. \{Quy ước đóng gói cần nhớ là **ORM**: **O**cclusion ở đỏ, **R**oughness ở lục, **M**etalness ở lam, trong một ảnh.\} Color maps (base color, emissive) are sRGB; data maps (normal, ORM) are linear — and the loader handles all of this for you, so **don't override `texture.colorSpace` after import.** \{Map màu (base, emissive) là sRGB; map dữ liệu (normal, ORM) là linear — loader lo hết, nên **đừng ghi đè `texture.colorSpace` sau khi import.**\}

## Why it looks different from Blender \{Vì sao trông khác Blender\}

A common panic is "it's darker/flatter than my Blender viewport". \{Nỗi hoảng thường gặp: "nó tối/phẳng hơn viewport Blender".\} Same data, different *camera*: Blender uses the Filmic/AgX view transform and its own world lighting, while Three.js uses your `renderer.toneMapping`, `outputColorSpace`, and whatever `scene.environment` you set. \{Cùng dữ liệu, khác *camera*: Blender dùng view transform Filmic/AgX và world riêng, còn Three.js dùng `toneMapping`, `outputColorSpace` và `scene.environment` của bạn.\} To get close: ACESFilmic tone mapping, an HDRI environment resembling Blender's world, and a matching exposure. \{Để gần giống: tone mapping ACESFilmic, một environment HDRI giống world của Blender, và exposure khớp.\} Aim for the same **material response**, not pixel-parity. \{Hãy nhắm tới cùng **phản ứng vật liệu**, không phải khớp từng pixel.\}

## Scale, units, fit-and-ground \{Tỉ lệ, đơn vị, fit và đặt sàn\}

The Avocado in the demo is authored in centimetres — load it raw and it's a speck; another asset might fill the screen. \{Quả bơ trong demo dựng theo centimet — nạp thô thì bé tí; asset khác lại chiếm hết màn hình.\} Real-world scale is correct *content*, but for a viewer you normalize it. \{Tỉ lệ thật là *nội dung* đúng, nhưng với trình xem thì bạn chuẩn hoá lại.\} Never hand-tweak numbers — measure the bounding box and fit: \{Đừng chỉnh số bằng tay — đo bounding box rồi fit:\}

```js
function fitAndGround(model, controls) {
  const box = new THREE.Box3().setFromObject(model);
  const size = box.getSize(new THREE.Vector3());
  const maxDim = Math.max(size.x, size.y, size.z) || 1;
  model.scale.setScalar(2.6 / maxDim);               // fit to ~2.6 units
  box.setFromObject(model);                           // re-measure after scaling
  const c = box.getCenter(new THREE.Vector3());
  model.position.x -= c.x;                            // center on X…
  model.position.z -= c.z;                            // …and Z
  model.position.y -= box.min.y;                      // drop onto y = 0
  controls?.target.set(0, (size.y * 2.6 / maxDim) * 0.5, 0);
}
```

The order matters: **scale first, then re-measure, then center.** \{Thứ tự quan trọng: **scale trước, đo lại, rồi căn giữa.**\} Centering on the original box after scaling leaves the model floating off-pivot. \{Căn giữa theo box cũ sau khi scale sẽ khiến model lệch tâm và lửng lơ.\}

## Animation, a bit deeper \{Animation, sâu thêm chút\}

If the file carries animation, it arrives as `gltf.animations` (an array of `AnimationClip`). \{Nếu file có animation, nó đến dưới dạng `gltf.animations` (mảng `AnimationClip`).\} Drive it with an `AnimationMixer`, one per model: \{Điều khiển bằng `AnimationMixer`, mỗi model một cái:\}

```js
const mixer = new THREE.AnimationMixer(model);
const idle = THREE.AnimationClip.findByName(gltf.animations, 'Idle');
const action = mixer.clipAction(idle);
action.setLoop(THREE.LoopRepeat);     // or LoopOnce + action.clampWhenFinished = true
action.play();
// every frame — delta time is mandatory:
mixer.update(clock.getDelta());
```

The one rule that trips everyone: **the mixer does nothing without `mixer.update(dt)` each frame**, fed a delta from a `THREE.Clock`. \{Quy tắc khiến ai cũng vấp: **mixer không làm gì nếu thiếu `mixer.update(dt)` mỗi frame**, với delta từ `THREE.Clock`.\} Blending clips with `crossFadeTo` is the heart of Part 17. \{Trộn clip bằng `crossFadeTo` là trọng tâm của Part 17.\}

## Swap models without leaking \{Đổi model không rò rỉ\}

Loaders allocate GPU geometry **and** textures; both must be released when you replace a model. \{Loader cấp phát geometry **và** texture trên GPU; phải giải phóng cả hai khi thay model.\} Textures are the part people forget: \{Texture là phần người ta hay quên:\}

```js
scene.remove(old);
old.traverse((o) => {
  if (!o.isMesh) return;
  o.geometry.dispose();
  for (const m of [].concat(o.material)) {
    for (const k in m) if (m[k]?.isTexture) m[k].dispose(); // every map
    m.dispose();
  }
});
```

## Troubleshooting: symptom → cause → fix \{Khắc phục: triệu chứng → nguyên nhân → cách sửa\}

Ninety percent of glTF problems are on this table. \{Chín mươi phần trăm sự cố glTF nằm trong bảng này.\}

| Symptom | Likely cause | Fix |
|---|---|---|
| Nothing appears | model off-screen or mis-scaled | log `Box3` size; run fit-and-ground |
| Microscopic / gigantic | authored in mm/cm/km | normalize via bounding box |
| Lying on its back / rotated | "+Y Up" off, transforms not applied | re-export with +Y Up; `Ctrl+A` in Blender |
| Pure black surfaces | no light/environment | add `scene.environment` (PMREM) + a light |
| Pink / white "missing texture" | external images 404 (separate glTF) | ship `.glb`, or fix relative paths/CORS |
| Washed-out or too bright | tone-map / color-space mismatch | ACESFilmic + `outputColorSpace = SRGB` |
| Colors look dull / grey | color map loaded as linear | let `GLTFLoader` set color space; don't override |
| Faceted / flat shading | normals missing or not exported | export Normals; Shade Smooth in Blender |
| Animation won't move | missing `mixer.update(dt)` | update the mixer in the loop |
| `No DRACOLoader instance` error | Draco-compressed file | `setDRACOLoader(...)` (Part 15) |
| CORS error in console | cross-origin host, no CORS headers | serve same-origin or enable CORS |

## Master's warnings \{Lời cảnh báo của bậc thầy\}

- **Never assume the network.** Always wire the error callback — a silent black canvas is the worst UX, and CDNs do fail. \{**Đừng tin mạng.** Luôn nối callback lỗi — canvas đen im lặng là UX tệ nhất.\}
- **One mega-mesh ≠ fast.** A single 200k-tri mesh can't be culled or instanced per-part. Keep logical objects separate in Blender. \{**Một mega-mesh không nhanh.** Mesh 200k-tri đơn lẻ không cull/instance theo bộ phận được.\}
- **Watch the texture budget.** A 5 MB `.glb` is usually 90% textures. Resize maps to what the screen needs before blaming the mesh. \{**Để ý ngân sách texture.** `.glb` 5 MB thường 90% là texture.\}
- **Don't ship Blender lights/cameras by reflex.** You almost always relight and reframe in Three.js. \{**Đừng theo phản xạ mà xuất đèn/camera của Blender.** Bạn gần như luôn dựng lại đèn và khung hình trong Three.js.\}
- **Decoder paths must be reachable.** Draco/KTX2 transcoders load at runtime from a CDN or your `/public` — a wrong path fails only for *compressed* files, which is maddening to debug. \{**Đường dẫn decoder phải tới được.** Sai đường dẫn chỉ fail với file *nén*, rất khó lần.\}
