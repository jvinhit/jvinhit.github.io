Phần 1–10 dạy bạn *cái gì* cần xây — semantic HTML, ARIA, bàn phím, focus, form, tên, màu, component và hành vi screen reader. Phần 11 về **cách giữ nó không regress**: pipeline test nhiều lớp bắt lỗi sớm và chặn merge hỏng.

Sự thật khó chịu: **công cụ tự động chỉ bắt khoảng 30–50% lỗi accessibility** — những lỗi có quy tắc rõ, máy kiểm tra được. Chúng bỏ sót alt text có nghĩa, thứ tự đọc hợp lý, cảm giác dùng keyboard trap, và liệu thông báo lỗi có thực sự giúp người dùng. Cách sửa không phải "chọn một tool" — mà là **kim tự tháp test** với tự động hóa ở đáy và phán đoán con người ở đỉnh.

```text
                    ┌─────────────────────────┐
                    │  Manual pass (keyboard,   │  ← catches the rest
                    │  screen reader, zoom)   │
                    └───────────┬─────────────┘
                                │
                    ┌───────────▼─────────────┐
                    │  E2E + CI (Playwright +  │  ← page-level regressions
                    │  axe, Lighthouse gate)  │
                    └───────────┬─────────────┘
                                │
                    ┌───────────▼─────────────┐
                    │  Unit / component tests  │  ← widget-level rules
                    │  (vitest-axe + RTL)     │
                    └───────────┬─────────────┘
                                │
                    ┌───────────▼─────────────┐
                    │  Authoring + browser dev │  ← cheapest feedback loop
                    │  (eslint-jsx-a11y, axe) │
                    └─────────────────────────┘
```

> **Tự động hóa phần máy kiểm tra được; thủ công xác minh phần con người trải nghiệm.** Cổng CI chặn regression hiển nhiên; một vòng chỉ bàn phím trước release bắt những gì linter không bao giờ bắt được.

## 1. Thời điểm viết code — bắt lỗi trước khi ship

Lớp rẻ nhất chạy **khi bạn gõ**. Với project React/JSX, **`eslint-plugin-jsx-a11y`** ép các quy tắc phản ánh lỗi WCAG phổ biến: thiếu `alt`, ARIA sai, phần tử không tương tác nhưng clickable, role thừa, v.v..

Cài và nối vào ESLint flat config:

```bash
pnpm add -D eslint-plugin-jsx-a11y
```

```js
// eslint.config.js
import jsxA11y from 'eslint-plugin-jsx-a11y';

export default [
  {
    plugins: { 'jsx-a11y': jsxA11y },
    rules: {
      ...jsxA11y.configs.recommended.rules,
      // Tighten the rules that regress most often in real codebases
      'jsx-a11y/anchor-is-valid': 'error',
      'jsx-a11y/click-events-have-key-events': 'error',
      'jsx-a11y/no-static-element-interactions': 'error',
      'jsx-a11y/label-has-associated-control': 'error',
    },
  },
];
```

Nó bắt gì trong thực tế:

| Rule | Example violation | Vì sao quan trọng |
|------|-------------------|--------------------------------------|
| `alt-text` | `<img src="hero.jpg" />` | Ảnh không thay thế fail Perceivable |
| `anchor-is-valid` | `<a onClick={go}>Next</a>` | Link giả không phải link thao tác được bằng bàn phím |
| `click-events-have-key-events` | `<div onClick={save}>` | Chỉ chuột loại người dùng bàn phím |
| `aria-props` | `aria-labeledby` (typo) | ARIA sai bị AT bỏ qua — tệ hơn không có ARIA |

Quy tắc lint **cần nhưng chưa đủ**. Chúng không phán alt text có *nghĩa* hay thứ tự focus khớp bố cục thị giác. Coi eslint như lan can, không phải chứng nhận tuân thủ.

## 2. Công cụ trình duyệt — axe trong vòng lặp dev

Khi dựng trang, chạy **axe DevTools** (extension trình duyệt của Deque) trên mọi view mới. Nó quét DOM thật — kể cả nội dung render động — và báo vi phạm theo mức impact.

Với app React, thêm **`@axe-core/react`** ở dev để vi phạm log ra console tự động sau mỗi lần render:

```tsx
// src/main.tsx — development only
if (import.meta.env.DEV) {
  import('@axe-core/react').then((axe) => {
    axe.default(React, ReactDOM, 1000); // debounce scans by 1s
  });
}
```

```bash
pnpm add -D @axe-core/react axe-core
```

Axe kiểm tra theo quy tắc WCAG 2.x trong **axe-core** — tỷ lệ tương phản, ARIA hợp lệ, nhãn form, ID trùng, và hàng chục quy tắc khác. Lọc kết quả theo **critical / serious / moderate / minor** và sửa critical trước.

> Axe có thể pass trang dùng `<div onclick>` với `role="button"` và `tabindex="0"` nếu ARIA đúng cú pháp — nhưng Phần 2 dạy `<button>` gốc vẫn tốt hơn. Tự động hóa validate quy tắc; không validate *chất lượng thiết kế*.

## 3. Test unit/component — vitest-axe + Testing Library

Test component là điểm ngọt cho accessibility **cấp widget**: modal, combobox, tab, và field form bạn ship trong design system. Kết hợp **Testing Library** với **vitest-axe** (hoặc jest-axe) để assert **không vi phạm axe** trên output render.

```bash
pnpm add -D vitest-axe axe-core @testing-library/react @testing-library/jest-dom
```

```tsx
// src/components/ui/dialog.test.tsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { axe, toHaveNoViolations } from 'vitest-axe';
import { Dialog } from './dialog';

expect.extend(toHaveNoViolations);

describe('Dialog', () => {
  it('has no axe violations when open', async () => {
    const { container } = render(
      <Dialog open title="Delete item">
        Are you sure?
      </Dialog>,
    );
    expect(await axe(container)).toHaveNoViolations();
  });

  it('closes on Escape and returns focus to trigger', async () => {
    const user = userEvent.setup();
    const onClose = vi.fn();
    render(
      <>
        <button type="button">Open</button>
        <Dialog open title="Delete item" onClose={onClose}>
          Are you sure?
        </Dialog>
      </>,
    );

    await user.keyboard('{Escape}');
    expect(onClose).toHaveBeenCalled();
    expect(screen.getByRole('button', { name: 'Open' })).toHaveFocus();
  });
});
```

API query của Testing Library **khuyến khích markup accessible theo thiết kế**. Ưu tiên query phản ánh cách người dùng và AT tìm phần tử:

| Priority | Query | Finds by |
|----------|-------|----------|
| 1 | `getByRole('button', { name: 'Save' })` | Role + accessible name |
| 2 | `getByLabelText('Email')` | Associated `<label>` |
| 3 | `getByPlaceholderText('Search…')` | Placeholder (fallback only) |
| 4 | `getByTestId('save-btn')` | `data-testid` — last resort |

Nếu không chọn được phần tử bằng `getByRole` hay `getByLabelText`, đó thường là **dấu hiệu component chưa accessible** — sửa markup trước khi thêm test ID làm lối thoát.

Chạy axe trên **trạng thái có nghĩa**: modal đóng và mở, form trống và lỗi, list loading và loaded. Component pass axe khi đóng nhưng vi phạm khi mở sẽ lọt qua test một trạng thái.

## 4. E2E và CI — Playwright + axe, cổng Lighthouse

Test unit không bắt lỗi **xuyên trang**: skip link hỏng, mất focus sau navigation, hay layout shift che vòng focus. Test end-to-end với **`@axe-core/playwright`** quét trang đầy đủ trong engine trình duyệt thật.

```bash
pnpm add -D @axe-core/playwright @playwright/test
```

```ts
// e2e/a11y.spec.ts
import { test, expect } from '@playwright/test';
import AxeBuilder from '@axe-core/playwright';

const routes = ['/', '/posts', '/about'];

for (const path of routes) {
  test(`no critical a11y violations on ${path}`, async ({ page }) => {
    await page.goto(path);
    const results = await new AxeBuilder({ page })
      .withTags(['wcag2a', 'wcag2aa', 'wcag21aa'])
      .analyze();

    const critical = results.violations.filter(
      (v) => v.impact === 'critical' || v.impact === 'serious',
    );
    expect(critical).toEqual([]);
  });
}
```

Kết hợp **Lighthouse CI** cho category accessibility có điểm và ngưỡng tối thiểu trên mỗi PR:

```yaml
# .github/workflows/a11y.yml
name: Accessibility

on:
  pull_request:
  push:
    branches: [main]

jobs:
  a11y:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: pnpm

      - run: pnpm install --frozen-lockfile
      - run: pnpm build
      - run: pnpm exec playwright install --with-deps chromium

      - name: Run Playwright axe scans
        run: pnpm exec playwright test e2e/a11y.spec.ts

      - name: Lighthouse CI accessibility gate
        uses: treosh/lighthouse-ci-action@v12
        with:
          urls: |
            http://localhost:4321/
            http://localhost:4321/posts
          uploadArtifacts: true
          configPath: .lighthouserc.json
        env:
          LHCI_BUILD_CONTEXT__CURRENT_HASH: ${{ github.sha }}
```

```json
// .lighthouserc.json
{
  "ci": {
    "assert": {
      "assertions": {
        "categories:accessibility": ["error", { "minScore": 0.95 }]
      }
    },
    "collect": {
      "startServerCommand": "pnpm preview",
      "startServerReadyPattern": "Local",
      "numberOfRuns": 3
    }
  }
}
```

**Tích hợp vào CI để chặn regression** — axe fail hay điểm Lighthouse giảm nên chặn merge giống lỗi type. Điều chỉnh cổng dần: bắt đầu chỉ chặn vi phạm axe **critical/serious**, rồi siết khi baseline tốt hơn.

## 5. Checklist thủ công mà tự động hóa không thay thế được

Không pipeline nào thay **test trải nghiệm**. Chặn 30–60 phút trước mỗi release và đi checklist này trên luồng người dùng chính:

### Vòng chỉ bàn phím

1. Rút chuột (hoặc không chạm).
2. `Tab` / `Shift+Tab` qua toàn bộ luồng — tới mọi control được không?.
3. Focus **luôn thấy**? Không bao giờ `outline: none` mà không có thay thế.
4. Tab order khớp thứ tự đọc hợp lý?.
5. Mở, thao tác, đóng mọi dialog, menu, disclosure chỉ bằng bàn phím (Phần 4–5)?.
6. Có **skip link** hoạt động tới nội dung chính?.

### Vòng screen reader

1. Test bằng **VoiceOver**, **NVDA**, hoặc **TalkBack** — ít nhất một.
2. Điều hướng theo **heading** và **landmark** — định hướng nhanh được không?.
3. Mọi control tương tác đọc **tên, role, state rõ** (Phần 10).
4. Cập nhật động (toast, live region, đổi route SPA) được **đọc** — không chèn im lặng.
5. Lỗi form gắn field và đọc khi submit (Phần 6).

### Vòng thị giác và zoom

1. Zoom **200%** — không mất nội dung hay cuộn ngang cho body text (Phần 8).
2. Thông tin không chỉ bằng **màu** — kiểm badge trạng thái, biểu đồ, lỗi.
3. Tôn trọng **`prefers-reduced-motion`** — không có thông tin quan trọng chỉ trong animation.

### Chất lượng nội dung (phán đoán con người)

1. **Alt text** mô tả mục đích, không phải tên file (Phần 7).
2. **Text link** có nghĩa tách khỏi ngữ cảnh — `"Read the accessibility guide"` không phải `"Click here"`.
3. **Heading** tạo outline hợp lý — không nhảy cấp vì styling (Phần 2).
4. **Thông báo lỗi** nói sai gì và sửa ra sao — không chỉ `"Invalid input"` (Phần 6).

Ghi phát hiện vào issue tracker với **mức nghiêm trọng** (chặn người dùng vs. làm trải nghiệm kém) và **tiêu chí WCAG** nếu biết. Danh sách đó là input cho báo cáo audit Phần 12.

## 6. Gắn pipeline lại với nhau

Triển khai thực tế cho team mọi quy mô:

| When | Tool / activity | Owner |
|------|-----------------|-------|
| Every keystroke | `eslint-plugin-jsx-a11y` in IDE | Engineer |
| Every PR | Playwright + axe on key routes; Lighthouse `minScore` gate | CI |
| Every component PR | vitest-axe on meaningful states + RTL role queries | Engineer |
| Every feature | Manual keyboard pass on the user story | Engineer + QA |
| Every release | Screen-reader pass + 200% zoom on primary flows | QA / designated a11y champion |
| Quarterly | Full manual audit against WCAG AA checklist | Whole team |

Mục tiêu là **shift left**: thiếu `alt` lúc viết code tốn vài phút; cùng lỗi ở production tốn uy tín, rework, và có thể rủi ro pháp lý. Tự động hóa là lưới; test thủ công là bằng chứng người thật hoàn thành việc thật.

## Tóm tắt

- Công cụ a11y tự động bắt **~30–50%** lỗi — kết hợp nhiều lớp theo kim tự tháp test, không một scanner duy nhất.
- **Lúc viết code**: `eslint-plugin-jsx-a11y` chặn lỗi JSX phổ biến trước commit.
- **Dev trình duyệt**: axe DevTools + `@axe-core/react` phản hồi nhanh trên DOM thật.
- **Test component**: vitest-axe + `getByRole` / `getByLabelText` test widget và khuyến khích markup accessible.
- **CI**: Playwright + `@axe-core/playwright` và cổng Lighthouse `minScore` chặn regression khi merge.
- **Vòng thủ công** (bàn phím, screen reader, zoom, chất lượng nội dung) vẫn bắt buộc — tự động hóa không phán trải nghiệm.

**Phần tiếp theo:** Capstone — gộp mọi thứ thành audit lặp lại trên trang thật, ánh xạ phát hiện sang tuân thủ WCAG, và viết báo cáo kiểu VPAT.
