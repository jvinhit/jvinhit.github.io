Tìm kiếm và lọc là tính năng có mặt ở gần như mọi app: command palette, ô lọc bảng, autocomplete, danh bạ. Khi danh sách nhỏ, `array.filter(includes)` là đủ. Khi danh sách lên hàng chục nghìn phần tử và bạn lọc theo từng phím gõ, cách làm ngây thơ sẽ giật.

Phần này đi từ lọc tuyến tính cơ bản, tới binary search cho dữ liệu đã sort, rồi fuzzy search để "iphn" vẫn ra "iPhone".

---

## 1. Lọc tuyến tính: rẻ và đủ tốt cho `n` nhỏ

Mặc định, lọc là một vòng `O(n)`. Với vài nghìn phần tử và chuỗi ngắn, nó chạy dưới 1ms — đừng tối ưu non.

```ts
function filterByName<T extends { name: string }>(items: T[], query: string): T[] {
  const q = query.trim().toLowerCase();
  if (!q) return items;
  return items.filter((item) => item.name.toLowerCase().includes(q));
}
```

Một tối ưu nhỏ mà nhiều người bỏ qua: **chuẩn hóa trước** thay vì gọi `toLowerCase()` cho mọi phần tử ở mỗi phím gõ. Nếu danh sách cố định, hãy tính sẵn dạng thường hóa một lần:

```ts
// Index once when data arrives (not on every keystroke)
const index = items.map((item) => ({ item, haystack: item.name.toLowerCase() }));

function filter(query: string) {
  const q = query.toLowerCase();
  return index.filter((row) => row.haystack.includes(q)).map((row) => row.item);
}
```

## 2. Binary search: `O(log n)` trên dữ liệu đã sort

Khi dữ liệu **đã được sort**, ta không cần quét tuyến tính. Binary search chia đôi không gian tìm kiếm mỗi bước: 1.000.000 phần tử chỉ cần ~20 bước (`log₂ 1.000.000 ≈ 20`).

```ts
// Returns index of target, or -1 if missing. Requires ascending-sorted array.
function binarySearch(arr: number[], target: number): number {
  let lo = 0;
  let hi = arr.length - 1;
  while (lo <= hi) {
    const mid = (lo + hi) >>> 1; // halve; unsigned shift avoids overflow and rounds down
    if (arr[mid] === target) return mid;
    if (arr[mid] < target) lo = mid + 1;
    else hi = mid - 1;
  }
  return -1;
}
```

Ở frontend, biến thể hữu ích hơn `binarySearch` là **`lowerBound`** — tìm vị trí *chèn* để giữ mảng sort. Nó là nền tảng cho ảo hóa danh sách chiều cao thay đổi (Phần 4): cho biết offset cuộn, dòng nào đang ở đầu màn hình.

```ts
// First index where arr[i] >= target. Maps "scrollTop → row index".
function lowerBound(arr: number[], target: number): number {
  let lo = 0;
  let hi = arr.length; // [lo, hi)
  while (lo < hi) {
    const mid = (lo + hi) >>> 1;
    if (arr[mid] < target) lo = mid + 1;
    else hi = mid;
  }
  return lo;
}
```

Lưu ý thực tế: binary search chỉ thắng khi dữ liệu **đã sort sẵn**. Nếu bạn phải sort `O(n log n)` chỉ để tìm một lần, lọc tuyến tính `O(n)` còn rẻ hơn. Binary search đáng giá khi bạn tìm **nhiều lần** trên cùng tập đã sort.

## 3. Tìm theo tiền tố nhanh với dữ liệu đã sort

Autocomplete thường cần "mọi từ bắt đầu bằng `q`". Nếu danh sách từ đã sort theo alphabet, mọi tiền tố khớp nằm **liền kề nhau**. Dùng hai lần `lowerBound` để lấy ra dải đó trong `O(log n)`:

```ts
function prefixRange(sortedWords: string[], prefix: string): string[] {
  const start = lowerBoundStr(sortedWords, prefix);
  // Every string in [prefix, prefix + highest_char) starts with prefix
  const end = lowerBoundStr(sortedWords, prefix + '\uffff');
  return sortedWords.slice(start, end);
}

function lowerBoundStr(arr: string[], target: string): number {
  let lo = 0;
  let hi = arr.length;
  while (lo < hi) {
    const mid = (lo + hi) >>> 1;
    if (arr[mid] < target) lo = mid + 1;
    else hi = mid;
  }
  return lo;
}
```

Với từ điển 100.000 từ, lấy gợi ý cho "ja" chỉ tốn vài chục phép so sánh thay vì quét cả 100.000.

## 4. Fuzzy search: gõ sai vẫn ra kết quả

Người dùng gõ nhanh và sai. Họ gõ "gthb" và mong ra "GitHub", gõ "usrpro" và mong ra "User Profile". Đó là **fuzzy matching** — cốt lõi của mọi command palette (VS Code, Linear, Raycast).

Thuật toán nền tảng là **subsequence matching**: chuỗi query khớp nếu các ký tự của nó xuất hiện trong target *theo đúng thứ tự* (không cần liền nhau).

```ts
// "gthb" is a subsequence of "github" → match
function isSubsequence(query: string, target: string): boolean {
  let qi = 0;
  for (let ti = 0; ti < target.length && qi < query.length; ti++) {
    if (query[qi] === target[ti]) qi++;
  }
  return qi === query.length; // matched all query characters
}
```

Nhưng "khớp/không khớp" thôi thì chưa đủ — ta cần **xếp hạng**. "gh" nên ưu tiên "GitHub" hơn "Graph". Một hàm chấm điểm thực dụng thưởng cho: khớp liền nhau, khớp ở đầu từ (sau khoảng trắng / dấu gạch / camelCase), và khớp ngay đầu chuỗi.

```ts
interface FuzzyResult<T> {
  item: T;
  score: number;
  matches: number[]; // matched char indices, for highlight (Part 10)
}

function fuzzyScore(query: string, target: string): { score: number; matches: number[] } | null {
  const q = query.toLowerCase();
  const t = target.toLowerCase();
  const matches: number[] = [];
  let qi = 0;
  let score = 0;
  let prevMatch = -2;

  for (let ti = 0; ti < t.length && qi < q.length; ti++) {
    if (t[ti] !== q[qi]) continue;

    let bonus = 1;
    if (ti === prevMatch + 1) bonus += 5; // consecutive with previous match
    if (ti === 0) bonus += 8; // match at very start
    const before = t[ti - 1];
    if (before === ' ' || before === '-' || before === '_' || before === '/') bonus += 6; // word start
    if (target[ti] >= 'A' && target[ti] <= 'Z') bonus += 4; // camelCase boundary

    score += bonus;
    matches.push(ti);
    prevMatch = ti;
    qi++;
  }

  if (qi < q.length) return null; // not a subsequence → reject
  score -= t.length * 0.1; // lightly penalize long strings so shorter ones rank higher
  return { score, matches };
}
```

Ghép lại thành một hàm tìm kiếm hoàn chỉnh, trả về kết quả đã xếp hạng:

```ts
function fuzzySearch<T>(items: T[], query: string, key: (item: T) => string): FuzzyResult<T>[] {
  if (!query) return items.map((item) => ({ item, score: 0, matches: [] }));
  const results: FuzzyResult<T>[] = [];
  for (const item of items) {
    const scored = fuzzyScore(query, key(item));
    if (scored) results.push({ item, score: scored.score, matches: scored.matches });
  }
  return results.sort((a, b) => b.score - a.score); // higher score first
}
```

```ts
const commands = [
  { id: 'open-file', label: 'Open File' },
  { id: 'go-to-line', label: 'Go to Line' },
  { id: 'git-commit', label: 'Git: Commit' },
];

fuzzySearch(commands, 'gc', (c) => c.label);
// → "Git: Commit" ranks first thanks to word-start bonus on "G" and "C"
```

> Trong dự án thật, thư viện như `fuse.js` hay `fzf`-style sẽ tinh vi hơn (xử lý Unicode, từ điển lỗi chính tả). Nhưng hiểu phiên bản này giúp bạn biết *vì sao* một kết quả lại xếp trên kết quả khác — và tự chỉnh trọng số bonus theo nhu cầu.

## 5. Ghép tất cả lại: pipeline tìm kiếm mượt

Một ô search "đúng chuẩn" kết hợp nhiều mảnh từ series này:

1. **Debounce** input (Phần 2) để không tính lại trên mỗi phím gõ.
2. **Normalize & index một lần** khi dữ liệu về, không phải mỗi lần gõ phím.
3. **Fuzzy score + sort** để xếp hạng.
4. Nếu danh sách rất lớn, **giới hạn kết quả render** (vd top 50) và virtualize phần còn lại (Phần 4).

```ts
const index = items.map((item) => ({ item, label: item.name }));

const onType = debounce((query: string) => {
  const top = fuzzySearch(index, query, (row) => row.label).slice(0, 50);
  render(top); // only paint the first 50 rows — enough for the user to see
}, 150);
```

Quan trọng: bottleneck thường **không** phải bước chấm điểm (nhanh) mà là **render hàng nghìn DOM node**. Vì vậy giới hạn số kết quả render là tối ưu hiệu quả nhất ở đây — dẫn thẳng tới Phần 4.

## Tóm tắt

- Lọc tuyến tính `O(n)` là đủ cho `n` nhỏ — đừng tối ưu non. Nếu cần, **chuẩn hóa & đánh chỉ mục một lần** thay vì mỗi phím.
- **Binary search** (`O(log n)`) thắng khi dữ liệu *đã sort* và bạn tìm nhiều lần; `lowerBound` còn dùng để map "scroll → dòng" cho ảo hóa.
- **Fuzzy search** dựa trên subsequence matching + hàm chấm điểm để gõ sai/tắt vẫn ra kết quả đúng và xếp hạng hợp lý.
- Bottleneck thật thường ở **render**, không ở tính toán — giới hạn số kết quả hiển thị.

**Phần tiếp theo:** Ảo hóa danh sách — render 100.000 dòng mà DOM chỉ giữ vài chục node.
