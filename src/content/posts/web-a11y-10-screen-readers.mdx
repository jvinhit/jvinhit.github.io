Scanner tự động bắt lỗi tương phản và thiếu `alt` — nhưng **không** nói được người dùng screen reader có hoàn tất checkout, hiểu toast, hay phục hồi sau submit form fail. Nghiên cứu ngành liên tục thấy công cụ tự động phát hiện khoảng **30–50%** lỗi a11y — nghĩa là **50–70% cần test thủ công** bằng bàn phím và AT thật.

Phần 10 lấp khoảng trống: screen reader hoạt động ra sao, test cái nào, và quy trình lặp lại trên mọi feature.

---

## 1. Các screen reader chính và cặp trình duyệt

Screen reader nằm giữa **cây accessibility** (Phần 1) và người dùng — truy vấn accessibility API của OS và chuyển node thành giọng nói hoặc braille.

| Screen reader | Platform | Cost | Typical browser pairing |
|---------------|----------|------|-------------------------|
| **VoiceOver** | macOS, iOS, iPadOS | Free (built-in) | **Safari** (best on Apple); Chrome supported on macOS |
| **NVDA** | Windows | Free (open source) | **Firefox** (traditional best pair); **Chrome** widely used |
| **JAWS** | Windows | Commercial | **Chrome**, Edge |
| **TalkBack** | Android | Free (built-in) | **Chrome** |
| **Orca** | Linux (GNOME) | Free (open source) | **Firefox** |

> **Ma trận test tối thiểu cho web app:** **VoiceOver + Safari** (macOS/iOS) và **NVDA + Firefox hoặc Chrome** (Windows) phủ đa số người dùng screen reader desktop và mobile.

Bạn không cần mua JAWS cho công việc hàng ngày — NVDA là substitute Windows miễn phí xuất sắc. Test trên **mobile thật** (VoiceOver + Safari iPhone, TalkBack + Chrome Android) vì gesture chạm khác hoàn toàn desktop.

## 2. Con trỏ ảo vs chế độ focus

Screen reader vận hành hai chế độ khác nhau trên web:

### Chế độ duyệt / con trỏ ảo

Ở **browse mode** (NVDA/JAWS: virtual cursor; VoiceOver: quick nav), screen reader inject **con trỏ ảo** di chuyển qua trang **độc lập với focus bàn phím**. Người dùng đọc tuần tự hoặc nhảy theo heading, landmark, link, bảng.

- **Phím mũi tên** di chuyển con trỏ ảo từng dòng hoặc phần tử.
- **`Tab`** di chuyển **focus thật** tới phần tử tương tác — chuyển về **focus/forms mode** trong widget.

### Chế độ focus / form / tương tác

Trong `<form>`, `<dialog>`, hoặc widget phức tạp (tabs, combobox), screen reader vào **forms mode** (NVDA) hoặc **interaction mode** (VoiceOver). Phím gõ **thẳng vào control** — gõ điền input, mũi tên di chuyển trong listbox.

```text
Browse mode:     Arrow ↓  →  reads next line of static text
                 H        →  jumps to next heading

Forms mode:      Arrow ↓  →  moves within <select> or listbox
                 a        →  types into <input>
```

Hiểu sai sự tách này là lý do dev nghĩ "mũi tên không chạy trên widget tùy chỉnh" — người dùng có thể vẫn ở browse mode và bạn chưa đưa focus vào widget.

## 3. Cách người dùng điều hướng — lệnh thiết yếu

Lệnh khác theo screen reader, nhưng **chiến lược điều hướng** phổ quát:

| Strategy | NVDA (Windows) | VoiceOver (macOS) |
|----------|----------------|-------------------|
| **Next heading** | `H` / `Shift+H` | `VO` + `Cmd` + `H` (or rotor) |
| **Landmarks / regions** | `D` / `Shift+D` | Rotor → Landmarks |
| **Links** | `K` / `Shift+K` | Rotor → Links |
| **Form fields** | `F` / `Shift+F` | `VO` + `Cmd` + `J` (next form control) |
| **Buttons** | `B` / `Shift+B` | Rotor → Form Controls |
| **Lists / tables** | `L`, `T` | Rotor → Headings, Tables |
| **Read from top** | `Ctrl+Home` then arrows | `VO+A` |

**VO** = modifier VoiceOver (**Caps Lock** hoặc **Ctrl+Option** trên Mac).

### Rotor VoiceOver (iOS/macOS)

Trên iOS và macOS, **rotor** (xoay hai ngón trên iPhone, `VO+U` trên Mac) cho chọn loại điều hướng — heading, link, form control, landmark — và vuốt lên/xuống di chuyển. Nếu heading và landmark hỏng, người dùng rotor không thể lướt app.

## 4. Cái gì được đọc — role, name, state, value

Mỗi node accessibility phơi tối đa bốn mảnh thông tin (Phần 1):

```text
<button aria-expanded="false" aria-controls="panel-1">
  Advanced options
</button>

Announced: "Advanced options, button, collapsed"
           ───────────────  ──────  ──────────
                 name         role     state
```

| Piece | Source | Example announcement |
|-------|--------|---------------------|
| **Role** | Implicit HTML or `role` | "button", "link", "checkbox", "heading level 2" |
| **Name** | Visible text, `aria-label`, `aria-labelledby`, `<label>` | "Delete account" |
| **State** | `aria-*` states, native properties | "checked", "expanded", "selected", "disabled" |
| **Value** | `value`, `aria-valuenow`, input content | "50%", "3 of 10", "user@example.com" |

Khi bất kỳ mảnh nào sai hoặc thiếu, người dùng nghe im lặng, "clickable" chung chung, hoặc nhãn sai lệch — **button chỉ icon không `aria-label`** là fail production phổ biến nhất.

Cập nhật động (toast, số giỏ hàng, lỗi validation) cần **live region** (Phần 3) — không có thì screen reader không đọc thay đổi.

## 5. Cách bắt đầu — bật screen reader hôm nay

Bạn không cần chứng chỉ để bắt đầu — cần **30 phút và kiên nhẫn**.

### macOS — VoiceOver

1. **`Cmd + F5`** bật/tắt VoiceOver (hoặc triple-click nút cạnh trên iPhone).
2. Mở **Safari** tới trang cần test.
3. **`Ctrl+Option + Mũi tên phải`** tới phần tử tiếp; **`Ctrl+Option + Space`** kích hoạt link và button.
4. **`Ctrl+Option + U`** mở rotor.
5. **`Ctrl+Option + H`** nhảy tới heading tiếp.

### Windows — NVDA

1. Tải [NVDA](https://www.nvaccess.org/download/) (miễn phí) và cài.
2. **`Ctrl+Alt+N`** khởi động NVDA; **`NVDA+Q`** thoát.
3. Mở **Firefox** hoặc **Chrome**.
4. **`H`** heading tiếp, **`D`** landmark tiếp, **`B`** button tiếp, **`F`** form field tiếp.
5. **`Tab`** / **`Shift+Tab`** qua control focusable — nghe từng thông báo.

> **Mẹo buổi đầu:** giảm tốc độ NVDA xuống 40–50% trong settings cho đến khi tai quen — bạn đang học ngôn ngữ mới.

## 6. Quy trình test AT thực tế

Chạy checklist này trên mọi feature mới hoặc thay đổi UI đáng kể:

### Bước 1 — lướt cấu trúc

- Điều hướng theo **heading** — dàn ý có kể câu chuyện mạch lạc?
- Nhảy theo **landmark** — tới được `main`, `nav`, và region có nhãn?
- Có **`<h1>`** (hoặc title trang hợp lý)?

### Bước 2 — bàn phím + focus

- Rút chuột; hoàn thành task chính chỉ bằng **Tab, Enter, Space, mũi tên**.
- Thứ tự focus khớp thứ tự thị giác; focus không bao giờ biến mất.

### Bước 3 — tên và state

- Tab qua mọi phần tử tương tác — **tên** có nghĩa ngoài ngữ cảnh? ("Delete", không phải "Click here").
- Bật/tắt checkbox, mở disclosure, đổi tab — **state** có được đọc?.

### Bước 4 — nội dung động

- Kích hoạt **toast**, lỗi form, hoặc hoàn tất loading — AT có đọc mà không di chuyển focus?
- Submit form invalid — **lỗi đầu** có được đọc và liên kết với field?.

### Bước 5 — pattern widget

- Mở **dialog** — focus bị trap bên trong? Escape đóng? Focus restore?.
- Thao tác **tabs** và **combobox** bằng mũi tên ở forms mode.

Ghi finding cùng ticket với bug thị giác — mức độ, bước, mong đợi vs thông báo nghe được.

## 7. Bug chỉ test AT mới lộ

Những cái này thường pass Lighthouse và axe nhưng fail người dùng thật:

| Bug | What the user hears / experiences |
|-----|-----------------------------------|
| **Icon button without accessible name** | "button" — no idea what it does |
| **Wrong role** (`div` with click handler) | "Clickable text" instead of "button" |
| **`aria-hidden="true"` on focused element's ancestor** | Focused control goes silent |
| **Missing live region on async success** | Action completes; user hears nothing |
| **Focus lost after modal close** | Thrown to top of page; must re-navigate |
| **Duplicate `id` values** | `aria-labelledby` resolves to wrong label |
| **Decorative icon not hidden** | "Image, star graphic" before every rating |
| **`placeholder` as only label** | Field announced as blank or unnamed |

```html
<!-- ❌ Passes color contrast; fails AT -->
<button><svg aria-hidden="false">...</svg></button>

<!-- ✅ -->
<button aria-label="Add to favorites">
  <svg aria-hidden="true">...</svg>
</button>
```

## 8. Tự động vs thủ công — biết giới hạn

| Method | Catches well | Misses |
|--------|--------------|--------|
| **axe / Lighthouse** | Missing `alt`, low contrast, duplicate IDs, some ARIA syntax | Focus order, meaningful names, keyboard traps, live region timing |
| **Keyboard-only test** | Focus visibility, tab order, activation keys | Announcement quality, browse vs forms mode |
| **Screen reader test** | Names, states, roles, dynamic announcements | Color-only cues (pair with visual review) |
| **Manual expert audit** | Everything — slow, expensive | — |

> **Quy tắc ngón tay cái:** tự động trong CI cho regression (Phần 11), test bàn phím mỗi PR, spot check screen reader mỗi feature, pass AT đầy đủ trước release lớn.

## Tóm tắt

- Test tối thiểu **VoiceOver + Safari** (Apple) và **NVDA + Firefox/Chrome** (Windows); thêm VoiceOver mobile và TalkBack cho app responsive.
- Screen reader dùng **browse/con trỏ ảo** để đọc và **focus/forms mode** trong widget — hành vi bàn phím phụ thuộc chế độ đang active.
- Người dùng điều hướng theo **heading, landmark, link và form field** — cấu trúc hỏng phá workflow thật.
- AT đọc **role + name + state + value** — verify mọi control tương tác và cập nhật động.
- Công cụ tự động bắt **~30–50%** lỗi; **test bàn phím + screen reader** là bắt buộc cho phần còn lại.

**Phần tiếp theo:** Test tự động và thủ công — axe trong CI, script test thủ công, và xây pipeline regression a11y.
