Phần 9 dựng các component accessible cơ bản (tabs, accordion, dialog). Phần này lên cấp với ba **composite widget** khó nhất trong **WAI-ARIA Authoring Practices Guide (APG)**: combobox/autocomplete, menu/menubar, và treegrid. Đây là nơi ARIA dễ sai nhất — nhưng cũng là nơi hiểu sâu hai mô hình focus tạo nên khác biệt.

> Composite widget = một control chứa nhiều control con, nhưng với bàn phím nó hành xử như **một** điểm dừng Tab. Bên trong, bạn điều hướng bằng phím mũi tên.

---

## 1. Hai mô hình quản lý focus

Mọi composite widget chọn một trong hai cách cho screen reader biết "con nào đang active":

```text
① Roving tabindex
   - DOM focus THẬT di chuyển giữa các con
   - con active: tabindex="0"; còn lại: tabindex="-1"
   - phím mũi tên đổi tabindex + .focus()
   - dùng khi: con là phần tử focus được (button, option thật)

② aria-activedescendant
   - DOM focus Ở YÊN trên container
   - container có aria-activedescendant="id-con-active"
   - phím mũi tên đổi giá trị thuộc tính (không .focus() con)
   - dùng khi: input giữ focus (combobox) hoặc danh sách rất lớn
```

Quy tắc chọn: nếu phần tử nhập liệu (input) phải giữ focus để gõ → `aria-activedescendant`. Nếu không → roving tabindex thường đơn giản hơn.

## 2. Combobox / Autocomplete — pattern khó nhất

Combobox = một `input` (hoặc nút) gắn với một popup `listbox`. Đây là widget hay bị làm sai nhất. Cấu trúc ARIA tối thiểu:

```html
<label for="fruit">Trái cây</label>
<input
  id="fruit"
  role="combobox"
  aria-expanded="false"
  aria-controls="fruit-list"
  aria-autocomplete="list"
  autocomplete="off"
>
<ul id="fruit-list" role="listbox" hidden>
  <li id="opt-1" role="option">Táo</li>
  <li id="opt-2" role="option" aria-selected="true">Chuối</li>
</ul>
```

Bàn phím bắt buộc (input giữ focus → dùng `aria-activedescendant`):

| Phím | Hành vi |
|---|---|
| `↓` | Mở popup nếu đóng; di chuyển option active xuống |
| `↑` | Di chuyển option active lên |
| `Enter` | Chọn option active, đóng popup |
| `Esc` | Đóng popup (lần 2: xóa input) |
| `Tab` | Chọn option active (nếu có) rồi rời |
| gõ chữ | Lọc danh sách, cập nhật `aria-activedescendant` |

```js
// Cập nhật con active KHÔNG dời DOM focus khỏi input
function setActive(input, optionEl) {
  input.setAttribute('aria-activedescendant', optionEl.id);
  for (const o of list.children) o.setAttribute('aria-selected', String(o === optionEl));
  optionEl.scrollIntoView({ block: 'nearest' });
}
```

> Mở popup phải set `aria-expanded="true"`; số kết quả nên thông báo qua live region (Part 16): "8 kết quả". Đừng dùng `aria-activedescendant` trỏ tới option đã bị lọc ẩn.

## 3. Menu & Menubar — không phải navigation

Cảnh báo quan trọng: `role="menu"` dành cho **menu lệnh kiểu ứng dụng** (như menu File/Edit của app desktop), **không** phải menu điều hướng website. Điều hướng site dùng `<nav>` + danh sách link thường. Dùng sai `role="menu"` cho nav làm screen reader kỳ vọng phím mũi tên và "menu item", gây rối.

```html
<!-- ✅ Menu lệnh ứng dụng (đúng ngữ cảnh dùng role=menu) -->
<button id="actions" aria-haspopup="true" aria-expanded="false" aria-controls="m1">Hành động</button>
<ul id="m1" role="menu" aria-labelledby="actions" hidden>
  <li role="menuitem" tabindex="-1">Sao chép</li>
  <li role="menuitem" tabindex="-1">Đổi tên</li>
  <li role="separator"></li>
  <li role="menuitem" tabindex="-1">Xóa</li>
</ul>
```

Bàn phím (roving tabindex — focus thật di chuyển):

```text
↓/↑     di chuyển giữa menuitem (vòng lại đầu/cuối)
Enter/Space  kích hoạt item, đóng menu, trả focus về nút
Esc     đóng menu, trả focus về nút mở
Home/End nhảy item đầu/cuối
gõ chữ  nhảy tới item bắt đầu bằng chữ đó (typeahead)
```

Menubar (thanh ngang nhiều menu) thêm `←/→` để di chuyển giữa các menu top-level. Mẫu chuẩn nằm trong APG; đừng tự sáng tạo lệch chuẩn.

## 4. Treegrid — bảng có thể điều hướng như cây

Treegrid là widget cao cấp: lưới 2 chiều (như bảng) nhưng các hàng có thể mở/đóng phân cấp (như cây). Dùng cho file explorer, comment lồng nhau có cột.

```html
<table role="treegrid" aria-label="Tệp">
  <tbody>
    <tr role="row" aria-level="1" aria-expanded="true" aria-posinset="1" aria-setsize="2">
      <td role="gridcell">src</td><td role="gridcell">—</td>
    </tr>
    <tr role="row" aria-level="2" aria-posinset="1" aria-setsize="3">
      <td role="gridcell">index.ts</td><td role="gridcell">2 KB</td>
    </tr>
  </tbody>
</table>
```

Bàn phím kết hợp tree + grid:

```text
↑/↓     di chuyển giữa hàng
←       đóng hàng đang mở; nếu đã đóng → lên hàng cha (aria-expanded=false)
→       mở hàng đóng; nếu đã mở → vào cell/hàng con
Enter   kích hoạt hàng
aria-level / aria-expanded / aria-posinset / aria-setsize  cho screen reader biết vị trí trong cây
```

`aria-level`, `aria-posinset`, `aria-setsize` cho phép screen reader đọc "mức 2, mục 1 trên 3" — bối cảnh thiết yếu khi không nhìn thấy thụt lề.

## 5. Nguyên tắc chung khi dựng composite widget

```text
1. Bắt đầu từ mẫu APG chính thức — đừng đoán role/phím.
2. Chọn đúng mô hình focus (roving vs activedescendant).
3. Một điểm dừng Tab cho cả widget; mũi tên điều hướng bên trong.
4. Trả focus về điểm gọi khi đóng popup (menu/dialog).
5. Test bằng bàn phím TRƯỚC, rồi screen reader (VoiceOver/NVDA).
6. Cân nhắc dùng thư viện headless đã kiểm thử a11y (Part 22) thay vì tự viết.
```

> Lời khuyên thực dụng: combobox và menubar cực khó làm đúng mọi edge case. Với production, ưu tiên primitive đã được kiểm thử (Radix, React Aria, Headless UI). Tự viết chỉ khi bạn thật sự cần và sẽ test kỹ với AT.

---

## Tóm tắt

- Composite widget hành xử như **một điểm dừng Tab**; điều hướng bên trong bằng phím mũi tên, theo một trong hai mô hình focus: **roving tabindex** hoặc **`aria-activedescendant`**.
- **Combobox**: input giữ focus + `aria-activedescendant`; cần `aria-expanded`/`aria-controls`/`aria-autocomplete`, bàn phím ↓↑/Enter/Esc/Tab, và thông báo số kết quả.
- **Menu/menubar** (`role="menu"`) chỉ dành cho **menu lệnh kiểu app**, KHÔNG cho điều hướng site; dùng roving tabindex, Esc trả focus về nút mở.
- **Treegrid** kết hợp grid 2 chiều với cây: `←/→` đóng/mở và lên cha/vào con; `aria-level`/`posinset`/`setsize` cấp bối cảnh.
- Luôn theo mẫu **APG** chính thức và ưu tiên thư viện headless đã kiểm thử a11y cho production.

**Phần tiếp theo:** Accessible data tables & grids — header phức tạp (scope, headers/id), bảng sortable, grid chỉnh sửa được, và làm a11y khi virtualize hàng nghìn dòng.
