Phần 2 và 3 cho semantic HTML và ARIA cho cây accessibility. Phần 4 về **khả năng thao tác**: người không bao giờ chạm chuột có thực sự tới và kích hoạt mọi control không?

WCAG **2.1.1 Keyboard** (Level A) yêu cầu mọi chức năng dùng được từ bàn phím. Đó không phải polish tùy chọn — là yêu cầu pháp lý và đạo đức tối thiểu.

> **Rút chuột ra.** Nếu không hoàn thành luồng người dùng chính chỉ bằng bàn phím, bạn đã fail conformance trước khi mở screen reader.

---

## 1. Ai phụ thuộc bàn phím

Accessibility bàn phím không phải edge case nhỏ:

| User group | Vì sao bàn phím quan trọng |
|------------|-----------------------------------------------------|
| **Motor disabilities** | Run tay, khuyết chi, RSI — độ chính xác chuột đau hoặc không thể |
| **Blind / low-vision + screen reader** | Input chính là bàn phím; AT điều khiển focus theo chương trình |
| **Power users** | Workflow nhanh hơn, điền form, công cụ dev |
| **Situational** | Trackpad hỏng, bàn đứng, tay bận |

Mỗi `<div onclick>` bạn ship loại trừ tất cả nhóm này cùng lúc. `<button>` và `<a href>` gốc bao gồm họ mặc định.

---

## 2. Gì focusable mặc định

**Focus** là con trỏ của trình duyệt tới "phần tử nhận input bàn phím ngay bây giờ". Chỉ phần tử focusable vào **tab order** — chuỗi `Tab` và `Shift+Tab` đi qua.

### Focusable tự nhiên

- link có URL thật (không phải `<a>` không `href`)
- `<button>` (all types)
- `<input>`, `<select>`, `<textarea>` (unless `disabled`)
- `<summary>` (inside `<details>`)
- `<iframe>` (with `tabindex` not set to `-1`)
- Any element with **`tabindex="0"`** or a **positive `tabindex`**

### Không focusable mặc định

- `<div>`, `<span>`, `<p>`, `<section>`, `<article>` — unless you add `tabindex`
- `<a>` without `href` — behaves like plain text
- Disabled form controls
- Elements with `display: none` or `visibility: hidden`

```html
<!-- ✅ In tab order -->
<a href="/docs">Docs</a>
<button type="button">Save</button>
<input type="text" name="search" />

<!-- ❌ Not in tab order — keyboard users cannot reach these -->
<div onclick="save()">Save</div>
<a onclick="save()">Save</a>
<span tabindex="0" role="button" onclick="save()">Save</span>
<!-- last one is focusable but still missing Enter/Space unless you add them -->
```

## 3. `tabindex` — ba giá trị quan trọng

Thuộc tính `tabindex` điều khiển phần tử có và tham gia điều hướng focus ra sao:

| Value | Tab order? | Programmatic focus? | When to use |
|-------|------------|---------------------|-------------|
| **(absent)** | Native default | Yes (if natively focusable) | Luôn ưu tiên |
| **`0`** | Yes — in DOM order among other `0` and native elements | Yes | Widget tùy chỉnh cần là tab stop |
| **`-1`** | No — skipped by Tab | Yes — via `.focus()` | Mục tiêu roving tabindex, focus ban đầu modal |
| **Positive (`1`, `2`, …)** | Yes — **before** all `0`/native, in numeric order | Yes | **Anti-pattern — tránh** |

### Vì sao `tabindex` dương cấm

```html
<!-- ❌ Tab order: Submit (1) → Cancel (2) → Name field (0) — illogical -->
<input tabindex="0" name="name" />
<button tabindex="2" type="button">Cancel</button>
<button tabindex="1" type="submit">Submit</button>
```

Giá trị dương ghi đè thứ tự DOM, tạo ác mộng bảo trì khi thêm/sắp xếp lại phần tử, và khác nhau giữa các trang — **không bao giờ dùng**. Nếu tab order sai, sửa **thứ tự DOM** hoặc cấu trúc lại layout — đừng vá bằng số.

### Focus không qua Tab

Dùng `-1` khi phần tử nên nhận focus theo chương trình nhưng không phải tab stop thường:

```typescript
// Open modal → move focus inside
function openModal(dialog: HTMLDialogElement): void {
  dialog.showModal();
  const firstFocusable = dialog.querySelector<HTMLElement>(
    'button, [href], input, select, textarea, [tabindex]:not([tabindex="-1"])'
  );
  firstFocusable?.focus();
}
```

Phần 5 đi pattern focus trap đầy đủ cho SPA và modal.

## 4. Tab order theo DOM — CSS có thể phá

Chuỗi tab mặc định theo **thứ tự DOM**, không phải thứ tự thị giác. Điều này cắn team reorder thị giác bằng Flexbox hoặc Grid:

```html
<!-- DOM order: Sidebar → Main. Visual order (flex order): Main → Sidebar -->
<div class="layout">
  <aside style="order: 2">Sidebar nav</aside>
  <main style="order: 1">Main content</main>
</div>
```

Người dùng bàn phím Tab qua sidebar **trước** trong khi người nhìn thấy main content bên trái — lệch pha gây rối, fail WCAG.

**Sửa:** khớp thứ tự DOM với thứ tự thị giác, hoặc dùng `tabindex`/`inert` cẩn thận kèm test bàn phím — nhưng ưu tiên cấu trúc lại DOM.

> **Quy tắc test:** Tab qua trang nhắm mắt (hoặc nhìn chỗ khác). Thứ tự focus kể câu chuyện mạch lạc không?.

## 5. Focus hiển thị — không bao giờ làm vòng biến mất

Chỉ báo focus trả lời: **"Tôi đang ở đâu?"** Xóa chúng là một trong những regression a11y phổ biến và có hại nhất.

```css
/* ❌ Never ship this globally */
*:focus {
  outline: none;
}
```

WCAG **2.4.7 Focus Visible** (Level AA) yêu cầu chỉ báo focus hiển thị. Nếu bỏ mặc định trình duyệt, bạn **phải** thay thế.

### Dùng `:focus-visible`

`:focus-visible` hiện vòng cho người dùng bàn phím nhưng ẩn khi click chuột — tốt nhất cả hai:

```css
/* Design token — adjust to your theme */
:root {
  --focus-ring-color: #c8ff00;
  --focus-ring-width: 2px;
  --focus-ring-offset: 2px;
}

:focus {
  outline: none; /* only safe because :focus-visible replaces it */
}

:focus-visible {
  outline: var(--focus-ring-width) solid var(--focus-ring-color);
  outline-offset: var(--focus-ring-offset);
}

/* High-contrast fallback for Windows High Contrast Mode */
@media (forced-colors: active) {
  :focus-visible {
    outline: 2px solid CanvasText;
  }
}
```

Yêu cầu vòng focus tốt:

- **Tương phản đủ** với màu lân cận (tối thiểu 3:1 cho chỉ báo).
- **Hiển thị trên mọi trạng thái tương tác** — kể cả component tùy chỉnh.
- **Không bị cắt** bởi tổ tiên `overflow: hidden` — thêm padding hoặc dùng `outline-offset`.

## 6. Skip link — nhảy qua chrome lặp

Mỗi trang có nav header buộc người dùng bàn phím Tab qua mọi link trước khi tới nội dung chính. **Skip link** là phần tử focusable đầu tiên — ẩn đến khi focus — nhảy thẳng tới `<main>`.

```html
<body>
  <a href="#main-content" class="skip-link">Skip to main content</a>

  <header><!-- long nav with 12 links --></header>

  <main id="main-content" tabindex="-1">
    <!-- primary content -->
  </main>
</body>
```

```css
.skip-link {
  position: absolute;
  top: -100%;
  left: 0;
  z-index: 100;
  padding: 0.75rem 1rem;
  background: var(--focus-ring-color, #c8ff00);
  color: #0a0a0a;
  font-weight: 600;
  text-decoration: none;
}

.skip-link:focus {
  top: 0;
}
```

Thêm `tabindex="-1"` lên `<main>` cho phép focus theo chương trình sau khi skip link kích hoạt, để AT đọc landmark:

```typescript
document.querySelector('.skip-link')?.addEventListener('click', (event) => {
  const main = document.getElementById('main-content');
  if (!main) return;
  event.preventDefault();
  main.focus();
});
```

Đặt skip link cho vùng lặp khi cần — nhưng **"Skip to main content"** là cái bắt buộc.

## 7. Pattern bàn phím chuẩn

Người dùng học quy ước nền tảng một lần và mong mọi site tuân theo. Lệch chuẩn buộc học lại mỗi lần ghé.

### Phần tử cơ bản

| Element | Keys | Behavior |
|---------|------|----------|
| **Button** | `Enter`, `Space` | Kích hoạt |
| **Link** | `Enter` | Điều hướng (Space cuộn trang — đừng chặn) |
| **Checkbox / radio** | `Space` | Bật/tắt / chọn trong nhóm |
| **Text input** | Printable keys | Gõ; `Escape` có thể xóa (tùy chọn) |
| **Select (native)** | `Space`, arrows | Mở / di chuyển option |

### Widget composite (giới thiệu)

Widget tùy chỉnh thêm điều hướng phím mũi tên trong container:

| Widget | Tab | Inside widget |
|--------|-----|---------------|
| **Tabs** | Stops on tab list | `←` `→` move tabs; `Enter`/`Space` activate |
| **Menu / menubar** | Stops on menu button | Arrows move items; `Escape` closes |
| **Radio group** | One stop for group (roving) | `↑` `↓` or `←` `→` move selection |
| **Dialog (modal)** | Trapped inside | `Escape` closes (if not destructive) |

Phần 9 implement pattern này từ APG đầy đủ.

### Phím tắt phổ quát người dùng mong đợi

- đóng modal, dropdown, hoặc hủy thao tác.
- xác nhận / kích hoạt hành động chính trong dialog.
- **Không kẹt phím** — người dùng luôn tab ra được trừ khi trong modal trap có chủ đích (Phần 5).

```typescript
// Minimal keyboard support for a custom toggle button
function onToggleKeyDown(event: KeyboardEvent, toggle: () => void): void {
  if (event.key === 'Enter' || event.key === ' ') {
    event.preventDefault();
    toggle();
  }
}
```

## 8. Roving tabindex — một tab stop mỗi nhóm

Trong widget composite (toolbar, tab list, radio group), cho mỗi item `tabindex="0"` nghĩa là hàng chục lần Tab để qua một control. **Roving tabindex** giữ **một** tab stop cho nhóm; phím mũi tên di chuyển focus bên trong.

```html
<div role="toolbar" aria-label="Text formatting">
  <button type="button" tabindex="0" aria-pressed="false">Bold</button>
  <button type="button" tabindex="-1" aria-pressed="false">Italic</button>
  <button type="button" tabindex="-1" aria-pressed="false">Underline</button>
</div>
```

```typescript
function roveFocus(
  items: HTMLElement[],
  currentIndex: number,
  direction: 1 | -1
): void {
  const nextIndex = (currentIndex + direction + items.length) % items.length;
  items[currentIndex]?.setAttribute('tabindex', '-1');
  items[nextIndex]?.setAttribute('tabindex', '0');
  items[nextIndex]?.focus();
}

function onToolbarKeyDown(event: KeyboardEvent, items: HTMLElement[]): void {
  const current = items.findIndex((el) => el === document.activeElement);
  if (current === -1) return;

  if (event.key === 'ArrowRight') {
    event.preventDefault();
    roveFocus(items, current, 1);
  }
  if (event.key === 'ArrowLeft') {
    event.preventDefault();
    roveFocus(items, current, -1);
  }
}
```

Item active giữ `tabindex="0"`; anh em giữ `-1`. Phím mũi tên rove focus và đổi giá trị tabindex. Đây là pattern APG chuẩn — Phần 9 áp dụng cho tab, menu, và listbox.

---

## Tóm tắt

- **Truy cập bàn phím là WCAG Level A** — người khiếm vận động, screen reader, và power user đều phụ thuộc.
- **Phần tử tương tác gốc** focusable và thao tác bàn phím được mặc định.
- **`tabindex="0"`** thêm tab stop tùy chỉnh; **`tabindex="-1"`** chỉ focus theo chương trình; **tabindex dương là anti-pattern**.
- **Tab order theo DOM** — reorder thị giác CSS (`order`, `grid-area`) có thể phá âm thầm.
- **Không bỏ outline focus** nếu không có thay thế `:focus-visible` đạt yêu cầu tương phản.
- **Skip link** cho người dùng bàn phím bỏ qua nav lặp và nhảy tới `<main>`.
- **Pattern phím chuẩn** và **roving tabindex** cho control nhóm là bắt buộc với widget tùy chỉnh.

**Phần tiếp theo:** Quản lý focus trong SPA — đổi route, modal, focus trap, và trả focus khi overlay đóng.
