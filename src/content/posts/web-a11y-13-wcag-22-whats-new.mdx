Mười hai phần đầu xây nền trên WCAG 2.1 mức AA. Nhưng tiêu chuẩn không đứng yên: **WCAG 2.2** (khuyến nghị chính thức từ 2023) thêm chín tiêu chí thành công mới, hầu hết nhắm vào người khiếm vận động và khiếm nhận thức — đúng những nhóm dễ bị bỏ quên. Phần này mở đầu loạt bài chuyên sâu bằng việc cập nhật bạn lên đúng phiên bản tiêu chuẩn hiện hành, rồi nhìn xa tới WCAG 3.

> Vì sao quan trọng: nhiều khung pháp lý (EU EAA 2025, EN 301 549) đang dần tham chiếu WCAG 2.2. Code đạt 2.1 AA có thể vẫn thiếu vài tiêu chí 2.2 AA.

---

## 1. Toàn cảnh: 9 tiêu chí mới + 1 bị gỡ

```text
WCAG 2.2 = WCAG 2.1 + 9 tiêu chí mới − 1 tiêu chí gỡ (4.1.1 Parsing)

Mới ở mức AA (6):           Mới ở mức AAA (3):
 2.4.11 Focus Not Obscured   2.4.12 Focus Not Obscured (Enhanced)
 2.5.7  Dragging Movements   2.4.13 Focus Appearance
 2.5.8  Target Size (Min)    3.3.9  Accessible Authentication (Enhanced)
 3.2.6  Consistent Help
 3.3.7  Redundant Entry
 3.3.8  Accessible Authentication (Min)
```

Tin tốt: **4.1.1 Parsing** bị gỡ (đánh dấu obsolete). Trình duyệt hiện đại tự sửa HTML lỗi, nên "thẻ phải đóng đúng, id duy nhất" không còn là tiêu chí riêng — bạn không cần lo về nó nữa (dù HTML hợp lệ vẫn tốt cho lý do khác).

## 2. Target Size (Minimum) — 2.5.8 (AA)

Vùng bấm phải **tối thiểu 24×24 CSS px**, hoặc có khoảng đệm đủ để hình tròn 24px quanh tâm không chồng lên target khác. Giúp người run tay, ngón to, dùng cảm ứng.

```css
/* ✅ đảm bảo tối thiểu 24×24, kể cả icon button nhỏ */
.icon-btn {
  min-block-size: 24px;
  min-inline-size: 24px;
  /* tốt hơn: 44×44 theo khuyến nghị cảm ứng (Part 21) */
}

/* Nếu mục tiêu nhỏ buộc phải có, dùng spacing để đạt ngoại lệ "khoảng cách" */
.tag-list { display: flex; gap: 24px; }
```

Ngoại lệ: link trong câu văn (inline), target do trình duyệt/UA quy định, hoặc có cách tương đương khác trên trang. Đây là sàn AA — Part 21 bàn mục tiêu 44px cho cảm ứng.

## 3. Focus Not Obscured (Minimum) — 2.4.11 (AA)

Khi một phần tử nhận focus bàn phím, nó **không được bị che hoàn toàn** bởi nội dung khác do tác giả tạo (sticky header, cookie banner, toolbar dính).

```text
❌ Sticky header che mất ô input vừa được Tab tới
┌──────────────────────────┐
│ STICKY HEADER (z cao)    │ ← che
├──────────────────────────┤
│ [input đang focus] ◄─────│── người dùng không thấy vòng focus
```

```css
/* ✅ chừa chỗ để phần tử focus không lọt dưới header dính */
:root { scroll-padding-top: 5rem; } /* khi cuộn tới anchor/focus */
/* hoặc dùng scroll-margin trên các target focus */
.section { scroll-margin-top: 5rem; }
```

Mức **Enhanced (2.4.12, AAA)** mạnh hơn: phần tử focus *không bị che chút nào*.

---

## 4. Focus Appearance — 2.4.13 (AAA)

Chỉ báo focus phải đủ to và tương phản: tối thiểu bằng diện tích đường viền 2px CSS quanh phần tử, và tương phản ≥ 3:1 giữa trạng thái có/không focus. Dù là AAA, nên xem như mục tiêu chất lượng.

```css
/* ✅ vòng focus dày, tương phản cao, không bao giờ outline:none trơ trọi */
:focus-visible {
  outline: 3px solid var(--accent);
  outline-offset: 2px;
}
```

## 5. Dragging Movements — 2.5.7 (AA)

Mọi chức năng dùng **kéo-thả** phải có cách thay thế **single-pointer** (không cần kéo), trừ khi kéo là thiết yếu. Giúp người không thực hiện được động tác kéo chính xác.

```text
Kéo-thả slider / sắp xếp / vẽ:
  ✅ kèm nút +/− hoặc click-to-move / lên-xuống
  ✅ hoặc click chọn → click đích
```

Đây là lý do mọi sortable list nên có nút "Move up / Move down". Part 17 dành riêng cho drag-and-drop accessible và liên hệ tiêu chí này.

## 6. Consistent Help (3.2.6) & Redundant Entry (3.3.7) — AA

**Consistent Help**: nếu trang có cơ chế trợ giúp (số điện thoại, chat, link "Liên hệ", "Tự phục vụ"), nó phải xuất hiện ở **cùng thứ tự tương đối** trên các trang — người khiếm nhận thức tìm thấy giúp đỡ ở chỗ quen thuộc.

**Redundant Entry**: trong cùng một quy trình (vd checkout nhiều bước), **không bắt nhập lại** thông tin đã nhập — tự điền lại hoặc cho chọn lại.

```html
<!-- ✅ địa chỉ giao = địa chỉ thanh toán: cho dùng lại, đừng bắt gõ lại -->
<label><input type="checkbox" name="same-as-shipping"> Dùng địa chỉ giao hàng</label>
```

Ngoại lệ Redundant Entry: nhập lại vì lý do bảo mật (vd nhập lại mật khẩu để xác nhận).

## 7. Accessible Authentication — 3.3.8 (AA) / 3.3.9 (AAA)

Không được bắt **một bài kiểm tra nhận thức** (nhớ mật khẩu, giải puzzle, chép ký tự) làm bước *bắt buộc* để đăng nhập, trừ khi có cách thay thế.

```text
✅ Cho phép:
  - dán mật khẩu (KHÔNG chặn paste!)
  - trình quản lý mật khẩu / autofill
  - đăng nhập bằng email link / passkey (WebAuthn)
  - OAuth
❌ Vi phạm:
  - chặn paste vào ô mật khẩu/OTP
  - CAPTCHA chữ méo là bước duy nhất
  - bắt nhớ rồi gõ lại mã không cho copy
```

```html
<!-- ✅ giúp password manager + autofill hoạt động (đừng chặn) -->
<input type="password" name="password" autocomplete="current-password">
<input type="text" name="otp" inputmode="numeric" autocomplete="one-time-code">
```

Mức **Enhanced (AAA)** loại cả ngoại lệ "nhận diện đối tượng". Thực tế: **đừng bao giờ chặn paste**, hỗ trợ passkey/autofill là cách dễ nhất đạt tiêu chí này.

## 8. WCAG 3 & APCA — đường chân trời

WCAG 3 (tên mã "Silver") là viết lại lớn, vẫn đang dự thảo (chưa dùng để tuân thủ). Vài điểm đáng theo dõi:

- **Mô hình điểm mới**: thay nhệ A/AA/AAA bằng thang đánh giá (bronze/silver/gold) linh hoạt hơn, phủ nhiều khuyết tật hơn.
- **APCA (Advanced Perceptual Contrast Algorithm)**: thuật toán tương phản mới thay công thức tỉ lệ 4.5:1 cũ — tính tới độ sáng cảm nhận, kích thước và độ đậm chữ. Chính xác hơn cho dark mode và chữ mảnh.

```text
Hôm nay:   dùng WCAG 2.2 AA để tuân thủ; thử APCA như công cụ tham khảo cho màu.
Tương lai: WCAG 3 sẽ mất nhiều năm để hoàn thiện và được luật tham chiếu.
```

Đừng chờ WCAG 3 — nó còn xa. Hãy chuẩn hóa lên **2.2 AA** ngay.

---

## Tóm tắt

- **WCAG 2.2** thêm 9 tiêu chí (6 ở AA) và **gỡ 4.1.1 Parsing** — bạn không cần lo HTML "hợp lệ tuyệt đối" như một tiêu chí nữa.
- AA mới phải đạt: **Target Size 24px**, **Focus Not Obscured**, **Dragging Movements** (luôn có cách không-kéo), **Consistent Help**, **Redundant Entry**, **Accessible Authentication** (đừng chặn paste, hỗ trợ passkey/autofill).
- AAA mới: Focus Not Obscured (Enhanced), **Focus Appearance**, Accessible Authentication (Enhanced) — nên xem là mục tiêu chất lượng.
- **WCAG 3 + APCA** là tương lai (dự thảo); dùng để tham khảo nhưng vẫn tuân thủ theo **2.2 AA** hôm nay.

**Phần tiếp theo:** APG composite widgets nâng cao — dựng combobox/autocomplete (pattern khó nhất), menu/menubar và treegrid đúng chuẩn WAI-ARIA Authoring Practices, với quản lý focus và thông báo chuẩn xác.
