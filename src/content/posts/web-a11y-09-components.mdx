Phần 1–8 đã cho bạn semantic, từ vựng ARIA, quy tắc bàn phím, quản lý focus, form, tên và thiết kế thị giác. Phần 9 áp dụng tất cả vào **widget thật** — pattern người dùng chạm mỗi ngày trong dashboard, panel cài đặt và ô tìm kiếm.

Tài liệu chuẩn là **[WAI-ARIA Authoring Practices Guide (APG)](https://www.w3.org/WAI/ARIA/apg/)** — với mỗi widget nó chỉ rõ **role, state, property, tương tác bàn phím và hành vi focus**. Coi APG là spec; lệch không có lý do ghi rõ là cách bug lọt production.

> **Quy tắc production:** với widget phức tạp (combobox, date picker, tree view), dùng **headless library đã được kiểm chứng** — Radix UI, React Aria, Headless UI — thay vì tự viết. Pattern APG trên giấy trông đơn giản; edge case thì không.

## 1. Cách đọc APG

Mỗi trang pattern APG có cấu trúc nhất quán:

| Section | Cho bạn biết gì |
|---------|--------------------------------------|
| **Roles** | Which ARIA roles each element carries (`tablist`, `tab`, `dialog`, …) |
| **States & properties** | Dynamic attributes (`aria-expanded`, `aria-selected`, `aria-modal`) |
| **Keyboard interaction** | Exact keys and when they apply |
| **Focus management** | Where focus moves on open, close, and navigation |
| **Examples** | Reference HTML/JS implementations |

Khi dựng bằng React (hay framework bất kỳ), bạn dịch **quy tắc focus/bàn phím mệnh lệnh** của APG thành state + event handler — thuộc tính ARIA một mình không làm gì nếu thiếu hành vi phía sau.

## 2. Disclosure (mở/đóng) — pattern đơn giản nhất

**Disclosure** là button hiện hoặc ẩn một phần nội dung. Nó là nền cho accordion, FAQ, và panel "Tùy chọn nâng cao".

### Yêu cầu APG

- Trigger là **`<button>`** (không phải div) với **`aria-expanded="true|false"`**.
- **`aria-controls="panel-id"`** nối button với panel nó bật/tắt.
- Panel là **region** có `id`; khi đóng, nội dung ẩn (không chỉ visually — thuộc tính `hidden` hoặc unmount cẩn thận).
- **`Enter`** và **`Space`** bật/tắt; không cần phím mũi tên.

### Đường tắt gốc

Nếu không cần hook style tùy chỉnh, **`<details>` + `<summary>`** implement disclosure không cần JS — ưu tiên dùng:

```html
<details>
  <summary>Advanced filters</summary>
  <div>
    <label>Min price <input type="number" /></label>
  </div>
</details>
```

### Ví dụ React — disclosure tùy chỉnh

```tsx
import { useId, useState } from 'react';

export function Disclosure({
  title,
  children,
  defaultOpen = false,
}: {
  title: string;
  children: React.ReactNode;
  defaultOpen?: boolean;
}) {
  const [open, setOpen] = useState(defaultOpen);
  const panelId = useId();

  return (
    <div className="disclosure">
      <button
        type="button"
        aria-expanded={open}
        aria-controls={panelId}
        onClick={() => setOpen((v) => !v)}
        className="flex w-full items-center justify-between"
      >
        {title}
        <span aria-hidden="true">{open ? '▾' : '▸'}</span>
      </button>
      <div
        id={panelId}
        role="region"
        aria-labelledby={undefined}
        hidden={!open}
      >
        {open ? children : null}
      </div>
    </div>
  );
}
```

Khi nhiều disclosure tạo **accordion**, thêm **`aria-disabled`** trên header khác nếu chỉ một panel mở, hoặc dùng roving pattern — xem pattern Accordion trong APG.

## 3. Tabs — roving tabindex và phím mũi tên

Tabs là widget bị làm hỏng phổ biến vì dev coi chúng là div có style với click handler. Pattern **Tabs** APG yêu cầu cấu trúc chính xác:

```text
[tablist]
  ├── tab (aria-selected, aria-controls → tabpanel)
  ├── tab
  └── tab
[tabpanel] (aria-labelledby → tab)
[tabpanel]
```

### Role và thuộc tính

| Element | Role | Key attributes |
|---------|------|----------------|
| Container | `tablist` | `aria-label` or `aria-labelledby` if multiple tab sets |
| Tab | `tab` | `aria-selected`, `aria-controls="panel-id"`, `id="tab-id"` |
| Panel | `tabpanel` | `aria-labelledby="tab-id"`, `id="panel-id"`, `tabIndex={0}` when active |

### Bàn phím (pattern Tabs APG)

Khi focus **trên tablist**:

- **Mũi tên Trái/Phải** — di chuyển giữa tab, kích hoạt tab focus (automatic) hoặc chỉ di chuyển focus (manual — chọn một và ghi rõ).
- **`Home` / `End`** — tab đầu / tab cuối.
- **`Tab`** — chuyển focus **vào** tab panel đang active (không phải sang tab kế tiếp).

### Roving `tabindex`

Chỉ **một tab** trong list có `tabIndex={0}`; các tab khác `tabIndex={-1}`. Phím mũi tên di chuyển focus và cập nhật roving tabindex — người dùng Tab vào tablist một lần, rồi mũi tên bên trong.

### Ví dụ React — tabs accessible

```tsx
import { useId, useRef, useState, type KeyboardEvent } from 'react';

const tabs = [
  { label: 'Overview', content: 'Overview content…' },
  { label: 'Settings', content: 'Settings content…' },
  { label: 'Billing', content: 'Billing content…' },
] as const;

export function Tabs() {
  const baseId = useId();
  const [activeIndex, setActiveIndex] = useState(0);
  const tabRefs = useRef<(HTMLButtonElement | null)[]>([]);

  function focusTab(index: number) {
    const clamped = (index + tabs.length) % tabs.length;
    setActiveIndex(clamped);
    tabRefs.current[clamped]?.focus();
  }

  function onKeyDown(e: KeyboardEvent<HTMLDivElement>) {
    const keys = ['ArrowLeft', 'ArrowRight', 'Home', 'End'] as const;
    if (!keys.includes(e.key as (typeof keys)[number])) return;
    e.preventDefault();

    if (e.key === 'ArrowLeft') focusTab(activeIndex - 1);
    if (e.key === 'ArrowRight') focusTab(activeIndex + 1);
    if (e.key === 'Home') focusTab(0);
    if (e.key === 'End') focusTab(tabs.length - 1);
  }

  return (
    <div>
      <div role="tablist" aria-label="Account sections" onKeyDown={onKeyDown}>
        {tabs.map((tab, i) => {
          const tabId = `${baseId}-tab-${i}`;
          const panelId = `${baseId}-panel-${i}`;
          const selected = i === activeIndex;

          return (
            <button
              key={tabId}
              ref={(el) => { tabRefs.current[i] = el; }}
              role="tab"
              id={tabId}
              type="button"
              aria-selected={selected}
              aria-controls={panelId}
              tabIndex={selected ? 0 : -1}
              onClick={() => setActiveIndex(i)}
            >
              {tab.label}
            </button>
          );
        })}
      </div>

      {tabs.map((tab, i) => {
        const tabId = `${baseId}-tab-${i}`;
        const panelId = `${baseId}-panel-${i}`;
        const selected = i === activeIndex;

        return (
          <div
            key={panelId}
            role="tabpanel"
            id={panelId}
            aria-labelledby={tabId}
            hidden={!selected}
            tabIndex={0}
          >
            {tab.content}
          </div>
        );
      })}
    </div>
  );
}
```

> **Đừng** lồng phần tử tương tác (link, button) trong `role="tab"` mà không test kỹ — thứ tự focus rối. Đặt action phụ trong tab panel.

## 4. Modal dialog — focus trap và `aria-modal`

Phần 5 đã nói **focus trap** trong SPA. Pattern **Dialog (Modal)** APG thêm yêu cầu semantic:

| Requirement | Implementation |
|-------------|----------------|
| **`role="dialog"`** or **`role="alertdialog"`** | On the modal container |
| **`aria-modal="true"`** | Tells AT to ignore content behind the dialog |
| **Accessible name** | `aria-labelledby` pointing to the visible title, or `aria-label` |
| **Focus on open** | Move focus to the dialog or first focusable element (prefer the primary action or the dialog wrapper with `tabIndex={-1}`) |
| **Focus restore on close** | Return focus to the element that opened the dialog |
| **`Escape`** | closes (unless destructive confirmation requires explicit choice) |
| **Background inert** | `inert` attribute on `<main>` or focus trap + `aria-hidden="true"` on backdrop siblings (careful with `aria-hidden` on ancestors of focus) |

### Ưu tiên `<dialog>` gốc

Trình duyệt hiện đại hỗ trợ **`<dialog>`** với `showModal()` — top layer, backdrop, và xử lý **`Escape`** sẵn:

```tsx
import { useEffect, useRef } from 'react';

export function ConfirmDialog({
  open,
  title,
  onConfirm,
  onCancel,
}: {
  open: boolean;
  title: string;
  onConfirm: () => void;
  onCancel: () => void;
}) {
  const dialogRef = useRef<HTMLDialogElement>(null);
  const triggerRef = useRef<HTMLElement | null>(null);

  useEffect(() => {
    const dialog = dialogRef.current;
    if (!dialog) return;

    if (open) {
      triggerRef.current = document.activeElement as HTMLElement;
      dialog.showModal();
    } else if (dialog.open) {
      dialog.close();
      triggerRef.current?.focus();
    }
  }, [open]);

  return (
    <dialog
      ref={dialogRef}
      aria-labelledby="dialog-title"
      onCancel={(e) => {
        e.preventDefault();
        onCancel();
      }}
      className="rounded-lg border border-border bg-bg p-6"
    >
      <h2 id="dialog-title">{title}</h2>
      <p>Delete this item permanently?</p>
      <div className="mt-4 flex gap-2">
        <button type="button" onClick={onCancel}>
          Cancel
        </button>
        <button type="button" onClick={onConfirm}>
          Delete
        </button>
      </div>
    </dialog>
  );
}
```

Verify **focus trap** và **scroll lock** trên trình duyệt mục tiêu — polyfill hoặc bổ sung headless dialog nếu hỗ trợ `<dialog>` chưa đủ.

## 5. Combobox / autocomplete — cái khó

Pattern **Combobox** APG nối input text với popup listbox — dùng trong tìm kiếm, chọn quốc gia, tag picker. Đây là **widget phổ biến khó nhất** vì kết hợp:

- Text input semantics and **`aria-autocomplete`**
- **`role="combobox"`** with **`aria-expanded`**, **`aria-controls`**, **`aria-activedescendant`**
- **`role="listbox"`** with **`role="option"`** children
- Keyboard: **Arrow Up/Down** to highlight, **Enter** to select, **Escape** to close, **typeahead**, home/end, page up/down
- Focus management between input and list (focus stays on input; activedescendant points to highlighted option)
- Async filtering, virtualization, and multi-select variants

```tsx
// Illustrative structure — not production-complete
<input
  role="combobox"
  aria-expanded={open}
  aria-controls="listbox-id"
  aria-activedescendant={open ? `option-${activeIndex}` : undefined}
  aria-autocomplete="list"
  onKeyDown={handleComboboxKeys}
/>
<ul
  id="listbox-id"
  role="listbox"
  hidden={!open}
>
  {options.map((opt, i) => (
    <li
      key={opt.id}
      id={`option-${i}`}
      role="option"
      aria-selected={i === activeIndex}
    >
      {opt.label}
    </li>
  ))}
</ul>
```

**Đừng ship combobox tự viết** trừ khi team có ngân sách maintain theo cập nhật APG và browser quirks. Dùng **Radix**, **React Aria ComboBox**, hoặc **Headless UI Combobox** — chúng xử lý activedescendant, typeahead và hành vi mobile.

## 6. Khi nào tự viết vs dùng library

| Widget | Hand-roll OK? | Recommended approach |
|--------|---------------|---------------------|
| **Disclosure** | ✅ Yes — or use `<details>` | Native or ~30 lines of React |
| **Tabs** | ⚠️ Careful — medium complexity | APG example or headless if >3 tab sets |
| **Dialog** | ⚠️ Prefer `<dialog>` | Native `<dialog>` + focus restore, or Radix Dialog |
| **Combobox** | ❌ No for production | React Aria, Radix, Headless UI |
| **Date picker, tree, menu** | ❌ No | Always use a vetted library |

Library cho **bản đồ bàn phím, focus trap và tuân APG** được team maintain sửa bug cross-browser — code sản phẩm tập trung business logic.

## 7. Checklist review component

Trước khi merge widget tùy chỉnh:

1. **Pattern APG** đã xác định và link trong PR.
2. **Role/state** khớp APG ở mọi trạng thái render.
3. **Bàn phím** — mọi phím APG hoạt động; không kẹt focus sai.
4. **Focus** — vòng thấy, vào/ra hợp lý, restore sau khi đóng.
5. **Tên** — mọi control có tên accessible (Phần 7).
6. **Test thủ công** — Tab + mũi tên + spot check screen reader (Phần 10).

## Tóm tắt

- **[WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/)** là spec cho role, state, bàn phím và focus widget — đọc trước khi dựng.
- **Disclosure** — `<button aria-expanded aria-controls>` + panel region; `<details>` khi có thể.
- **Tabs** — `tablist`/`tab`/`tabpanel`, `aria-selected`, roving `tabIndex`, mũi tên + Home/End.
- **Dialog** — `role="dialog"`, `aria-modal`, title có nhãn, focus trap + restore; ưu tiên `<dialog>`.
- **Combobox** — pattern khó nhất; dùng **React Aria / Radix / Headless UI** trên production.

**Phần tiếp theo:** Screen reader và test với công nghệ hỗ trợ — cách AT thực sự điều hướng UI và quy trình thực tế tìm bug mà automation bỏ sót.
