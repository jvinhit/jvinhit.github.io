Accessibility và internationalization (i18n) chồng lấn nhiều hơn ta tưởng. Một screen reader phải biết trang bằng *ngôn ngữ nào* để phát âm đúng giọng; một giao diện tiếng Ả Rập hay Do Thái phải chảy từ phải sang trái mà không vỡ; và số liệu phải đọc theo quy ước bản địa. Phần này nối a11y với i18n — đặc biệt quan trọng nếu bạn phục vụ người dùng đa ngôn ngữ.

> Mấu chốt: thuộc tính `lang` không chỉ cho SEO — nó quyết định **bộ giọng và quy tắc phát âm** mà screen reader dùng. Sai `lang` = giọng đọc sai, gần như không hiểu được.

---

## 1. lang — phát âm đúng ngôn ngữ

Khai báo ngôn ngữ trang trên `<html>`, và **đánh dấu đoạn đổi ngôn ngữ** bằng `lang` cục bộ. Screen reader chuyển bộ giọng theo đó.

```html
<html lang="vi">
  <body>
    <p>Tôi đang đọc cuốn <span lang="en">The Pragmatic Programmer</span>.</p>
    <p>Châm ngôn: <q lang="la">carpe diem</q>.</p>
  </body>
</html>
```

```text
Không có lang="en":  SR tiếng Việt đọc "The Pragmatic Programmer" bằng âm Việt → khó hiểu
Có lang="en":        SR chuyển sang giọng Anh cho đúng đoạn đó → tự nhiên
```

Dùng mã **BCP 47** hợp lệ: `vi`, `en`, `en-US`, `zh-Hans`, `ar`. Đây là tiêu chí WCAG **3.1.1 Language of Page** (A) và **3.1.2 Language of Parts** (AA).

## 2. dir & văn bản hai chiều (bidi)

Ngôn ngữ như Ả Rập, Do Thái, Ba Tư viết **phải-sang-trái (RTL)**. Đặt hướng bằng `dir` trên `<html>` (hoặc khối cụ thể), không bằng CSS — vì hướng là *ngữ nghĩa*, ảnh hưởng cả thứ tự đọc của AT.

```html
<html lang="ar" dir="rtl">
```

Khi trộn nội dung hai hướng (vd tên tiếng Anh trong câu Ả Rập), dùng `dir="auto"` hoặc phần tử `<bdi>` để cô lập, tránh chữ "nhảy" lung tung do thuật toán bidi của Unicode:

```html
<!-- Cô lập đoạn người-dùng-nhập có hướng chưa biết -->
<p lang="ar" dir="rtl">
  المستخدم <bdi>john_123</bdi> علّق
</p>
```

`<bdi>` (bidi isolation) ngăn một username hay giá trị động làm đảo lộn hướng của câu xung quanh — quan trọng cho nội dung do người dùng tạo.

## 3. Logical properties — layout đảo chiều tự động

Để giao diện RTL không vỡ, **đừng hard-code `left`/`right`**. Dùng **CSS logical properties** chảy theo hướng đọc. Khi `dir` đổi, layout tự lật.

```css
/* ❌ cố định vật lý — vỡ khi RTL */
.card { margin-left: 1rem; border-left: 2px solid; text-align: left; }

/* ✅ logic — tự lật theo dir */
.card {
  margin-inline-start: 1rem;     /* trái ở LTR, phải ở RTL */
  border-inline-start: 2px solid;
  text-align: start;
}
```

| Vật lý | Logic |
|---|---|
| `margin-left` | `margin-inline-start` |
| `padding-right` | `padding-inline-end` |
| `left` / `right` | `inset-inline-start` / `-end` |
| `width` / `height` | `inline-size` / `block-size` |

Logical properties vừa giúp RTL vừa làm code sạch hơn — nên dùng kể cả khi hiện chỉ hỗ trợ LTR.

## 4. Icon & hướng có ý nghĩa

Một số biểu tượng *có hướng* (mũi tên "tiếp theo", nút back) cần **lật** ở RTL; số khác (logo, icon play) thì **không**. Phân biệt rõ:

```css
/* Lật icon định hướng theo chiều đọc */
[dir="rtl"] .icon-next { transform: scaleX(-1); }
```

```text
Lật ở RTL:   mũi tên next/prev, breadcrumb chevron, nút undo/redo
KHÔNG lật:   đồng hồ, logo, icon play (▶ vẫn là play), số có chiều cố định
```

## 5. Format số/ngày/tiền — Intl & accessibility

Số liệu phải đọc theo quy ước bản địa, và screen reader đọc chúng dựa trên *văn bản hiển thị*. Dùng `Intl` để format đúng locale.

```js
// Định dạng theo locale → SR đọc tự nhiên theo ngôn ngữ đó
new Intl.NumberFormat('vi-VN', { style: 'currency', currency: 'VND' }).format(1500000);
// "1.500.000 ₫"
new Intl.DateTimeFormat('vi-VN', { dateStyle: 'long' }).format(new Date());
```

Với ngày/giờ, dùng `<time datetime="…">` để máy có giá trị chuẩn còn người đọc thấy bản địa hóa:

```html
<time datetime="2026-10-15">15 tháng 10, 2026</time>
```

> Cẩn thận viết tắt và ký hiệu: "T2" (thứ Hai), "tr." (trang) có thể bị SR đọc khó hiểu. Dùng `<abbr title="…">` cho từ viết tắt để cấp dạng đầy đủ.

---

## 6. Tóm tắt

- `lang` (BCP 47) trên `<html>` + đánh dấu **đoạn đổi ngôn ngữ** quyết định **giọng phát âm** của screen reader (WCAG 3.1.1/3.1.2).
- Hướng RTL đặt bằng **`dir`** (ngữ nghĩa), dùng `dir="auto"`/`<bdi>` để cô lập nội dung động hai chiều.
- Dùng **CSS logical properties** (`margin-inline-start`, `inset-inline-*`…) để layout tự lật theo hướng — sạch hơn và RTL-ready.
- **Lật** icon định hướng (mũi tên, back) ở RTL; **giữ nguyên** icon không định hướng (logo, play).
- Format số/ngày/tiền bằng **`Intl`** theo locale; dùng `<time datetime>` và `<abbr title>` để máy có giá trị chuẩn còn người đọc thấy bản địa hóa.

**Phần tiếp theo:** Cognitive accessibility (COGA) — ngôn ngữ rõ ràng, giảm tải trí nhớ, thông báo lỗi dễ hiểu, xử lý timeout, và xác thực không bắt ghi nhớ (liên hệ WCAG 2.2).
