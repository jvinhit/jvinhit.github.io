CLS (≤ 0.1) đo mức độ bố cục nhảy bất ngờ. Khác với LCP/INP (về tốc độ), CLS về **sự ổn định**. Nguyên nhân gần như luôn là một: **nội dung được chèn vào mà không chừa chỗ trước**, đẩy những thứ xung quanh đi. Tin tốt: phần lớn CLS sửa được triệt để bằng cách đặt chỗ trước.

---

## 1. Ảnh & video không có kích thước

Thủ phạm số một. Khi ảnh chưa tải, trình duyệt không biết nó cao bao nhiêu nên dành 0px; tải xong, ảnh "bung ra" đẩy nội dung bên dưới xuống.

```html
<!-- ❌ no dimensions → browser allocates 0px → jumps when loaded -->
<img src="/photo.jpg" alt="..." />

<!-- ✅ declare width/height → browser computes aspect-ratio and reserves space -->
<img src="/photo.jpg" alt="..." width="800" height="600" />
```

Mấu chốt hiện đại: chỉ cần khai báo `width`/`height` (thuộc tính HTML), trình duyệt tự tính **aspect-ratio** và giữ chỗ đúng — kể cả khi CSS làm ảnh co giãn responsive:

```css
img {
  max-width: 100%;
  height: auto; /* preserve ratio; paired with HTML width/height → no jump */
}
```

Với ảnh chưa biết tỉ lệ, dùng `aspect-ratio` trong CSS để giữ khung:

```css
.thumb {
  aspect-ratio: 16 / 9; /* reserve the correct ratio frame before the image loads */
}
```

Áp dụng tương tự cho `<video>`, `<iframe>` (embed YouTube, bản đồ) — luôn đặt kích thước/khung.

## 2. Nội dung chèn động: dành không gian trước

Banner thông báo, "đọc thêm", nội dung tải bất đồng bộ — nếu chèn vào *trên* nội dung người dùng đang xem sẽ đẩy mọi thứ xuống.

Nguyên tắc:

- **Dành sẵn không gian** (min-height) cho khu vực sẽ có nội dung động, để khi nội dung về không đẩy gì.
- **Đừng chèn nội dung phía trên nội dung hiện có** trừ khi do người dùng chủ động (CLS bỏ qua shift trong 500ms sau tương tác).
- **Skeleton có kích thước đúng** với nội dung thật — skeleton cao 100px rồi nội dung cao 300px vẫn gây shift.

```css
/* Reserve space for the banner so it doesn't push content when it appears */
.notification-slot {
  min-height: 60px;
}
```

## 3. Quảng cáo & embed: khung cố định

Quảng cáo là nguồn CLS khét tiếng vì kích thước thay đổi và tải muộn. Luôn **bọc trong container có kích thước cố định** theo slot lớn nhất dự kiến, để dù quảng cáo nào về cũng không đẩy bố cục:

```css
.ad-slot {
  min-height: 250px; /* match ad unit size; reserve even before ad loads */
  display: flex;
  align-items: center;
  justify-content: center;
}
```

## 4. Font swap gây shift (FOUT)

Khi font tùy chỉnh tải xong và thay font hệ thống, kích thước chữ thay đổi nhẹ → text "xô" lại → CLS. Đây là đánh đổi với LCP (Phần 10 bàn kỹ). Cách giảm shift:

- **`size-adjust` / `ascent-override`** trong `@font-face` để font hệ thống fallback *khớp metric* với font tùy chỉnh, làm bước swap gần như không đổi kích thước:

```css
@font-face {
  font-family: 'Inter Fallback';
  src: local('Arial');
  size-adjust: 107%; /* tune to match Inter width/height → swap doesn't jump */
  ascent-override: 90%;
}
```

- **Preload font critical** (Phần 4) để swap xảy ra sớm, trước khi người dùng kịp đọc.

> Đây là điểm tinh tế: `font-display: swap` tốt cho *cảm nhận tốc độ* (text hiện ngay) nhưng có thể *gây CLS* nếu fallback lệch metric. `size-adjust` hòa giải mâu thuẫn này.

## 5. Animation: dùng transform, không đổi layout

Animate các thuộc tính layout (`top`, `left`, `width`, `height`, `margin`) làm phần tử dịch chuyển *trong dòng layout* → có thể tính vào CLS và gây reflow mỗi frame. Animate bằng `transform` thì không:

```css
/* ❌ changing top shifts layout + may count toward CLS */
.toast { transition: top 0.3s; }

/* ✅ transform runs on compositor, doesn't touch layout, doesn't count CLS */
.toast { transition: transform 0.3s; }
```

(Đây cũng là bài học của RAIL/Animation ở Phần 1 và FLIP ở series thuật toán Phần 11.)

## 6. Tìm thủ phạm CLS cụ thể

CLS khó vì shift xảy ra chớp nhoáng. Cách định vị:

- **Tab Performance** (Phần 3): mỗi shift hiện một vạch "Layout Shift"; click để xem phần tử nào nhảy.
- **`LayoutShift` API** (Phần 2): log `entry.sources` để biết node nào dịch chuyển.

```ts
new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    const e = entry as LayoutShift;
    if (!e.hadRecentInput && e.value > 0.01) {
      // sources pinpoints exactly which node caused the shift
      console.log('Shift', e.value.toFixed(3), e.sources?.map((s) => s.node));
    }
  }
}).observe({ type: 'layout-shift', buffered: true });
```

## 7. Checklist CLS

1. Mọi `<img>`/`<video>`/`<iframe>` có **width/height** hoặc **aspect-ratio**?
2. Khu vực nội dung động có **min-height** chừa sẵn?
3. Quảng cáo/embed bọc trong **container cố định**?
4. Font có **preload** + **fallback khớp metric** (`size-adjust`)?
5. Animation chỉ dùng **transform/opacity**, không đổi thuộc tính layout?
6. Skeleton **đúng kích thước** với nội dung thật?

---

## Tóm tắt

- CLS = bố cục nhảy do **chèn nội dung không chừa chỗ**; sửa bằng đặt chỗ trước.
- Ảnh/video/iframe: luôn khai **width/height** hoặc **aspect-ratio**.
- Nội dung động/quảng cáo: **dành min-height** và **container cố định**; đừng chèn phía trên nội dung đang xem.
- Font swap: dùng **`size-adjust`** để fallback khớp metric + preload → swap không nhảy.
- Animate bằng **transform**, không đổi thuộc tính layout.

**Phần tiếp theo:** JavaScript performance — bundle size, code splitting, tree shaking và lazy load.
