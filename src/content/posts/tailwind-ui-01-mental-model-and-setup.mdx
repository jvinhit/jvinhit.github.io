## 1. Vấn đề mà utility-first giải quyết

CSS truyền thống bắt bạn nghĩ ra tên cho mọi thứ. Bạn viết `.card`, `.card__title`, `.card--featured`, rồi nhảy qua lại giữa file HTML và file CSS để giữ chúng đồng bộ. Tên bị lệch, file phình mãi (CSS thực tế chỉ thêm chứ hiếm khi xóa), và câu hỏi "class này còn dùng không?" trở nên không thể trả lời.

```css
/* The traditional way — naming + a separate file + context switching */
.btn-primary {
  padding: 0.5rem 1rem;
  border-radius: 0.375rem;
  background: #6366f1;
  color: white;
  font-weight: 600;
}
```

```html
<button class="btn-primary">Save</button>
```

Tailwind lật ngược lại: thay vì đặt tên cho một *component* rồi định nghĩa style ở nơi khác, bạn áp các **utility class** nhỏ, đơn-nhiệm ngay trong markup.

```html
<!-- The Tailwind way — design in your markup, no naming, no CSS file -->
<button class="px-4 py-2 rounded-md bg-indigo-500 text-white font-semibold">
  Save
</button>
```

Mỗi class là *một* khai báo CSS: `px-4` → `padding-left/right: 1rem`, `rounded-md` → `border-radius: 0.375rem`, và cứ thế. Đó là toàn bộ ý tưởng.

## 2. Một ý tưởng làm mọi thứ "thông"

> **Một utility class là cái tên cho một khai báo CSS đơn lẻ, cố định.**

Các giá trị không tùy tiện — chúng đến từ một **thang design system**. Bước spacing, bảng màu, thang radius, thang shadow. Nhờ vậy UI của bạn *nhất quán theo thiết kế* — bạn chỉ chọn được trong thang.

Thử ngay bên dưới — bật/tắt utility và xem chuỗi `class` cùng **CSS tương đương** mà Tailwind sinh ra:

<iframe
  src="/tools/tailwind-utility-playground/"
  title="Tailwind utility-first playground"
  loading="lazy"
  style="width:100%;height:760px;border:1px solid var(--color-border);border-radius:8px;background:#0a0a0a;"

Hai phản đối thường gặp, trả lời luôn:

- *"Markup xấu / dài quá."* Sau một tuần bạn ngừng "đọc" các class, y như đã ngừng đọc `display: flex`. Lặp lại được giải quyết bằng **component**, không phải đặt tên CSS — Phần 5.
- *"CSS sẽ to lắm?"* Không — Tailwind quét file và chỉ sinh ra **những class bạn thực sự dùng**. Một build production điển hình chỉ vài kB.

## 3. Cài đặt — Tailwind v4 với Vite

Ta nhắm **Tailwind v4**, đơn giản hơn hẳn v3. Setup phổ biến nhất cho React là **Vite**.

**Bước 1 — cài**:

```bash
npm install tailwindcss @tailwindcss/vite
```

**Bước 2 — thêm plugin Vite**. Ở v4 không cần config PostCSS và không bắt buộc `tailwind.config.js` — plugin lo hết:

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import tailwindcss from '@tailwindcss/vite';

export default defineConfig({
  plugins: [react(), tailwindcss()],
});
```

**Bước 3 — import Tailwind trong CSS**. Một dòng này thay cho bộ ba `@tailwind base/components/utilities` cũ:

```css
/* src/index.css */
@import "tailwindcss";
```

**Bước 4 — đảm bảo CSS được nạp một lần**, tại entry của app:

```ts
// src/main.tsx
import './index.css';
```

Xong — `npm run dev` và mọi utility class đã sẵn sàng.

> **v3 vs v4 trong một hơi**: v3 dùng file config JS + PostCSS + ba directive `@tailwind`. v4 dùng plugin Vite/PostCSS, một `@import "tailwindcss"`, và đưa cấu hình **vào trong CSS** qua `@theme` (Phần 3). Nếu bạn vào codebase v3, *các utility class gần như giống hệt* — chỉ khác phần setup.

### Cài cho editor — làm một lần

Cài extension **Tailwind CSS IntelliSense** cho VS Code. Bạn có autocomplete cho mọi class, hover để xem CSS, và preview màu. Chính công cụ này biến "học thuộc class" thành "khám phá khi đang gõ".

## 4. Component đầu tiên do bạn ghép

Đọc một card thật từng dòng — mỗi class là một khai báo bạn đã nhận ra:

```html
<div class="max-w-sm rounded-xl bg-white p-6 shadow-md">
  <h3 class="text-lg font-semibold text-slate-900">Deploy faster</h3>
  <p class="mt-2 text-sm text-slate-600">
    Ship your UI without writing a single line of custom CSS.
  </p>
  <button class="mt-4 rounded-md bg-indigo-500 px-4 py-2 text-sm font-medium text-white">
    Get started
  </button>
</div>
```

Đọc nó dưới dạng CSS: `max-width` `24rem`, `border-radius: 0.75rem`, nền trắng, padding `1.5rem`, shadow vừa. Tiêu đề `1.125rem`, semibold, gần đen. `mt-2` / `mt-4` `mt-2` / `mt-4` là margin-top từ **cùng thang spacing**, nên nhịp nhìn cân mà không cần đo gì.

Sự nhất quán đó — mọi giá trị rút từ một thang chung — mới là phần thưởng thật của utility-first, và là nền cho mọi thứ còn lại trong series.

## Điểm chính

- Utility-first = **thiết kế ngay trong markup** bằng các class nhỏ đơn-nhiệm, thay vì đặt tên component và sửa stylesheet riêng.
- Một utility = **một khai báo CSS**, giá trị đến từ **thang design chung** → nhất quán theo thiết kế.
- **Setup v4 cực gọn**: plugin `@tailwindcss/vite` + một `@import "tailwindcss"`. Không PostCSS, không bắt buộc config JS.
- Cài **Tailwind IntelliSense** — biến học thuộc thành khám phá.
