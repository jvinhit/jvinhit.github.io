Factory là pattern khởi tạo (creational) đơn giản nhất và hữu dụng nhất ở frontend. Ý tưởng: thay vì rải logic "tạo cái gì, cấu hình ra sao" khắp codebase, ta **gom vào một nơi**. Khi cách tạo đổi, chỉ sửa một chỗ.

---

## 1. Vấn đề: logic khởi tạo bị rải khắp nơi

```ts
// ❌ "create client by environment" logic repeated in every file that needs it
// file A:
const client = import.meta.env.PROD
  ? new ApiClient({ baseUrl: 'https://api.prod.com', timeout: 5000 })
  : new ApiClient({ baseUrl: 'http://localhost:3000', timeout: 30000 });
// file B: ...copies the same block again, and forgets to update when config changes
```

Khi cấu hình thay đổi (thêm header xác thực, đổi timeout), bạn phải tìm và sửa mọi bản sao — và chắc chắn sẽ bỏ sót một chỗ.

---

## 2. Factory function: gom khởi tạo vào một hàm

Ở JavaScript/TypeScript, **factory function** (hàm trả về object) thường gọn và "JS" hơn class. Đây là dạng Factory bạn nên dùng mặc định.

```ts
interface ApiClient {
  get<T>(path: string): Promise<T>;
  post<T>(path: string, body: unknown): Promise<T>;
}

function createApiClient(config: { baseUrl: string; timeout: number; token?: string }): ApiClient {
  const headers: Record<string, string> = { 'Content-Type': 'application/json' };
  if (config.token) headers.Authorization = `Bearer ${config.token}`;

  const request = async <T>(path: string, init?: RequestInit): Promise<T> => {
    const res = await fetch(config.baseUrl + path, { ...init, headers });
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json() as Promise<T>;
  };

  return {
    get: (path) => request(path),
    post: (path, body) => request(path, { method: 'POST', body: JSON.stringify(body) }),
  };
}
```

Factory function tận dụng closure để giấu chi tiết (`headers`, `request`), chỉ lộ ra giao diện sạch — kết hợp đẹp với Module pattern (Phần 2).

## 3. Factory theo môi trường / theo loại

Khi cần chọn một trong nhiều cách tạo dựa trên điều kiện, Factory tập trung phép chọn đó vào một nơi:

```ts
type Environment = 'development' | 'staging' | 'production';

// Lookup table instead of if/else chains — easy to add new environments (Open/Closed, Part 1)
const ENV_CONFIG: Record<Environment, { baseUrl: string; timeout: number }> = {
  development: { baseUrl: 'http://localhost:3000', timeout: 30000 },
  staging: { baseUrl: 'https://api.staging.com', timeout: 10000 },
  production: { baseUrl: 'https://api.prod.com', timeout: 5000 },
};

export function apiClientFor(env: Environment, token?: string): ApiClient {
  return createApiClient({ ...ENV_CONFIG[env], token });
}
```

Dùng **bảng tra cứu** (object) thay vì `switch`/`if-else` là một nâng cấp quan trọng: thêm môi trường/loại mới chỉ là thêm một dòng vào bảng, không sửa logic — đúng nguyên lý Open/Closed.

## 4. Component Factory trong React

Factory cũng áp dụng cho component. Tình huống điển hình: render component khác nhau theo `type` của dữ liệu (notification, form field, block trong CMS).

```tsx
type FieldType = 'text' | 'number' | 'select' | 'checkbox';

interface FieldConfig {
  type: FieldType;
  name: string;
  label: string;
  options?: string[];
}

// Map type → component. Adding a new field type = one new entry.
const FIELD_COMPONENTS: Record<FieldType, React.ComponentType<{ config: FieldConfig }>> = {
  text: TextField,
  number: NumberField,
  select: SelectField,
  checkbox: CheckboxField,
};

function FieldFactory({ config }: { config: FieldConfig }) {
  const Component = FIELD_COMPONENTS[config.type];
  if (!Component) return null; // safe with unknown data
  return <Component config={config} />;
}

// Render an entire form from schema — no if/else per field type
function DynamicForm({ schema }: { schema: FieldConfig[] }) {
  return (
    <form>
      {schema.map((field) => <FieldFactory key={field.name} config={field} />)}
    </form>
  );
}
```

Pattern này là xương sống của mọi **form builder, page builder, CMS block renderer**: dữ liệu mô tả "cần gì", factory quyết định "dựng bằng component nào".

## 5. Factory cho test data (rất hay dùng)

Một ứng dụng Factory cực kỳ thực tế nhưng ít được gọi tên: **tạo dữ liệu test**. Thay vì lặp lại object đầy đủ trong mỗi test, factory tạo object mặc định và cho phép ghi đè phần cần:

```ts
function makeUser(overrides: Partial<User> = {}): User {
  return {
    id: crypto.randomUUID(),
    name: 'Nguyễn Văn A',
    role: 'member',
    createdAt: Date.now(),
    ...overrides, // only declare what's different per test
  };
}

const admin = makeUser({ role: 'admin' }); // concise, test intent is clear
```

Cách này làm test ngắn, dễ đọc, và khi `User` thêm trường mới bạn chỉ sửa factory — không sửa hàng chục test.

## 6. Khi nào KHÔNG dùng

- **Tạo object đơn giản, một kiểu, một chỗ** → một object literal là đủ. Đừng bọc Factory cho `{ x: 1 }`.
- **Abstract Factory nhiều tầng class** thường thừa ở frontend — JS có factory function gọn hơn nhiều, hiếm khi cần hệ thống class trừu tượng kiểu Java.
- Factory chỉ đáng giá khi (a) logic khởi tạo **lặp lại**, (b) cần **chọn theo điều kiện**, hoặc (c) cần **giấu chi tiết** phức tạp.

---

## Tóm tắt

- **Factory** gom logic khởi tạo vào một nơi; ở JS ưu tiên **factory function** hơn class.
- Dùng **bảng tra cứu** thay `if/else`/`switch` để chọn theo loại — thêm loại mới không sửa logic (Open/Closed).
- **Component factory** (bảng type → component) là xương sống của form/page builder và CMS.
- Factory cho **test data** (mặc định + overrides) làm test ngắn và bền.
- Đừng bọc Factory cho khởi tạo đơn giản — chỉ dùng khi có lặp lại, chọn điều kiện, hoặc cần giấu chi tiết.

**Phần tiếp theo:** Strategy — hoán đổi thuật toán/hành vi mà không đụng vào code gọi.
