## JWT thực chất là gì

JWT là ba phần Base64URL nối bằng dấu chấm. Header nêu thuật toán, payload chứa **claim**, signature chứng minh không bị giả mạo.

```text
eyJhbGciOiJIUzI1NiJ9 . eyJzdWIiOiIxMjMiLCJyb2xlIjoiYWRtaW4ifQ . <signature>
   header (alg)              payload (claims: sub, role, exp)         HMAC/RSA signature
```

Signature **không** phải mã hóa — ai cũng đọc được payload. **Đừng bao giờ để bí mật trong JWT**. Nó đảm bảo *tính toàn vẹn*, không phải *tính bí mật*.

```ts
import jwt from 'jsonwebtoken';
const token = jwt.sign({ sub: user.id, role: user.role }, process.env.JWT_SECRET!,
  { expiresIn: '15m', issuer: 'api', audience: 'web' });
const claims = jwt.verify(token, process.env.JWT_SECRET!, { issuer: 'api', audience: 'web' });
```

**HS256** dùng một secret chung; **RS256** ký bằng private key và verify bằng public key.

## Access token + refresh token

Một token sống lâu duy nhất là rủi ro — nếu bị trộm, kẻ tấn công có quyền lâu và bạn không thu hồi được. Pattern senior là **hai token**:

- sống ngắn, gửi mỗi request, không trạng thái.
- sống lâu, lưu phía server/thu hồi được, chỉ để cấp access token mới.

```ts
function issueTokens(user: User) {
  const accessToken  = jwt.sign({ sub: user.id, role: user.role }, ACCESS_SECRET, { expiresIn: '15m' });
  const refreshToken = jwt.sign({ sub: user.id, jti: randomUUID() }, REFRESH_SECRET, { expiresIn: '7d' });
  return { accessToken, refreshToken };
}
```

### Xoay refresh token

Mỗi lần dùng refresh token, cấp một cái **mới** và vô hiệu `jti` cũ. Nếu một token cũ (đã xoay) bị phát lại, đó là dấu hiệu trộm — thu hồi cả họ token và bắt đăng nhập lại.

## Thu hồi với Redis

JWT không trạng thái không thể bị hủy phát — nên cho logout và "thu hồi mọi nơi" bạn cần trạng thái server. Theo dõi `jti` của refresh token trong Redis với TTL bằng tuổi token:

```ts
// on login: allowlist this refresh token
await redis.set(`rt:${jti}`, user.id, 'EX', 7 * 24 * 3600);
// on refresh: must still exist, then rotate
if (!(await redis.get(`rt:${jti}`))) throw new UnauthorizedException('revoked');
await redis.del(`rt:${jti}`);                 // invalidate old
// on logout / breach: del the jti (or all of a user's) → instant revocation
```

Access token để ngắn nên hiếm khi cần chặn; cho khẩn cấp giữ một **denylist** nhỏ.

## Lưu token ở đâu — quyết định bảo mật thật sự

Đây là câu hỏi tách biệt senior:

| Lưu | Lộ với | Ghi chú |
| --- | --- | --- |
| `localStorage` + `Authorization` header | **XSS** (any injected script can read it) | easy CORS/mobile; one XSS = stolen token |
| `httpOnly` cookie | **CSRF** (sent automatically) | JS can't read it → XSS-safe; needs CSRF defense |

Đồng thuận senior: **refresh token trong cookie `httpOnly`, `Secure`, `SameSite`**; access token trong bộ nhớ.

```ts
res.cookie('refresh', refreshToken, {
  httpOnly: true,            // JS can't read it → mitigates XSS token theft
  secure: true,              // HTTPS only
  sameSite: 'strict',        // mitigates CSRF
  path: '/auth/refresh',     // sent only to the refresh endpoint
  maxAge: 7 * 24 * 3600_000,
});
```

`httpOnly` chặn đọc XSS; `SameSite` chặn phần lớn CSRF.

## OAuth2 & OIDC — đăng nhập ủy quyền

"Sign in with Google" là **OAuth2** cộng **OpenID Connect**. Dùng **Authorization Code flow với PKCE**:

1. App chuyển hướng tới provider kèm `code_challenge`.
2. User xác thực; provider chuyển về kèm **code** ngắn hạn.
3. App đổi code + `code_verifier` phía server lấy token.

PKCE buộc code với bên yêu cầu gốc, đánh bại tấn công chặn code. **Đừng tự cài crypto** — dùng strategy Passport hoặc client OIDC đã kiểm chứng, và luôn validate `state`, `nonce`, issuer, audience.

## RBAC làm guard NestJS

Xác thực là "bạn là ai"; **phân quyền** là "bạn được làm gì". Với vòng đời Phase 14, kiểm vai trò là một decorator + guard tùy biến:

```ts
export const Roles = (...roles: string[]) => SetMetadata('roles', roles);

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}
  canActivate(ctx: ExecutionContext): boolean {
    const required = this.reflector.get<string[]>('roles', ctx.getHandler());
    if (!required) return true;
    const { user } = ctx.switchToHttp().getRequest();        // set by the JWT auth guard
    return required.includes(user?.role);
  }
}

@Roles('admin')
@UseGuards(JwtAuthGuard, RolesGuard)
@Delete(':id')
remove(@Param('id', ParseIntPipe) id: number) { return this.posts.remove(id); }
```

Cho kiểm soát mịn hơn, lưu **permission** thay vì vai trò rộng.

## Các đòn tấn công mọi senior phòng vệ

- kẻ tấn công đặt header `none` hoặc tráo thuật toán. Ghim thuật toán mong đợi trong `verify`.
- luôn đặt `expiresIn`.
- secret HS256 phải dài và ngẫu nhiên, không commit.
- trộm token qua XSS — cookie `httpOnly` + CSP mạnh.
- validate `aud`/`iss`.
