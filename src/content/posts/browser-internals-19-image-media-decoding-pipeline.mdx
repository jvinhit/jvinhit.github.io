Ảnh thường là phần nặng nhất của một trang, và cách trình duyệt xử lý chúng ảnh hưởng trực tiếp tới mượt mà. Nhiều người nghĩ "tải ảnh xong là xong" — nhưng giữa byte tải về và pixel trên màn hình có một bước tốn kém dễ chặn luồng chính: **decode**. Phần này theo dấu một tấm ảnh từ mạng tới màn hình.

---

## 1. Ba giai đoạn: download → decode → upload

```text
Byte nén (JPEG/PNG/WebP/AVIF)
   │  ① download (mạng — Phần 9)
   ▼
Bitmap thô (pixel RGBA, KHÔNG nén — lớn hơn nhiều)
   │  ② decode (giải nén → pixel; tốn CPU/bộ nhớ)
   ▼
GPU texture
   │  ③ upload (đưa bitmap lên VRAM để composite)
   ▼
Màn hình
```

Điểm bất ngờ: file 200KB JPEG khi *decode* thành bitmap có thể chiếm hàng chục MB RAM (width × height × 4 byte). Decode cũng tốn CPU — và nếu chạy trên luồng chính, nó *chặn* mọi thứ khác (Phần 7).

---

## 2. Decode đồng bộ vs bất đồng bộ

Theo mặc định, trình duyệt cố decode ảnh *trước* khi present khung chứa nó. Decode lớn trên luồng chính → "janky" lúc ảnh xuất hiện. Thuộc tính `decoding` cho phép gợi ý:

```html
<!-- async: đừng chặn render để decode; hiện khi sẵn sàng -->
<img src="hero.avif" decoding="async" alt="...">

<!-- sync: decode trước khi present (hiếm khi cần) -->
<img src="logo.svg" decoding="sync" alt="...">
```

Để *chủ động* decode rồi mới chèn (tránh nhấp nháy/jank khi swap ảnh lớn):

```js
const img = new Image();
img.src = 'big.avif';
await img.decode();     // chờ decode xong (off-main-thread khi có thể)
container.append(img);  // chèn khi pixel đã sẵn sàng → không jank
```

`img.decode()` trả promise, resolve khi ảnh đã decode và sẵn sàng vẽ — lý tưởng cho chuyển ảnh trong gallery/lightbox.

## 3. createImageBitmap — decode off-main-thread

`createImageBitmap()` decode/resize ảnh thành một `ImageBitmap` — đối tượng bitmap đã giải mã, sẵn sàng vẽ, và có thể **transfer** sang worker. Đây là công cụ chuẩn để đẩy decode khỏi luồng chính.

```js
// Trong worker: tải + decode hoàn toàn ngoài luồng chính
const res = await fetch(url);
const blob = await res.blob();
const bitmap = await createImageBitmap(blob, {
  resizeWidth: 400, resizeQuality: 'high', // resize ngay khi decode
});
postMessage({ bitmap }, [bitmap]); // transfer (zero-copy) về main
```

Khác `new Image()`, `ImageBitmap` không gắn DOM, decode ngay, và transfer được — phù hợp pipeline xử lý ảnh nặng.

## 4. OffscreenCanvas — vẽ ngoài luồng chính

`OffscreenCanvas` tách canvas khỏi DOM để **render trong worker**. Kết hợp với `transferControlToOffscreen()`, toàn bộ việc vẽ (game, data-viz, xử lý ảnh) chạy trên worker, không đụng luồng chính.

```js
// main thread
const offscreen = canvas.transferControlToOffscreen();
worker.postMessage({ canvas: offscreen }, [offscreen]);

// worker.js — vẽ độc lập với luồng chính
onmessage = ({ data }) => {
  const ctx = data.canvas.getContext('2d');
  function draw() { /* ... */ ctx.clearRect(0,0,w,h); /* ... */ requestAnimationFrame(draw); }
  draw(); // rAF tồn tại trong worker với OffscreenCanvas
};
```

Đây là cầu nối tới Phần 20: OffscreenCanvas + worker là cách chính để giữ canvas 60fps khi luồng chính bận.

## 5. Lazy loading, priority & responsive

Trình duyệt cũng quyết định *khi nào* và *cái nào* tải, ảnh hưởng pipeline:

```html
<img
  src="photo-800.avif"
  srcset="photo-400.avif 400w, photo-800.avif 800w, photo-1600.avif 1600w"
  sizes="(max-width: 600px) 100vw, 800px"
  loading="lazy"          
  decoding="async"
  fetchpriority="low"     
  width="800" height="600" 
  alt="...">
```

- `loading="lazy"`: hoãn tải tới khi gần viewport (như `content-visibility` nhưng cho tải).
- `srcset`/`sizes`: chọn độ phân giải đúng → decode bitmap nhỏ hơn, ít RAM hơn.
- `fetchpriority`: nâng ảnh LCP (`high`) hoặc hạ ảnh phụ (`low`).
- `width`/`height`: cho trình duyệt biết tỉ lệ → tránh layout shift (CLS).

> Định dạng hiện đại (AVIF/WebP) decode khác JPEG; AVIF nén tốt hơn nhưng decode có thể nặng CPU hơn trên ảnh lớn — cân nhắc theo thiết bị mục tiêu.

## 6. Video — pipeline thời gian thực

Video không decode một lần mà là **dòng khung liên tục**, thường tăng tốc phần cứng:

```text
Container (mp4/webm) ─► demux ─► luồng video nén (H.264/VP9/AV1)
   │
   ▼ hardware decoder (GPU/ASIC) — không qua luồng chính
Khung đã decode ─► đồng bộ với audio clock ─► compositor ─► màn hình
```

API nâng cao: **WebCodecs** (`VideoDecoder`/`VideoEncoder`) cho truy cập khung ở mức thấp; `requestVideoFrameCallback` để chạy code đồng bộ từng khung video (vd vẽ overlay). Mặc định, `<video>` decode trên đường phần cứng và composite như một layer riêng (Phần 13), nên phát video không chặn luồng chính.

---

## 7. Tóm tắt

- Ảnh đi qua **download → decode → upload GPU**; decode giải nén thành bitmap RGBA *lớn hơn nhiều* file gốc và tốn CPU.
- `decoding="async"` tránh chặn render; `img.decode()` cho phép chờ decode xong trước khi chèn (hết jank khi swap ảnh lớn).
- **`createImageBitmap`** decode/resize off-main-thread và transfer được sang worker; `ImageBitmap` không gắn DOM.
- **`OffscreenCanvas`** + `transferControlToOffscreen()` đưa toàn bộ việc vẽ vào worker (rAF chạy trong worker).
- `loading="lazy"`, `srcset`/`sizes`, `fetchpriority`, `width/height` điều khiển *khi nào/cái nào* tải và tránh CLS.
- **Video** decode bằng phần cứng theo dòng khung, composite như layer riêng; WebCodecs/`requestVideoFrameCallback` cho điều khiển mức thấp.

**Phần tiếp theo:** Threading deep — Web Workers, SharedArrayBuffer + Atomics, OffscreenCanvas ở quy mô lớn, và cross-origin isolation (COOP/COEP) mở khoá bộ nhớ chia sẻ + timer độ phân giải cao.
