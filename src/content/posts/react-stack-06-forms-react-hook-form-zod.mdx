Ta đã có mutation `useCreateCustomer` từ Phần 5. Giờ dựng form nuôi nó — đúng cách. Form là nơi code non rò rỉ re-render và bug validate nhiều nhất, nên phần này làm *chuẩn production*: input không kiểm soát cho hiệu năng, **một schema zod** dùng chung form và API, và xử lý lỗi đúng cho cả cấp field lẫn cấp server.

---

## 1. Vì sao react-hook-form (không phải `useState` kiểm soát)?

*Docs: [react-hook-form](https://react-hook-form.com/get-started).*

### Cách ngây thơ

```tsx
const [name, setName] = useState('');
const [email, setEmail] = useState('');
// …a useState per field, an onChange per field…
<input value={name} onChange={(e) => setName(e.target.value)} />
```

Mỗi phím gọi `setState`, **re-render cả form**. Với 10 field và validate, gõ giật và component phình.

### Công cụ: input không kiểm soát qua ref

react-hook-form đăng ký input dạng **không kiểm soát** (đọc qua ref), nên phím không kích re-render React. Nó chỉ re-render khi cần — vd khi lỗi xuất hiện. Ít render, ít code, hiệu năng tốt hơn.

```bash
pnpm add react-hook-form @hookform/resolvers
```

### Tóm tắt một dòng

react-hook-form dùng input không kiểm soát nên gõ không re-render form — nhanh hơn và ít boilerplate hơn nhiều so với `useState` mỗi field.

## 2. Một schema zod, dùng chung form và API

Hình input của form tạo *chính là* hình input của API — nên định nghĩa một lần. Tái dùng schema field từ `customerSchema` của Phần 4 để tránh lệch:

```ts
// src/features/customers/schema.ts
import { z } from 'zod';

export const createCustomerSchema = z.object({
  name: z.string().min(2, 'Name must be at least 2 characters'),
  email: z.string().email('Enter a valid email'),
  plan: z.enum(['starter', 'pro', 'enterprise']),
});

// the form values type is derived — never hand-written
export type CreateCustomerValues = z.infer<typeof createCustomerSchema>;
```

Schema duy nhất này validate form *và* type input mutation từ Phần 5 — một nguồn chân lý cho hình, thông điệp, và type.

### Tóm tắt một dòng

Định nghĩa hình input một lần bằng schema zod và suy type bằng `z.infer`; form và mutation API dùng chung.

## 3. Nối form với `zodResolver`

`zodResolver` cắm schema vào react-hook-form để validate chạy từ cùng luật:

```tsx
// src/features/customers/CreateCustomerForm.tsx
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { createCustomerSchema, type CreateCustomerValues } from './schema';

export function CreateCustomerForm({ onDone }: { onDone: () => void }) {
  const { mutateAsync, isPending } = useCreateCustomer();

  const form = useForm<CreateCustomerValues>({
    resolver: zodResolver(createCustomerSchema),
    defaultValues: { name: '', email: '', plan: 'starter' },
  });

  // …render below…
}
```

`defaultValues` nên đầy đủ và ổn định — định nghĩa literal (không tạo lại từ props mỗi render) để RHF tính dirty đúng.

### Tóm tắt một dòng

`useForm` + `zodResolver(schema)` chạy validate từ luật zod; cho nó `defaultValues` đầy đủ, ổn định, type bằng `z.infer`.

## 4. Component Form shadcn + a11y

*Docs: [shadcn — Form](https://ui.shadcn.com/docs/components/form).*

Primitive `Form` của shadcn nối label, control, mô tả và thông điệp lỗi với đúng `aria-*` miễn phí:

```tsx
<Form {...form}>
  <form onSubmit={form.handleSubmit(onSubmit)} className="space-y-4" noValidate>
    <FormField
      control={form.control}
      name="name"
      render={({ field }) => (
        <FormItem>
          <FormLabel>Name</FormLabel>
          <FormControl>
            <Input placeholder="Acme Inc." {...field} />
          </FormControl>
          <FormMessage />
        </FormItem>
      )}
    />

    <FormField
      control={form.control}
      name="email"
      render={({ field }) => (
        <FormItem>
          <FormLabel>Email</FormLabel>
          <FormControl>
            <Input type="email" {...field} />
          </FormControl>
          <FormMessage />
        </FormItem>
      )}
    />

    <Button type="submit" disabled={isPending}>
      {isPending ? 'Saving…' : 'Create customer'}
    </Button>
  </form>
</Form>
```

`FormMessage` tự render lỗi zod của field; `FormLabel` liên kết input qua `htmlFor`, và lỗi nhận `aria-invalid` + `aria-describedby` để screen reader đọc. `noValidate` giao validate cho zod thay vì trình duyệt.

### Tóm tắt một dòng

`Form`/`FormField`/`FormMessage` của shadcn cho nối label↔input↔lỗi a11y mà không cần `aria-*` thủ công.

## 5. Submit vào mutation + map lỗi server

Handler submit chỉ chạy khi validate client qua; rồi await mutation và dịch lỗi *server* về đúng field:

```tsx
const onSubmit = form.handleSubmit(async (values) => {
  try {
    await mutateAsync(values);
    form.reset();
    onDone();
  } catch (error) {
    // map a known field error from the API onto the form
    if (error instanceof ApiError && error.status === 409) {
      form.setError('email', { message: 'This email already exists' });
      return;
    }
    // unknown errors already surfaced via the mutation's onError toast
  }
});
```

Hai lớp validate: **phía client** (zod, tức thì, không request) bắt lỗi rõ; **phía server** (map qua `form.setError`) bắt thứ chỉ server biết, như tính duy nhất. Đừng bao giờ tin mỗi client.

### Tóm tắt một dòng

`handleSubmit` chỉ chạy khi input hợp lệ; `await mutateAsync`, rồi map lỗi server đã biết (vd 409) vào field bằng `form.setError`.

## 6. Ghi chú hiệu năng & re-render

- **Đừng định nghĩa thân render `FormField` thành hàm component inline riêng** chỗ khác rồi remount — giữ là prop `render` inline mà RHF mong.
- Subscribe hẹp: đọc `isSubmitting`/`isDirty` chỉ nơi cần; `formState` là proxy theo dõi field bạn thực đọc.
- Với component kiểm soát ngoài (`Select` tùy biến), dùng `Controller` của RHF thay vì nâng lên `useState` và re-render form.

### Tóm tắt một dòng

Giữ input không kiểm soát, subscribe `formState` hẹp, và cầu nối widget kiểm soát bằng `Controller` — không phải thêm `useState`.

## 7. Bài tập

**1.** Vì sao input không kiểm soát nhanh hơn form `useState`-mỗi-field?

<details>
<summary>Lời giải</summary>

Input kiểm soát gọi `setState` mỗi phím, re-render cả form. Input không kiểm soát đọc qua ref, nên gõ không kích render; RHF chỉ re-render khi có gì quan sát được đổi (như lỗi).
</details>

**2.** Bạn validate bằng zod ở client. Sao vẫn xử lý lỗi server bằng `form.setError`?

<details>
<summary>Lời giải</summary>

Validate client không biết sự thật chỉ-server (vd email đã dùng). API từ chối vd 409, và `form.setError('email', …)` đặt thông điệp lên đúng field để user thấy tại chỗ. Kiểm client là UX, không phải bảo mật/chân lý.
</details>

**3.** Dùng chung một schema zod giữa form và API được gì?

<details>
<summary>Lời giải</summary>

Một nguồn chân lý cho hình, thông điệp, và type TS (`z.infer`). Form không thể validate khác hình API mong, và đổi field cập nhật cả validate lẫn type cùng lúc.
</details>

Nâng cao:đặt form vào `Dialog` shadcn, vô hiệu submit khi `isPending`, và khi thành công đóng dialog và toast — tái dùng mutation optimistic từ Phần 5.

## Điểm chính

- Input không kiểm soát qua react-hook-form = ít re-render, ít boilerplate hơn `useState` kiểm soát.
- **Một schema zod** validate form và type input API qua `z.infer`.
- Primitive `Form` shadcn cho nối label/lỗi a11y; `noValidate` nhường zod.
- Validate client *và* map lỗi server bằng `form.setError`; đừng tin mỗi client.
