Component shadcn đẹp sẵn, nhưng cốt lõi của việc *sở hữu code* là làm chúng trông giống **của bạn**. Theme shadcn chỉ là mẫu token ngữ nghĩa từ Phần 3, áp dụng có hệ thống. Nắm chắc và bạn re-skin cả app bằng cách sửa vài biến.

---

## 1. Theme chỉ là biến CSS

`init` đã thêm một khối **token màu ngữ nghĩa** vào stylesheet. Mọi component shadcn tham chiếu các tên này — không bao giờ màu thô:

```css
:root {
  --radius: 0.625rem;
  --background: oklch(1 0 0);
  --foreground: oklch(0.145 0 0);
  --primary: oklch(0.205 0 0);
  --primary-foreground: oklch(0.985 0 0);
  --secondary: oklch(0.97 0 0);
  --muted-foreground: oklch(0.556 0 0);
  --border: oklch(0.922 0 0);
  --destructive: oklch(0.577 0.245 27);
  --ring: oklch(0.708 0 0);
  /* …card, popover, accent, input… */
}

.dark {
  --background: oklch(0.145 0 0);
  --foreground: oklch(0.985 0 0);
  --primary: oklch(0.985 0 0);
  --primary-foreground: oklch(0.205 0 0);
  /* …every token redefined for dark… */
}
```

> shadcn hiện đại dùng màu **OKLCH** (đồng đều theo cảm nhận), nhưng cơ chế giống hệt mọi setup hex/HSL — vẫn chỉ là biến được định nghĩa lại dưới `.dark`.

Token được nối với Tailwind qua `@theme inline` để các utility như `bg-primary`, `text-muted-foreground`, `border-input` tồn tại:

```css
@theme inline {
  --color-background: var(--background);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  /* … */
}
```

## 2. Quy tắc cặp đôi: `*` và `*-foreground`

Cách đặt tên là một **hợp đồng**: một token nền `--primary` luôn có token chữ `--primary-foreground` khớp, đảm bảo đọc được trên đó. Nên bạn viết theo cặp:

```html
<div class="bg-primary text-primary-foreground">always legible</div>
<div class="bg-destructive text-white">…</div>
<div class="bg-muted text-muted-foreground">…</div>
```

Theo quy tắc này thì độ tương phản luôn đúng ở cả hai theme một cách tự động.

---

## 3. Gắn thương hiệu — đổi vài biến

Để biến `primary` thành màu brand, bạn đổi token ở **một nơi** và mọi Button, Badge, Switch, focus ring đi theo:

```css
:root  { --primary: oklch(0.62 0.19 260); --primary-foreground: oklch(0.98 0 0); }
.dark  { --primary: oklch(0.72 0.17 260); --primary-foreground: oklch(0.18 0 0); }
```

Chọn màu và radius rồi xem component re-skin trực tiếp, kèm CSS chính xác để paste:

## 4. Nối dây dark mode

Khối `.dark` đã có; bạn chỉ cần bật class. Trong app Vite thuần, đoạn ở Phần 3 hoạt động. Trong **Next.js**, chuẩn cộng đồng là `next-themes`:

```tsx
// app/providers.tsx
'use client';
import { ThemeProvider } from 'next-themes';

export function Providers({ children }) {
  return (
    <ThemeProvider attribute="class" defaultTheme="system" enableSystem>
      {children}
    </ThemeProvider>
  );
}
```

```tsx
// a theme toggle
import { useTheme } from 'next-themes';
const { setTheme, theme } = useTheme();
<Button variant="ghost" onClick={() => setTheme(theme === 'dark' ? 'light' : 'dark')}>
  Toggle theme
</Button>
```

`attribute="class"` là thứ làm nó đặt `.dark` lên `<html>`, khớp khối `.dark { … }` của shadcn.

## 5. Tùy biến một component đã copy

Vì mã nguồn là của bạn, tùy biến chỉ là **sửa một file**. Ba nước đi phổ biến:

**Thêm variant** — mở rộng `cva` của component:

```tsx
// components/ui/button.tsx
variant: {
  // …existing…
  brand: 'bg-gradient-to-r from-indigo-500 to-fuchsia-500 text-white hover:opacity-90',
}
```

**Override theo lần dùng** — `className` vẫn merge qua `cn` (Phần 5):

```tsx
<Button className="w-full rounded-full">Full width pill</Button>
```

**Đổi markup** — xóa variant không dùng, thêm slot icon, đổi tên prop. Là file của bạn; không hỏng chỗ khác.

## 6. Registry — chia sẻ component của bạn

Lệnh `add` của CLI kéo được từ **bất kỳ URL nào**, không chỉ catalog của shadcn. Đó là hệ **registry**:

```bash
# install a component from a third-party (or your own) registry
npx shadcn@latest add https://your-design-system.com/r/fancy-card.json
```

Bạn có thể publish component của mình thành một registry để cả tổ chức cài giống nhau. Một mục registry là JSON mô tả liệt kê file + dependency:

```json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "fancy-card",
  "type": "registry:component",
  "dependencies": ["@radix-ui/react-slot"],
  "files": [{ "path": "components/ui/fancy-card.tsx", "type": "registry:component" }]
}
```

Đây là cách design system nội bộ được phân phối trên nền shadcn — cùng workflow `add`, component của bạn.

## 7. Bài tập

**1.** Vì sao component shadcn luôn ghép `bg-primary` với `text-primary-foreground`?

<details>
<summary>Lời giải</summary>

Token `*-foreground` đảm bảo đọc được trên nền khớp của nó ở cả hai theme, nên tương phản luôn đúng tự động.
</details>

**2.** Bạn muốn mọi góc tròn hơn chút trên toàn app. Đổi gì?

<details>
<summary>Lời giải</summary>

Một token `--radius` — shadcn suy ra mọi cỡ `rounded-*` từ nó.
</details>

**3.** Làm sao thêm variant `brand` vào Button mà không đụng nơi dùng?

<details>
<summary>Lời giải</summary>

Thêm key `brand` vào map `variant` của `buttonVariants` trong `components/ui/button.tsx`.
</details>

Nâng cao:trong generator, chuyển light/dark và xác nhận *cùng* markup component vẫn đọc được — đó là hợp đồng `*-foreground` đang chạy.

---

## Điểm chính

- Theme shadcn là **biến CSS ngữ nghĩa**; `.dark` định nghĩa lại cùng token.
- Luôn ghép `bg-x` với `text-x-foreground` để đảm bảo tương phản qua các theme.
- Gắn brand bằng cách sửa vài token; tùy biến component bằng sửa **mã nguồn của chúng**.
- **Registry** cho phép `add` cài từ bất kỳ URL nào — phân phối design system của bạn theo cùng cách.
