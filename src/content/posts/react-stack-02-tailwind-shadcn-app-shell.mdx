Ở Phần 1 ta dựng **Pulse** với pnpm, Vite, TypeScript strict, và oxlint/oxfmt. Giờ ta cho nó một thân thể: nền **Tailwind v4 + shadcn/ui** từ series trước, áp vào app thật, cộng **vỏ app** — layout sidebar + topbar cố định mà mọi trang sống bên trong.

Cuối phần này vỏ trông như vầy — và nó giữ mount trong khi trang đổi bên trong slot nội dung:

```text
┌──────────────────────────────────────────────┐
│ Sidebar │  Topbar (search · theme · user menu) │
│ ─────── │ ─────────────────────────────────────│
│ Overview│                                       │
│ Customers│   <Outlet/>  ← the active page       │
│ Settings│   (only this region scrolls)          │
│         │                                       │
└──────────────────────────────────────────────┘
```

Nếu bạn đã đọc series Tailwind/Radix/shadcn, đây là chương "giờ làm thật".

## 1. Tailwind v4 vào project Vite

*Docs: [Tailwind — install with Vite](https://tailwindcss.com/docs/installation/using-vite).*

Ta đã thêm `@tailwindcss/vite` vào `vite.config.ts` ở Phần 1 (nằm cạnh `react()`). Còn hai bước:

```bash
pnpm add tailwindcss @tailwindcss/vite
```

```css
/* src/index.css */
@import "tailwindcss";
```

```ts
// src/main.tsx — load the CSS once, at the root
import './index.css';
```

Một `@import` đó kéo vào **Preflight** (reset có quan điểm của Tailwind), **engine utility** (quét file và chỉ sinh class bạn dùng), và điểm móc cho theme qua `@theme` (§4). Không PostCSS, không `tailwind.config.js`.

### Tóm tắt một dòng

Tailwind v4 = `@tailwindcss/vite` + `@import "tailwindcss"` + một import CSS ở gốc.

## 2. shadcn/ui — init & `components.json`

*Docs: [shadcn/ui — Vite](https://ui.shadcn.com/docs/installation/vite).*

### Vấn đề

App thật cần hàng chục component dễ tiếp cận — button, input, dialog, dropdown, table. Tự dựng mỗi cái là vài tuần a11y; cài thư viện component đóng thì không restyle được mà không đánh nhau với API.

### Công cụ: component bạn *sở hữu*

shadcn/ui không phải dependency runtime — nó **chép mã nguồn component vào repo bạn**, style bằng Tailwind, chạy trên Radix. Bạn sở hữu và sửa code.

```bash
pnpm dlx shadcn@latest init
```

Nó hỏi vài câu và ghi `components.json` — hợp đồng giữa CLI và project:

```jsonc
// components.json
{
  "style": "new-york",
  "rsc": false,
  "tsx": true,
  "tailwind": {
    "css": "src/index.css",
    "baseColor": "zinc",
    "cssVariables": true
  },
  "aliases": {
    "components": "@/components",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "utils": "@/lib/utils"
  }
}
```

Đây là lý do ta đặt alias `@/` ở Phần 1 — CLI thả component vào `@/components/ui` và import `cn` từ `@/lib/utils`. `cssVariables: true` làm theme thành việc đổi biến (§4).

### Thêm component khi cần

```bash
pnpm dlx shadcn@latest add button input dialog dropdown-menu sonner
```

Mỗi lệnh ghi một file `.tsx` thật, sửa được vào `src/components/ui/`.

### Tóm tắt một dòng

`shadcn init` ghi `components.json`; `shadcn add` chép mã nguồn component bạn sở hữu vào `@/components/ui`.

## 3. Helper `cn`

*Docs: [clsx](https://github.com/lukeed/clsx) · [tailwind-merge](https://github.com/dcastil/tailwind-merge).*

`shadcn init` tạo cái này — util dùng nhiều nhất cả app:

```ts
// src/lib/utils.ts
import { clsx, type ClassValue } from 'clsx';
import { twMerge } from 'tailwind-merge';

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}
```

- nối tên class và bỏ giá trị falsy, nên `cn('p-2', isActive && 'bg-accent')` chạy.
- giải xung đột utility Tailwind để cái cuối thắng:

```ts
cn('px-2 py-1', 'px-4')
// → 'py-1 px-4'   (px-4 overrides px-2; py-1 untouched)
```

Nối chuỗi thuần cho `'px-2 py-1 px-4'`, và padding nào thắng phụ thuộc thứ tự CSS chứ không phải ý định. Giải xung đột đó là lý do mọi component nhận `className` rồi chạy qua `cn` — để người gọi override an toàn.

### Tóm tắt một dòng

`cn` = `clsx` (nối điều kiện) + `tailwind-merge` (utility xung đột cuối thắng) — cơ chế override an toàn cho mọi component.

## 4. Token theme ngữ nghĩa

*Docs: [Tailwind — theme variables (`@theme`)](https://tailwindcss.com/docs/theme).*

### Vấn đề

Nếu component dùng màu palette thô (`bg-zinc-900`, `text-zinc-50`) thì theme là tìm-thay hàng trăm chỗ.

### Công cụ: biến CSS map sang tên ngữ nghĩa

shadcn định nghĩa token là biến CSS, rồi `@theme inline` phơi cho Tailwind thành `bg-background`, `text-primary`,… Component dùng *vai trò*, không phải màu. Blog này dark-only nên token nằm trên `:root` (ta vẫn giữ cấu trúc sẵn-sàng-`.dark` để dễ mở rộng):

```css
/* src/index.css */
@import "tailwindcss";

:root {
  --background: oklch(0.14 0 0);
  --foreground: oklch(0.98 0 0);
  --card: oklch(0.17 0 0);
  --primary: oklch(0.87 0.20 123);          /* lime accent */
  --primary-foreground: oklch(0.14 0 0);
  --muted: oklch(0.22 0 0);
  --muted-foreground: oklch(0.65 0.01 285);
  --border: oklch(0.27 0 0);
  --destructive: oklch(0.58 0.22 27);
  --radius: 0.5rem;
}

@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-card: var(--card);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-muted: var(--muted);
  --color-muted-foreground: var(--muted-foreground);
  --color-border: var(--border);
  --color-destructive: var(--destructive);
  --radius-lg: var(--radius);
}
```

Giờ một card viết `bg-card text-foreground border-border` tự đổi theme khi biến đổi — bạn sửa một chỗ, không phải mọi component. `oklch` Dùng `oklch` vì nó đồng nhất về cảm nhận: đổi lightness cho các sắc cách đều.

### Tóm tắt một dòng

Dùng **token ngữ nghĩa** (`bg-card`, `text-primary`), không màu palette thô — theme thành việc đổi biến.

## 5. Vỏ app — sidebar + topbar

### Vấn đề

Mọi trang dashboard chung khung: sidebar điều hướng, top bar cho tìm kiếm và menu user, và vùng nội dung cuộn được. Render lại khung đó mỗi trang là lặp; ta muốn nó mount **một lần**, chỉ đổi nội dung — và phải chạy trên mobile cùng dễ tiếp cận cho user bàn phím + screen-reader.

### Nav là dữ liệu có type, đưa lên module

Định nghĩa nav như hằng có type *ngoài* component, để không bị tạo lại mỗi render và dễ test:

```tsx
// src/components/layout/nav.ts
export interface NavItem {
  to: string;
  label: string;
}

export const NAV: readonly NavItem[] = [
  { to: '/', label: 'Overview' },
  { to: '/customers', label: 'Customers' },
  { to: '/settings', label: 'Settings' },
] as const;
```

### Vỏ

```tsx
// src/components/layout/AppShell.tsx
import { Outlet } from 'react-router';
import { Sidebar } from './Sidebar';
import { Topbar } from './Topbar';

export function AppShell() {
  return (
    <div className="grid min-h-screen grid-cols-1 bg-background text-foreground md:grid-cols-[16rem_1fr]">
      {/* keyboard users can jump straight to content */}
      <a
        href="#main"
        className="sr-only focus:not-sr-only focus:absolute focus:left-4 focus:top-4 focus:z-50 focus:rounded-md focus:bg-primary focus:px-3 focus:py-2 focus:text-primary-foreground"
      >
        Skip to content
      </a>

      <Sidebar />

      <div className="flex min-w-0 flex-col">
        <Topbar />
        <main id="main" className="flex-1 overflow-y-auto p-6">
          <Outlet />
        </main>
      </div>
    </div>
  );
}
```

- một cột (xếp chồng) trên mobile, sidebar cố định `16rem` + nội dung co giãn từ `md`.
- không có nó, bảng rộng sẽ ép grid tràn thay vì cho nội dung cuộn.
- ẩn về mặt nhìn cho tới khi focus; cho user bàn phím bỏ qua nav (mẫu a11y cơ bản).
- chỉ nội dung cuộn; sidebar và topbar đứng yên.

### Sidebar

```tsx
// src/components/layout/Sidebar.tsx
import { NavLink } from 'react-router';
import { cn } from '@/lib/utils';
import { NAV } from './nav';

export function Sidebar() {
  return (
    <aside className="border-b border-border bg-card md:border-b-0 md:border-r">
      <div className="px-4 py-4 text-lg font-semibold">Pulse</div>
      <nav aria-label="Primary" className="flex gap-1 px-2 pb-3 md:flex-col">
        {NAV.map((item) => (
          <NavLink
            key={item.to}
            to={item.to}
            end={item.to === '/'}
            className={({ isActive }) =>
              cn(
                'rounded-md px-3 py-2 text-sm transition-colors',
                isActive
                  ? 'bg-primary text-primary-foreground'
                  : 'text-muted-foreground hover:bg-muted hover:text-foreground',
              )
            }
          >
            {item.label}
          </NavLink>
        ))}
      </nav>
    </aside>
  );
}
```

- `NavLink` phơi `isActive` — đưa vào `cn` để tô route hiện tại bằng token ngữ nghĩa.
- không có nó, `/` sẽ khớp *mọi* route (nó là tiền tố của tất cả).
- đặt tên landmark `<nav>` để user screen-reader phân biệt với nav khác.

`Topbar` theo cùng hình (ô tìm + `DropdownMenu` cho user); ta nối nút theme bằng Zustand ở Phần 7, và tìm kiếm vào bảng ở Phần 8.

### Một ví dụ cụ thể

Điều hướng tới `/customers`:

```text
URL = /customers
  → AppShell stays mounted (it's a layout route — Part 3)
  → "Customers" NavLink isActive → bg-primary; others muted
  → <Outlet/> renders the Customers page into <main id="main">
  → only <main> scroll position resets; sidebar/topbar untouched
```

Tính cố định đó là toàn bộ ý nghĩa của vỏ: khung chung mount một lần, nội dung đổi trong `Outlet`.

### Best practice trong vỏ này

- **Đừng định nghĩa component bên trong component** — `Sidebar`/`Topbar` ở cấp cao nhất, không lồng trong `AppShell`. Component định nghĩa trong cái khác bị tạo lại mỗi render, remount cả subtree và mất state.
- **Đưa dữ liệu tĩnh lên module** — `NAV` ở module scope nên có identity ổn định, không kích re-render hay chạy lại effect.
- **Ternary thay `&&` cho UI điều kiện** — khi render drawer mobile vs nav desktop, ưu tiên `cond ? <A/> : <B/>`; `&&` với số như `count && <X/>` có thể render literal `0`.

### Lỗi thường gặp

- **Scroll sai phần tử** — nếu grid ngoài cuộn, sidebar cuộn theo nội dung. Giữ `overflow-y-auto` chỉ trên `<main>`.
- **Hard-code nav vào JSX** — giữ `NAV` là dữ liệu; sau này lọc theo role user (Phần 9).
- **Quên `min-w-0`** — con flex/grid mặc định `min-width: auto`, nên nội dung rộng (bảng) tràn viewport thay vì cuộn.

### Tóm tắt một dòng

Vỏ là grid responsive mount sidebar + topbar một lần, render trang vào một `<Outlet />` cuộn được, và tích hợp a11y (landmark, skip link).

## 6. Bài tập

**1.** `cn('px-2 py-1', condition && 'px-6')` với `condition` đúng — trả gì, và vì sao nối thuần sai?

<details>
<summary>Lời giải</summary>

`'py-1 px-6'`. Nối thuần cho `'px-2 py-1 px-6'`; vì `px-2` và `px-6` đều set `padding-inline`, cái thắng phụ thuộc thứ tự CSS. `tailwind-merge` biết chúng xung đột và giữ cái cuối.
</details>

**2.** Vì sao `NAV` định nghĩa ở module scope thay vì trong `Sidebar`?

<details>
<summary>Lời giải</summary>

Hằng mức module có identity ổn định qua các render, nên không gây re-render hay chạy lại effect và import được vào test. Định nghĩa trong component tạo lại mảng mỗi render.
</details>

**3.** Vì sao component dùng `bg-card` thay vì `bg-zinc-900`?

<details>
<summary>Lời giải</summary>

`bg-card` map tới biến CSS mà theme bất kỳ override được, nên component đổi theme mà không đổi class. `bg-zinc-900` khóa cứng một màu.
</details>

**4.** Bỏ `end` trên `NavLink` `/` thì hỏng gì?

<details>
<summary>Lời giải</summary>

`/` là tiền tố của mọi path, nên link Overview hiện active trên `/customers`, `/settings`,… `end` làm nó chỉ khớp đúng path.
</details>

Nâng cao:biến sidebar thành drawer trượt trên mobile (shadcn `Sheet` mở bằng nút menu ở Topbar) trong khi vẫn là cột tĩnh ở `md+`. Giữ state toggle cục bộ bằng `useState` đã — ta nâng UI state lưu lên Zustand ở Phần 7.

## Điểm chính

- Tailwind v4 chỉ cần plugin Vite + một `@import` + một import CSS gốc.
- shadcn/ui **chép mã nguồn bạn sở hữu** vào `@/components/ui`; `components.json` là hợp đồng với CLI.
- `cn` là cơ chế override an toàn; dùng **token ngữ nghĩa** để theme được.
- **Vỏ app** mount khung chung một lần; làm responsive và dễ tiếp cận, đưa `NAV` lên module, và đừng định nghĩa component trong component.
