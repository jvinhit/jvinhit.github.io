Nhiều “TypeScript error” thực ra là ba hệ thống bất đồng: editor resolve một đường, bundler resolve đường khác, Node runtime chạy đường thứ ba.

## TypeScript không định nghĩa runtime module

Hãy chốt theo thứ tự:

1. Runtime là browser qua bundler, Node ESM, Node CJS hay runtime khác?
2. Ai emit/bundle JavaScript?
3. Package được publish với entry points nào?
4. Sau đó mới chọn `module` và `moduleResolution`.

## Hai baseline phổ biến

App do bundler xử lý:

```json
{
  "compilerOptions": {
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "verbatimModuleSyntax": true,
    "noEmit": true
  }
}
```

Node library/app chạy output trực tiếp:

```json
{
  "compilerOptions": {
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "verbatimModuleSyntax": true,
    "rootDir": "src",
    "outDir": "dist"
  }
}
```

`Bundler` cho phép một số resolution mà Node trực tiếp không cho. Đừng dùng nó để type-check package rồi chạy unbundled bằng Node.

## Extension trong Node ESM

```ts
// src/index.ts
export { parse } from './parse.js';
```

Viết `.js` vì specifier đó tồn tại ở runtime sau emit. TypeScript map ngược sang `parse.ts` khi type-check. Đây không phải typo.

## Type-only import là contract emit

```ts
import type { User } from './types.js';
import { createUser } from './create-user.js';
```

Với `verbatimModuleSyntax`, import không có `type` được giữ theo đúng ý nghĩa runtime. Điều này làm side effect và ESM/CJS mismatch lộ rõ hơn.

## `exports` là public firewall

```json
{
  "name": "@acme/sdk",
  "type": "module",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js"
    },
    "./testing": {
      "types": "./dist/testing.d.ts",
      "import": "./dist/testing.js"
    }
  },
  "types": "./dist/index.d.ts"
}
```

Chỉ expose subpath bạn cam kết semver. Consumer import `@acme/sdk/dist/internal.js` là coupling vào layout build; `exports` nên chặn nó.

Condition order có ý nghĩa. `types` nên đứng trước condition runtime trong cùng object để TypeScript tìm declaration tương ứng.

## Dual package hazard

Nếu cùng package có CJS và ESM implementation riêng, process có thể load hai instance — singleton, class identity và cache tách đôi. Giảm rủi ro bằng một implementation chung với wrapper mỏng, hoặc chỉ ship ESM nếu consumer matrix cho phép.

## Alias không tự tồn tại ở runtime

`paths` chủ yếu báo cho TypeScript cách resolve; nó không rewrite import trong output. Bundler/runtime/test runner cũng phải biết alias. Với package nội bộ, workspace package hoặc package `imports` thường rõ hơn alias ảo.

## Debug theo evidence

```bash
tsc --traceResolution -p tsconfig.json
node --input-type=module -e "import('@acme/sdk').then(console.log)"
```

Kiểm tra package `type`, extension, exports condition, output thật và consumer matrix. Không sửa bằng cách bật ngẫu nhiên `esModuleInterop`.
