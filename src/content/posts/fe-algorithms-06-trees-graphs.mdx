Cây và đồ thị nghe có vẻ "học thuật", nhưng chúng có mặt ở mọi UI: menu nhiều cấp, cây comment, file explorer, breadcrumb, sơ đồ tổ chức, và cả mạng phụ thuộc giữa các trường form. Biết duyệt và biến đổi cây thành thạo giúp bạn xử lý những tính năng này mà không rối.

## 1. Biểu diễn cây trong frontend

Hai dạng dữ liệu thường gặp, và bạn phải chuyển qua lại giữa chúng:

```ts
// Nested shape — convenient for recursive render
interface TreeNode {
  id: string;
  label: string;
  children?: TreeNode[];
}

// Flat shape — convenient for DB storage, virtual list, O(1) updates
interface FlatNode {
  id: string;
  label: string;
  parentId: string | null;
}
```

API thường trả flat, còn UI thường cần nested để render. Chuyển flat → nested trong `O(n)` bằng `Map`:

```ts
function buildTree(nodes: FlatNode[]): TreeNode[] {
  const byId = new Map<string, TreeNode>();
  nodes.forEach((n) => byId.set(n.id, { id: n.id, label: n.label, children: [] }));

  const roots: TreeNode[] = [];
  for (const n of nodes) {
    const node = byId.get(n.id)!;
    if (n.parentId === null) roots.push(node);
    else byId.get(n.parentId)?.children!.push(node); // attach to parent — O(1) lookup
  }
  return roots;
}
```

## 2. DFS & BFS: hai cách duyệt cây

**DFS (depth-first)** đi sâu hết một nhánh rồi mới sang nhánh khác — hợp khi cần xử lý theo cấu trúc lồng (render, tính tổng con). **BFS (breadth-first)** đi theo từng tầng — hợp khi tìm "gần gốc nhất" (đường ngắn nhất theo số cấp).

```ts
// Recursive DFS: concise for trees that aren't too deep
function dfs(node: TreeNode, visit: (n: TreeNode, depth: number) => void, depth = 0): void {
  visit(node, depth);
  node.children?.forEach((child) => dfs(child, visit, depth + 1));
}

// Iterative DFS with stack: avoids stack overflow on very deep trees
function dfsIterative(roots: TreeNode[], visit: (n: TreeNode) => void): void {
  const stack = [...roots];
  while (stack.length) {
    const node = stack.pop()!;
    visit(node);
    if (node.children) stack.push(...node.children); // push children to process later
  }
}

// BFS with queue: traverse level by level
function bfs(roots: TreeNode[], visit: (n: TreeNode, depth: number) => void): void {
  const queue: Array<{ node: TreeNode; depth: number }> = roots.map((node) => ({ node, depth: 0 }));
  while (queue.length) {
    const { node, depth } = queue.shift()!;
    visit(node, depth);
    node.children?.forEach((child) => queue.push({ node: child, depth: depth + 1 }));
  }
}
```

> Lưu ý `queue.shift()` là `O(n)` trên mảng JS. Với BFS trên cây rất lớn, dùng con trỏ đầu (head index) thay vì `shift` để giữ `O(1)` mỗi bước — ta sẽ làm cấu trúc queue/heap kỹ ở Phần 8.

## 3. Các thao tác cây hay dùng

### Tìm một node và đường dẫn tới nó (cho breadcrumb)

```ts
function findPath(roots: TreeNode[], targetId: string): TreeNode[] | null {
  for (const root of roots) {
    const path = dfsPath(root, targetId, []);
    if (path) return path;
  }
  return null;
}

function dfsPath(node: TreeNode, targetId: string, trail: TreeNode[]): TreeNode[] | null {
  const next = [...trail, node];
  if (node.id === targetId) return next; // found → trail is the breadcrumb
  for (const child of node.children ?? []) {
    const found = dfsPath(child, targetId, next);
    if (found) return found;
  }
  return null;
}
```

### Cập nhật bất biến một node (cho React state)

Khi cây nằm trong React state, ta cần trả về cây *mới* (immutable) để trigger re-render, chỉ thay nhánh chứa node đổi:

```ts
function updateNode(nodes: TreeNode[], id: string, patch: Partial<TreeNode>): TreeNode[] {
  return nodes.map((node) => {
    if (node.id === id) return { ...node, ...patch };
    if (node.children) return { ...node, children: updateNode(node.children, id, patch) };
    return node; // unrelated branch keeps same reference → React.memo can skip
  });
}
```

Chi tiết tinh tế: nhánh không liên quan **giữ nguyên reference**, nhờ vậy `React.memo` (Phần 7) bỏ qua được, chỉ re-render nhánh thực sự đổi.

### Phẳng hóa để ảo hóa cây (tree + virtualization)

Muốn ảo hóa một cây (file explorer hàng nghìn node), ta phẳng hóa các node *đang mở* thành danh sách tuyến tính kèm `depth`, rồi đưa vào virtual list (Phần 4):

```ts
function flattenVisible(roots: TreeNode[], expanded: Set<string>): Array<{ node: TreeNode; depth: number }> {
  const out: Array<{ node: TreeNode; depth: number }> = [];
  const walk = (node: TreeNode, depth: number) => {
    out.push({ node, depth });
    if (expanded.has(node.id)) node.children?.forEach((c) => walk(c, depth + 1));
  };
  roots.forEach((r) => walk(r, 0));
  return out; // depth used for indent when rendering
}
```

## 4. Đồ thị: khi quan hệ không còn là cây

Cây là đồ thị đặc biệt (mỗi node một cha, không chu trình). Khi quan hệ phức tạp hơn — phụ thuộc giữa các trường form, thứ tự load module, workflow nhiều bước — ta cần **đồ thị có hướng**.

```ts
// Adjacency list: node → nodes it points to (dependencies)
type Graph = Map<string, string[]>;
```

### Topological sort: sắp thứ tự theo phụ thuộc

Bài toán: trường `city` phụ thuộc `country`, `district` phụ thuộc `city`. Phải tính/validate theo thứ tự nào? Đó là **topological sort** — sắp các node sao cho mọi phụ thuộc đứng trước.

```ts
// Kahn's algorithm: repeatedly take nodes with no unprocessed dependencies
function topoSort(graph: Graph): string[] | null {
  const indegree = new Map<string, number>();
  for (const [node] of graph) indegree.set(node, 0);
  for (const [, deps] of graph) for (const d of deps) indegree.set(d, (indegree.get(d) ?? 0) + 1);

  const queue = [...indegree].filter(([, deg]) => deg === 0).map(([node]) => node);
  const order: string[] = [];

  while (queue.length) {
    const node = queue.shift()!;
    order.push(node);
    for (const next of graph.get(node) ?? []) {
      const deg = indegree.get(next)! - 1;
      indegree.set(next, deg);
      if (deg === 0) queue.push(next);
    }
  }

  // if not all nodes processed ⇒ a cycle exists
  return order.length === graph.size ? order : null;
}
```

### Phát hiện chu trình: chống vòng lặp vô hạn

Chu trình phụ thuộc (`A` cần `B`, `B` cần `A`) gây vòng lặp vô hạn khi tính toán. `topoSort` trả `null` đã báo có chu trình, nhưng đôi khi ta cần **chỉ ra** chu trình bằng DFS với 3 màu:

```ts
function hasCycle(graph: Graph): boolean {
  const WHITE = 0, GRAY = 1, BLACK = 2; // unvisited / in stack / done
  const color = new Map<string, number>();
  for (const [node] of graph) color.set(node, WHITE);

  const visit = (node: string): boolean => {
    color.set(node, GRAY);
    for (const next of graph.get(node) ?? []) {
      const c = color.get(next);
      if (c === GRAY) return true; // hit a node currently in stack → cycle
      if (c === WHITE && visit(next)) return true;
    }
    color.set(node, BLACK);
    return false;
  };

  for (const [node, c] of color) if (c === WHITE && visit(node)) return true;
  return false;
}
```

Ứng dụng thật: validate cấu hình workflow do người dùng kéo-thả, kiểm tra phụ thuộc giữa các feature flag, hay phát hiện import vòng tròn trong một plugin system.

## 5. Cẩn thận với đệ quy sâu

DFS đệ quy gọn nhưng có giới hạn: cây/đồ thị sâu vài nghìn cấp có thể gây *stack overflow* trong trình duyệt. Với dữ liệu do người dùng tạo (độ sâu không kiểm soát), ưu tiên bản **lặp dùng stack/queue tường minh** như `dfsIterative` ở mục 2. Đây là khác biệt giữa code "chạy demo được" và code "chịu được dữ liệu thực".

## Tóm tắt

- Frontend đầy cây (menu, comment, file explorer) và đồ thị (phụ thuộc, workflow).
- Chuyển flat ↔ nested trong `O(n)` bằng `Map`; cập nhật cây bất biến để hợp với React.
- **DFS** (đi sâu) hợp render/tính tổng; **BFS** (theo tầng) hợp tìm gần gốc nhất.
- **Topological sort** sắp thứ tự theo phụ thuộc; **phát hiện chu trình** (DFS 3 màu) chống vòng lặp vô hạn.
- Với độ sâu không kiểm soát, dùng bản **lặp** để tránh stack overflow.

**Phần tiếp theo:** Memoization & LRU cache — nhớ kết quả để khỏi tính lại, và giới hạn bộ nhớ cache một cách thông minh.
