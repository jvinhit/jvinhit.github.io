Bảng dữ liệu là nơi a11y vừa dễ vừa khó: dễ vì HTML `<table>` ngữ nghĩa cho rất nhiều thứ miễn phí, khó vì các tính năng "app" như sort, edit, virtualize lại phá vỡ ngữ nghĩa đó nếu làm ẩu. Phần này đi từ bảng đúng chuẩn tới data grid tương tác đầy đủ.

> Quy tắc đầu tiên: nếu là **dữ liệu dạng bảng**, hãy dùng `<table>` thật — không phải `<div>` với CSS grid. `<table>` cho screen reader biết quan hệ hàng/cột mà `<div>` không có.

---

## 1. Bảng đúng chuẩn — nền tảng miễn phí

```html
<table>
  <caption>Doanh thu quý theo vùng</caption>
  <thead>
    <tr>
      <th scope="col">Vùng</th>
      <th scope="col">Q1</th>
      <th scope="col">Q2</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Bắc</th>
      <td>1.2 tỷ</td>
      <td>1.5 tỷ</td>
    </tr>
  </tbody>
</table>
```

Ba thứ làm bảng "đọc được" với screen reader:

- **`<caption>`**: tên bảng, đọc khi vào bảng — luôn có.
- **`scope="col"` / `scope="row"`**: gắn ô header với cột/hàng. Khi đọc một ô, screen reader đọc kèm header tương ứng ("Bắc, Q2, 1.5 tỷ").
- **`<th>` cho cả header cột và header hàng** (cột đầu thường là `<th scope="row">`).

---

## 2. Header phức tạp — headers/id

Khi bảng có header gộp nhiều tầng (header nhóm + header con), `scope` không đủ. Dùng **`headers`/`id`** để liên kết tường minh mỗi ô dữ liệu với các header của nó.

```html
<table>
  <caption>Lịch học</caption>
  <tr>
    <td></td>
    <th id="sang" colspan="2">Sáng</th>
  </tr>
  <tr>
    <td></td>
    <th id="t2" headers="sang">Thứ 2</th>
    <th id="t3" headers="sang">Thứ 3</th>
  </tr>
  <tr>
    <th id="toan">Toán</th>
    <td headers="toan sang t2">8:00</td>
    <td headers="toan sang t3">9:00</td>
  </tr>
</table>
```

Mỗi `<td>` liệt kê id của *mọi* header áp dụng. Screen reader đọc đầy đủ: "Toán, Sáng, Thứ 3, 9:00". Dùng `headers/id` chỉ khi `scope` không diễn tả nổi — nó dài dòng nhưng chính xác.

## 3. Bảng sortable — aria-sort

Khi cho phép sort theo cột, đặt nút trong `<th>` và phản ánh trạng thái bằng **`aria-sort`** (chỉ một cột có giá trị tại một thời điểm).

```html
<th scope="col" aria-sort="ascending">
  <button type="button">
    Tên <span aria-hidden="true">▲</span>
  </button>
</th>
<th scope="col" aria-sort="none">
  <button type="button">Ngày <span aria-hidden="true">⇅</span></button>
</th>
```

```js
function onSort(th, direction) {
  // xóa trạng thái cũ, set cột hiện tại
  for (const h of headers) h.setAttribute('aria-sort', 'none');
  th.setAttribute('aria-sort', direction); // 'ascending' | 'descending'
  // sau khi sắp lại, thông báo cho người dùng SR (Part 16)
  announce(`Đã sắp xếp theo ${th.textContent.trim()}, ${direction === 'ascending' ? 'tăng dần' : 'giảm dần'}`);
}
```

`aria-sort` chỉ đặt trên `<th>`, dùng `none`/`ascending`/`descending`. Mũi tên hình là trang trí → `aria-hidden`.

## 4. Data grid tương tác — role="grid"

Bảng *chỉ đọc* dùng `<table>` mặc định (điều hướng bằng phím tắt riêng của screen reader). Nhưng khi cần **điều hướng ô bằng phím mũi tên** (như spreadsheet) hoặc **chỉnh sửa ô**, nâng lên `role="grid"` và quản lý focus như composite widget (Part 14).

```html
<table role="grid" aria-label="Bảng tính">
  <tr role="row">
    <td role="gridcell" tabindex="0">A1</td>
    <td role="gridcell" tabindex="-1">B1</td>
  </tr>
</table>
```

```text
Bàn phím grid (roving tabindex):
  ↑↓←→   di chuyển giữa ô (một điểm dừng Tab cho cả grid)
  Enter/F2  vào chế độ sửa ô
  Esc       hủy sửa, về chế độ điều hướng
  Home/End  đầu/cuối hàng;  Ctrl+Home/End  góc bảng
```

> Đừng nâng mọi bảng lên `role="grid"`. Chỉ dùng khi thật sự cần điều hướng ô kiểu app — bảng đọc thuần dùng `<table>` mặc định thân thiện screen reader hơn.

## 5. Sticky header & virtualization — bẫy a11y

Hai kỹ thuật hiệu năng phổ biến dễ phá a11y:

**Sticky header** (`position: sticky`): an toàn về ngữ nghĩa nếu vẫn là `<thead>`/`<th>` thật. Chỉ cẩn thận tiêu chí **Focus Not Obscured** (Part 13) — đảm bảo header dính không che ô đang focus khi điều hướng grid.

**Virtualization** (chỉ render hàng trong viewport) phá vỡ quan hệ bảng vì DOM không chứa đủ hàng:

```text
❌ Vấn đề: chỉ 20/10000 hàng trong DOM
   → screen reader đọc "bảng 20 hàng" (sai)
   → aria-rowcount không khớp DOM

✅ Cách xử lý:
   - role="grid" + aria-rowcount="10000" trên grid
   - mỗi hàng render: aria-rowindex="<vị trí thật>" (1-based)
   - mỗi ô: aria-colindex nếu cột cũng ảo hóa
```

```html
<div role="grid" aria-rowcount="10000" aria-label="Giao dịch">
  <div role="row" aria-rowindex="142">
    <div role="gridcell" aria-colindex="1">…</div>
  </div>
</div>
```

`aria-rowcount`/`aria-rowindex` cho screen reader biết tổng số thật và vị trí hàng, dù DOM chỉ có vài chục hàng. Đây là cách hòa giải virtualization với a11y.

---

## 6. Tóm tắt

- Dữ liệu dạng bảng dùng `<table>` thật; nền tảng miễn phí là **`<caption>`** + **`scope="col"/"row"`** trên `<th>`.
- Header gộp nhiều tầng dùng **`headers`/`id`** để liên kết tường minh ô dữ liệu với mọi header của nó.
- Sortable: nút trong `<th>` + **`aria-sort`** (none/ascending/descending, chỉ một cột), và thông báo kết quả qua live region.
- Chỉ nâng lên **`role="grid"`** khi cần điều hướng ô bằng phím mũi tên / chỉnh sửa; dùng roving tabindex, Enter/F2 sửa, Esc hủy.
- **Sticky header** coi chừng Focus Not Obscured; **virtualization** phải khai báo `aria-rowcount` + `aria-rowindex` để bù số hàng thiếu trong DOM.

**Phần tiếp theo:** Live regions & thông báo bất đồng bộ — `aria-live` polite vs assertive, `role="status"`/`role="alert"`, toast, thông báo khi đổi route trong SPA, và `aria-busy` cho trạng thái đang tải.
