## Kết nối


```ts
import Redis from 'ioredis';
```

## Các kiểu dữ liệu quan trọng

Biết dùng kiểu nào là toàn bộ kỹ năng:

| Type | Dùng cho |
| --- | --- |
| **String** | cached JSON, counters (`INCR`), flags |
| **Hash** | objects/records — update one field without rewriting all |
| **List** | simple queues, recent-items feeds (`LPUSH`/`LRANGE`) |
| **Set** | uniqueness, tags, "who's online" |
| **Sorted Set (ZSet)** | leaderboards, rate windows, priority queues (score = rank/time) |
| **Stream** | append-only event log with consumer groups |

## Caching: cache-aside + TTL

Pattern chủ đạo: kiểm cache, nếu miss thì đọc DB và nạp lại kèm hạn.

```ts
async function getPost(id: number) {
  const key = `post:${id}`;
  const hit = await redis.get(key);
  if (hit) return JSON.parse(hit);                       // cache hit

  const post = await prisma.post.findUnique({ where: { id } }); // miss → DB (Phase 12)
  if (post) await redis.set(key, JSON.stringify(post), 'EX', 300); // TTL 5 min
  return post;
}
```

**Luôn đặt TTL** trừ khi có chiến lược vô hiệu rõ ràng — key không hết hạn là rò bộ nhớ chậm. Khi ghi, vô hiệu hóa cache.

### Cơn giẫm đạp cache

Khi một key nóng hết hạn, hàng nghìn request đồng thời miss cùng lúc và dộng DB. Phòng vệ: một **khóa** ngắn để chỉ một request dựng lại, **TTL ngẫu nhiên nhẹ** (jitter), hoặc phục vụ dữ liệu cũ trong khi làm mới nền.

## Pub/Sub và Streams

Cả hai chuyển tin, nhưng độ bền ngược nhau:

```ts
// Pub/Sub — fire-and-forget; offline subscribers MISS messages
sub.subscribe('orders');
sub.on('message', (ch, msg) => handle(JSON.parse(msg)));
pub.publish('orders', JSON.stringify({ id: 42 }));

// Streams — durable append-only log; consumers replay & ack what they processed
await redis.xadd('orders', '*', 'id', '42');
const res = await redis.xreadgroup('GROUP', 'workers', 'w1', 'COUNT', 10, 'STREAMS', 'orders', '>');
// ... process, then: redis.xack('orders', 'workers', id)
```

Dùng **Pub/Sub** cho fan-out tạm thời nơi mất tin cũng được. Dùng **Streams** khi mọi sự kiện phải được xử lý ít nhất một lần.

## Rate limit — bộ đếm nguyên tử

Limiter cửa sổ cố định là hai thao tác nguyên tử:

```ts
async function allow(ip: string, limit = 100, windowSec = 60) {
  const key = `rl:${ip}`;
  const count = await redis.incr(key);          // atomic
  if (count === 1) await redis.expire(key, windowSec); // start the window
  return count <= limit;
}
```

Vì `INCR` nguyên tử, nó đúng cả khi đồng thời nặng. Cho giới hạn mượt hơn dùng sliding window với **sorted set** timestamp, lý tưởng trong script Lua để nguyên tử.

## Khóa phân tán

Để chỉ một process làm việc gì đó, dùng `SET key value NX PX`:

```ts
const token = crypto.randomUUID();
const got = await redis.set('lock:rebuild', token, 'PX', 10_000, 'NX');
if (got === 'OK') {
  try { /* critical section */ }
  finally {
    // release ONLY if we still own it (compare-and-delete via Lua)
    await redis.eval(
      `if redis.call("get",KEYS[1])==ARGV[1] then return redis.call("del",KEYS[1]) else return 0 end`,
      1, 'lock:rebuild', token,
    );
  }
}
```

> Ghi chú senior: luôn kèm `token` ngẫu nhiên và giải phóng bằng compare-and-delete. Cho đúng đa node, hiểu tranh luận Redlock trước khi tin một khóa một-instance cho việc liên quan tiền.

## Session

Redis là kho session chuẩn cho app scale ngang — instance nào cũng đọc được session nào:

```ts
import session from 'express-session';
import { RedisStore } from 'connect-redis';

app.use(session({
  store: new RedisStore({ client: redis }),
  secret: process.env.SESSION_SECRET!,
  resave: false, saveUninitialized: false,
  cookie: { httpOnly: true, secure: true, sameSite: 'lax', maxAge: 86_400_000 },
}));
```

## Job nền với BullMQ

Đừng làm việc chậm trong request. Đẩy sang hàng đợi nền Redis và xử lý trong worker:

```ts
import { Queue, Worker } from 'bullmq';
const connection = { host: 'localhost', port: 6379 };

const emailQueue = new Queue('email', { connection });
await emailQueue.add('welcome', { to: 'a@ex.com' }, {
  attempts: 3, backoff: { type: 'exponential', delay: 1000 },  // retry on failure
});

new Worker('email', async (job) => { await sendEmail(job.data); }, { connection });
```

Có sẵn retry, backoff, job trễ/lặp, và concurrency — cách production giữ độ trễ request thấp.

## Lời cảnh báo của sư phụ

- **Mọi cache key cần TTL hoặc kế hoạch vô hiệu.**
- **Vô hiệu cache khó — giữ đơn giản.**
- **Pub/Sub rớt tin với subscriber offline.**
- **Khóa phải tự hết hạn và xác minh sở hữu.**
- **Redis (phần lớn) đơn luồng.** `KEYS *` chặn mọi thứ — dùng `SCAN`.
